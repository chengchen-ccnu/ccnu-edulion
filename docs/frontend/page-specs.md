# 前端页面与信息架构规格

> 状态：平台级唯一事实来源
>
> 维护者：总控任务
>
> 最近总控产品更新：2026-09-29（T16 首期范围与三端消息入口；业务代码尚未实施）
>
> 适用范围：`student-web`、`teacher-web`、`admin-web` 及其共享前端包

## 1. 使用规则

本文冻结三端的路由、页面职责、访问能力、核心状态和任务归属。OpenAPI 决定接口字段，本文决定这些接口应被哪个页面消费；两者均不能由功能任务自行猜测。

- 总控任务负责新增、删除或改变页面职责，并同步总体架构、backlog 和任务依赖。
- Txx 功能任务只能实现本文已分配给自己的页面区域；发现规格不足时停止扩展，向总控报告差异。
- 修改路由、导航名称、跨应用跳转或页面职责时，必须先更新本文，再修改实现。
- 未接通真实契约的入口不得伪装成可用功能。可以不展示，或在确有产品价值时展示明确、不可操作的阶段说明；禁止用假数据、空成功页或永久占位页冒充完成。
- 页面完成不等于路由可打开。必须同时覆盖权限、加载、空态、部分失败、业务错误、离线、响应式、键盘操作和深链接恢复。

当前 `main@1150203` 已包含 T12C.0、T12C.1、T12C.1.1 和 T12C.2（PR #76）。教师端已在冻结的 `/teacher/students`、`/teacher/analytics` 与固定“学情分析”槽位交付页面，真实 MySQL、服务 HTTP 和浏览器门禁验收已完成。T12C.1.2 仅收口学情响应中 OpenAPI 必需 nullable 字段被服务端省略的契约偏差，不改变页面职责、可见性或路由；T12H 和 T16 后续分别处理账号注销及运营审核。

## 2. 不可破坏的信息架构边界

### 2.1 课程详情不是课程学习页

`/courses/:courseId` 是公开课程落地页，服务于了解、比较和决定是否学习：展示封面、简介、教师、目录预览、访问规则，以及“开始学习/继续学习/试看/报名”行动。课程公告虽位于该页介绍之后、目录之前，但须单独请求受保护内容；公共响应不得包含公告正文。

`/learn/:courseId/:lessonId` 是受保护的学习工作区，服务于持续学习：承载视频或图文内容、章节目录、上一课/下一课、进度、笔记、资料和当前课时任务。正式播放器不得嵌回公开课程详情页。

### 2.2 公共身份、学习能力和教学能力相互独立

- 课程中心对游客和具有学习能力的普通账号保持角色中立。管理员是独立管理身份，首期不具备学生/教师能力；可读取必要公开信息不等于可报名、教学或申请教师。
- 学习空间按 `learning:access` 和课程访问事实授权，不永久绑定 `STUDENT` 角色。T11 已按能力建立后端边界，T12 应允许同时具有教学和学习能力的教师进入学习空间。
- 教师工作台按 `teaching:access` 和课程所有权授权；“课程中心”和“教学管理”不是同一列表。
- 管理端按 `administration:access` 授权，前端隐藏入口不替代服务端权限校验。

### 2.3 三个产品空间

| 空间 | 用户目标 | 主要入口 |
|---|---|---|
| 公共课程门户 | 发现和了解课程 | 首页、课程列表、课程详情 |
| 学习空间 | 继续学习、练习、复习和答疑 | 我的学习、课程学习、练习、结果、错题、AI |
| 创作与治理空间 | 创建课程、管理教学、审核与运营 | 教师工作台、管理端 |

统一登录由 `student-web` 物理承载，但文案和行为必须角色中立。登录后根据能力进入唯一工作台、工作台选择页或经过白名单验证的原始目标。

### 2.4 账号生命周期与教师能力

- `/login`、注册、密码找回和公共协议均由 `student-web` 的角色中立身份区域物理承载；教师端、管理端不得复制第二套表单。
- 自主注册只创建普通学习账号并授予 `learning:access`。管理员不允许公开注册；普通用户通过教师申请、资质上传和管理员审核后，由 IAM 为同一账号增加 `teaching:access`，不创建第二个教师账号。
- 普通账号只允许学生、学生＋教师或两项均无（封禁）；仅教师非法。首次授予教学能力必须有通过的资质审核。管理员账号只能经受控初始化或现有管理员的邮箱邀请建立，不能通过公开注册、教师申请或普通权限勾选获得；管理员不可自封禁或停用最后一名可用管理员。
- 撤销教师能力不等于封禁学习账号；管理员权限页需展示受影响课程/学生、要求原因与二次确认，旧教学令牌立即失效。撤权或封禁引发本人已发布课程系统暂停；恢复只恢复本次系统暂停的课程。禁用账号的明确提示只能在账号密码正确后出现，未知账号/错密码不得被区分。
- 注册验证码、发送冷却、失败次数和短期锁定属于 Redis 短期安全状态；用户、唯一身份、角色、协议同意、教师申请、Refresh Session 和审计事实仍由 MySQL 保存。
- 修改/重置密码、禁用账号或管理员强制下线必须递增持久化账号会话版本并撤销 Refresh Session；Redis 只缓存当前版本，不能作为唯一撤销事实。
- 身份页面必须支持 `422` 字段错误、`429 Retry-After`、验证码过期、目标已占用、离线和服务故障；不得通过不同错误泄露手机号、邮箱或账号是否存在。

#### 2.4.1 注册、登录与身份绑定冻结规则

- 正式登录标识只允许已验证邮箱或手机号；昵称允许重名且绝不参与登录。既有 `account` 只作为兼容的内部技术标识，T12D.1 为新用户自动生成且不向注册者索取，任何环境都不得保留用户名登录后门。
- local/test 固定身份使用 `student1@example.invalid`、`teacher1@example.invalid`、`teacher2@example.invalid`、`admin1@example.invalid`，可直接标记为已验证并登录，但不得参与 SMTP 发送。真实 SMTP 验收只能使用操作者本人控制的临时邮箱并精确清理验收数据。
- 注册卡片默认邮箱注册，可切换手机注册；注册字段为昵称、邮箱或手机号、算式验证码、一次性验证码、密码、确认密码以及用户协议/隐私政策同意。昵称为 1～30 个可见字符、允许中文和重名，禁止纯空白和控制字符；普通敏感词及冒充治理后移，不属于 T16 首期。
- 邮箱去除首尾空格并按不区分大小写的规范值建立唯一约束。首期手机号只支持中国大陆 11 位输入，服务端统一保存为 `+86` E.164；接口模型保留未来国家区号扩展能力，但页面暂不显示国际区号选择器。
- 密码登录使用“邮箱或手机号＋密码”；验证码登录使用“邮箱或手机号＋算式验证码＋一次性验证码”。验证码登录只允许已有账号，不得把未知身份自动注册，未知身份必须保持不可枚举的统一响应和近似处理时序。
- 一个账号最多绑定一个已验证邮箱和一个已验证手机号。新增第二种身份需要当前密码和新身份验证码；换绑必须先验证新身份再原子替换旧身份；解绑需要当前密码且不得删除最后一个已验证身份。无法访问任何身份时只能进入后续人工申诉，不得自行绕过。
- 新增第二种身份保留当前设备但撤销其他设备；换绑或解绑撤销全部设备并将当前页面送回登录。身份写入使用 revision/`409` 防止并发静默覆盖，并记录安全审计。
- 注册成功后前端自动调用登录接口建立既有会话并进入公共课程中心；登录失败不得重复注册，只能明确提示账号已创建并返回登录。

#### 2.4.2 验证码、协议和会话冻结规则

- 邮箱使用供应商无关交付端口并先实现标准 SMTP，可通过本机加密配置向真实测试邮箱发信；local/test 固定码继续保留。手机仅在 local/test 使用固定码，生产未配置短信供应商时由服务端能力查询隐藏手机注册和手机验证码登录，未来接供应商只新增适配器。
- 邮箱注册、手机注册和找回密码在发送一次性验证码前必须通过服务端算式验证码。答案只保存在 Redis，约 2 分钟过期且一次消费；支持有限刷新，连续错误后必须换图。输入标签为“请输入图片中的计算结果”，图片替代说明为“算式验证码图片，看不清可点击换一张”，刷新按钮使用可见文字并支持键盘操作，任何可访问性文字都不得泄露答案。
- 密码登录前 1～3 次失败只校验身份和密码；第 4～5 次尝试必须先通过算式验证码，第 5 次密码仍错误后锁定账号 15 分钟。算式验证码错误不校验密码且不增加密码错误次数，但其刷新和错误次数单独限流；未知身份执行相同外部语义。
- IAM 公开返回当前用户协议和隐私政策的类型、不可变版本、正文、生效时间、当前状态及是否要求已有用户重新同意；注册只能提交当前有效版本。测试正文必须明确标记“开发测试版本，不可用于正式发布”。新版本不得覆盖旧正文或历史同意；正式重新同意引导留给 T17A。
- 注册卡片点击协议名称打开文本弹窗，`/terms` 和 `/privacy` 同时作为可刷新、可分享的公共深链展示同一服务端正文；`/help` 首期只提供静态帮助与账号安全说明，不展示无后端契约的反馈按钮。
- 不增加“记住我”：Access JWT 固定 15 分钟且只存在浏览器内存，Refresh Token 固定 7 天且仅由 `HttpOnly` Cookie 持有。MySQL 保存 Refresh Session、设备、撤销和审计事实，Redis 只保存/缓存会话版本、验证码、失败计数、短期锁定和限流，不保存完整 JWT 或完整用户会话副本。
- 退出请求失败时前端可以清理内存并锁定本地页面，但不得宣称服务端会话已安全撤销；应显示可操作的未确认状态并提供有限重试。验证码、完整邮箱/手机号、Access/Refresh Token 不得进入 URL、浏览器历史或日志。
- T12E 不提供账号注销入口；账号注销、冷静期、跨域数据保留、恢复和审计由独立 T12H 先完成契约设计，未交付前不得放置无效按钮。

### 2.5 全局应用壳不可变规则

三端全局应用壳均分为品牌区、主导航区和账号工具区。页面切换、登录状态、当前角色和功能逐步上线只能改变入口的激活/启用状态，不能改变主导航的标签、顺序或位置。

- 品牌区始终显示 `Edu Lion`，不得把“学生学习中心”“课程中心”“教师工作台”或当前页面名称写入品牌标题。当前页面标题、课程名和面包屑属于页面内容区。
- 主导航使用下文冻结的固定槽位。未交付的槽位保留原位置，以“建设中”状态和 `aria-disabled=true` 明确不可操作，不得链接到 `PlaceholderPage`、空成功页或不存在的路由；对应任务完成后只启用槽位，不新增、改名或换序。
- 账号工具区固定容纳工作台控制和账号控制。匿名时账号控制显示“登录”，登录后在同一位置显示头像/账号菜单；“消息”及未读角标属于头像菜单，进入同一 `/notifications` 页面，不再提供独立通知槽位。单工作台账号显示当前工作台，多工作台账号在同一位置提供切换，不向主导航临时插入“选择工作台”。
- 当前路由只改变 `aria-current` 和视觉高亮：课程列表/详情高亮课程中心，学习页、我的学习以及 `/learn/.../tasks...` 中的 HOMEWORK/EXAM 作答与结果高亮我的学习，`/practice...` 的 PRACTICE 作答/结果和错题高亮题库，AI 会话高亮 AI 答疑。
- 响应式只能把同一组入口折叠为菜单、抽屉或横向滚动，不能删减、重排或改名。键盘焦点顺序必须与冻结顺序一致。
- `AppShell` 等共享包只渲染品牌、导航模型和具名区域，不包含学生/教师/管理员角色判断；各应用负责提供符合本文的固定导航模型，服务端权限仍是最终授权依据。

### 2.8 管理端固定导航

管理端主导航采用稳定左侧栏，首期固定顺序为“教师审核”“账号权限”；管理端默认落点为 `/admin/teacher-review`。工作台摘要后移，只有总控另行定义真实契约与导航规格后才启用。课程审核、内容治理、运营配置、数据报表不在首期导航中放可点击入口，不保留空成功页。顶部只保留 `Edu Lion` 品牌、当前“管理端”工作台标识以及工作台/头像账号工具；“消息”只在头像菜单，不再重复独立通知入口。

T17C 之前未交付的管理入口不得进入占位页；T17C 只启用上述真实模块。收起侧栏、移动端抽屉和权限禁用不得改变已启用入口的标签、顺序或活动路由映射。已上线后三端主导航仍遵守冻结槽位规则；本次由总控明确调整管理端首期冻结集合。

#### 3.2.1 内容投影与 Markdown 安全边界

- 公共 `/courses/:courseId` 只返回章节、课时标题、类型、试看标记等目录摘要，不返回正文、资源绑定、`mediaId` 或可推断私有内容的字段。既有公共 `LessonSummary.resources` 在 OpenAPI 0.19.0 中改为可选并标记 deprecated，服务端公共响应停止返回；不为此复制 `/api/v2`。
- 教师草稿投影包含完整正文和资源绑定；学生使用受保护课时内容接口。`course-service` 必须校验登录、当前发布版本、报名事实或 `previewable` 后再返回正文、有效海报和资源投影。试看仍要求登录，禁止从公共响应、页面源码或持久化缓存提前取得正文。
- T12F.1.1 为教师 owner 的当前可编辑版本增加专用正文内容投影，只对正文实际引用、同课时唯一绑定、用途为 `ARTICLE_IMAGE` 且 `READY` 的资产返回短期 `ORIGINAL/INLINE` 授权。它不把正文图片加入普通资料列表，不支持 PREVIEW/DOWNLOAD 动作，也不允许其他教师、历史/错课程版本或浏览器提交任意 `mediaId`。响应不得包含 Bucket、Object Key、永久 URL 或可复用服务令牌。
- 图文正文保存为受控 Markdown，每课时最多 100,000 个可见字符，支持 LaTeX、标题、列表、表格、代码和 `https` 链接。禁止原始 HTML、脚本、iframe、危险协议、外部图片和 `data:`；教师预览与学生渲染必须使用同一解析和消毒规则。
- 正文图片固定使用 `![替代文字](media:媒体UUID)`；替代文字必填。UUID 必须同时存在于该课时唯一的 `ARTICLE_IMAGE` 绑定中并处于 `READY`，正文引用与绑定在发布时必须完全一致。一个绑定可在正文多处引用且可使用不同替代文字；从正文删除最后一个引用并保存时，通过课程事务 Outbox 释放绑定。
- 草稿保存允许 ARTICLE 正文为空或 VIDEO 暂无视频，但立即拒绝危险 Markdown、非法占位符、错用途、重复绑定和非 `READY` 资产。发布时 VIDEO 必须有 `READY` 视频，新上传视频还必须已经成功生成自动海报；ARTICLE 必须有非空合法正文。全部已绑定海报、字幕、课件、附件和正文图片都必须用途正确且 `READY`；已发布的历史视频不被新校验追溯改写。已发布版本不可原地修改。

#### 3.2.2 学习资料、海报和播放器冻结规则

- 学习资料在本页统一展示名称、类型和大小。课程版本保存上传时原文件名、MIME、大小的不可变快照，以及教师可填的 1～120 字 `displayName` 和 `presentation=INLINE|DOWNLOAD`；不保存 Bucket、Object Key 或 URL。
- 浏览器按 `courseId + lessonId + resourceId + preview/download 动作` 申请授权，`course-service` 自行解析 `mediaId`、用途、变体和 disposition。PDF/普通图片支持预览与下载，`presentation` 只决定主按钮；PPTX/TXT 首期只下载；`ARTICLE_IMAGE` 只在正文内展示。每个动作都重新经过服务端授权。
- PDF/普通图片的短期 `INLINE` 授权在新标签打开；PPTX/TXT 等通过短期 `ATTACHMENT` 授权下载。授权到期后只能回到原学习页重新申请，不自动无限刷新；首期不实现 Office 在线转换或自建文档查看器。
- 新上传视频只有 HLS 和自动 `poster-v1` 都成功后才进入 `READY`。教师可上传独立 `VIDEO_POSTER` 覆盖自动海报，解除后恢复自动海报。历史视频没有自动海报时显示统一占位图；T12F.2 真实验收可在明确的本地开发范围内通过正常授权、上传、绑定和新版本发布为少量历史视频补自定义海报，不增加生产重处理 API。
- 倍速固定为 1 / 1.25 / 1.5 / 2 / 2.5 / 3，并保持音调；只作用于当前播放器实例。切换课时、刷新或重新进入课程都恢复 1x，不写 `localStorage`/`sessionStorage`。
- 本轮不实现多码率、清晰度选择或字幕。保留既有 `SUBTITLE` 枚举、上传策略、`READY` 校验和后端扩展位置，但页面不得出现字幕按钮、菜单、空面板或上传入口。

#### 3.2.3 图文完成与类型切换

- 受保护正文成功渲染后，前端使用稳定请求 ID 调用 Learning 的显式图文完成命令，将本人进度单调写为 100%；内容加载失败、无权限、未渲染或未报名的试看访问不记录完成。
- 页面存活期间同一逻辑请求最多有限重试 3 次；仍失败时提示“正文可继续阅读，完成状态尚未同步”，不阻止阅读和资料访问，离页后不后台无限重试。再次打开使用新的逻辑请求 ID，服务端以 0→100 单调幂等保证不重复产生完成事实。
- VIDEO→ARTICLE、ARTICLE→VIDEO 以及 ASSESSMENT 与其他类型互转必须二次确认。保存事务清除不兼容正文/绑定并写引用释放 Outbox，通用 `COURSEWARE` 可保留；取消确认时保留原类型及全部未保存内容，不能只在界面隐藏不兼容数据。

#### 3.2.4 视频进度缓冲与同步状态

- T12G.1 将进度写契约向前演进为可选 `eventType=HEARTBEAT|PAUSE|LESSON_SWITCH|LEAVE|ENDED`。缺少 `eventType` 的旧页面、已打开页面和回滚版本继续沿用既有同步 MySQL 行为；服务端不得根据请求间隔猜测事件类型。T12G.2 已在既有播放器显式发送事件，后续破坏性版本才可评估将字段改为必填。
- 播放期间最多每 5 秒合并一次 `HEARTBEAT`。普通心跳成功写入 Redis 后返回 `BUFFERED`，由 Learning 内部 Worker 在正常情况下约 5 秒内批量合并到 MySQL；`PAUSE`、`LESSON_SWITCH`、`LEAVE`、`ENDED` 直接形成 MySQL 强制检查点并返回 `PERSISTED`。只有 `ENDED` 可以请求完成，服务端仍负责判定完成条件。
- 学生本人进度读取合并 Redis 最新值和 MySQL 事实；Redis 不可用时回退到 MySQL 并标记 `PERSISTED_ONLY`。教师学情、报表和统计始终读取 MySQL，不依赖尚未落库的 Redis 值。
- 普通心跳失败或离线时不能显示虚假成功。页面在内存中合并尚未保存的观看秒数并有限重试，显示低干扰的“同步中/已保存/未保存”状态；不把未保存进度长期写入 `localStorage` 或 `IndexedDB`，也不在离页后无限重试。
- 暂停、主动退出、切课和播放结束等待强制检查点最多约 3 秒；失败时留在当前页并允许重试或明确选择“仍然离开”。刷新、关闭标签页和崩溃只能使用 keepalive/beacon 尽力提交，页面不得承诺百分之百保存。存在未保存观看进度时才警告离开，一次旧请求失败不得永久卡住页面。
- 多设备同时播放首期不加设备锁。服务端保持最远播放位置和完成状态单调，并按服务端接收时间窗口限制可累计观看秒数，避免多个设备简单叠加刷时长；Redis 中的旧值不得覆盖更新的 MySQL 强制检查点。

#### 3.2.5 当前发布内容身份与进度继承

- T12C.0 在 Course 发布事实中为课时维护稳定的“发布内容修订 ID”，该 ID 标识一次有效的教学内容修订，不替代 `lessonId` 或媒体资产 `mediaId`。不同视频必须继续使用不同 `mediaId`；额外修订 ID 用于防止 A→B→A 后错误恢复第一次观看 A 的旧进度，不使用内容 Hash。
- 只改标题、排序、说明、海报或普通附件时沿用当前修订。VIDEO 主视频替换、解绑、删除、重新绑定（即使重新绑定曾使用过的同一 `mediaId`）或课时类型变化时生成新修订；删除后重新创建的课时也不得继承旧事实。
- ARTICLE 正文、正文图片或附件变化不重置既有完成状态，也不建立阅读时长；ARTICLE 与其他类型互转时按新类型重新开始。正文修改不会再次产生“首次完成”事件。
- Learning 的 MySQL 进度、Redis 缓冲、强制检查点和学生当前进度均绑定内容修订 ID。当前课程只读取当前发布修订；旧修订事实内部保留但不进入学生当前完成度、当前观看时长或教师学情接口，也不提供历史版本页面。
- 已打开的旧播放器继续携带打开时取得的旧修订并可正常播放、保存旧事实，不强制刷新或显示课程更新提示；刷新、重新进入或切课返回后读取最新修订。Course 发布通过 Outbox 向前同步，Learning 尚未收到时可使用受控内部 Course 校验有限补齐；页面保持普通加载，超时只显示通用进度暂未同步状态，禁止把新内容进度写入旧修订。
- local/test 在 T12C.0 实施时精确清理残缺课时进度、事件、Redis 缓冲和相关日聚合，再幂等重建最小演示数据。不得删除或重建用户手工创建的《线性代数》课程；真实短视频验收可使用其第二课时，但不得修改该课程结构、发布版本或媒体绑定。

### 3.3 测评作答、结果与错题稳定工作流

- T12B 已作为一个功能任务一次性交付学生练习/考试、结果和错题本，以及教师测评管理；学生端、教师端和演示数据共用 OpenAPI 0.16.0 生成契约，没有形成平行路由或第二套 DTO。
- 作答区以一道主问题为一个连续页面区块，提供题号导航、上一题/下一题、已答/未答和整卷概览。组合题及有序小问必须处于同一主问题区块，不得拆到不同页面。
- 普通作答允许在正式提交或服务端截止前回看并修改。答案变化后防抖保存，并以定时刷新作为兜底；每次逻辑保存使用稳定请求标识，界面明确区分保存中、已保存和失败。仅仍有未保存答案时才警告离页，旧请求失败不得永久卡住页面。
- 考试时间以服务端为准；浏览器倒计时只展示和提前锁定。本地归零、刷新、系统休眠恢复或本机时间变化后必须重新校准。到期立即锁定输入，只允许提交服务端最后成功保存的草稿；网络恢复后复用同一请求做有限重试，不接受截止后的新答案，也不得无限重试。
- 结果页提供 `view=all` 和 `view=single&question=<序号>` 两种可恢复视图。前者连续显示所有主问题，后者按答题卡逐题查看；组合题始终整体展示。两种视图消费同一份安全结果，不维护第二套结果接口或 DTO。
- 学生提交后始终可见提交回执、本人答案和提交时间。成绩未公布时不显示总分、逐题得分、对错或可推断评分的信息；参考答案未公布时对应区域显示“教师暂未公布参考答案与解析”，但响应本身也必须隐藏数据，不能仅用 CSS 遮挡。
- 只公布成绩时显示最新总分、逐题得分、本人答案和最后更新时间；只公布参考答案时显示本人答案、参考答案和解析，但不显示成绩、得分或对错；两者都公布时才展示完整结果。重新批改后直接呈现最新成绩和最后更新时间，不增加刻意的“成绩已更新”横幅。
- 错题本在当前页面展开单题重做，调用 T11A 独立、有限次数的 redo 接口，立即展示本次结果和剩余次数；不得跳回原测评或重新打开已提交 attempt。

### 3.4 课程作业与考试稳定工作流

- HOMEWORK 和 EXAM 继续复用现有测评、题目快照、草稿、提交、自动/人工批改、结果公布和错题事实，不建立第二套作业领域。无课程归属的自主 PRACTICE 留在顶部题库；课程关联 PRACTICE 与 HOMEWORK/EXAM 均从所属课程进入。T10C.1/T10C.2 增补课程 PRACTICE 的投影与路由，不能仅按枚举推断归属，不能放松已有 HOMEWORK/EXAM 的时间/答案/成绩规则。
- HOMEWORK 的 `opensAt` 可空，空值表示发布后立即开放；`closesAt` 必填。EXAM 保留服务端时间和限时能力。HOMEWORK/EXAM 可绑定课时，也可作为课程级任务；当前课时页只能显示 `lessonId` 精确匹配的任务，不提供课程总览链接，课程总览入口只在已报名用户的课程详情中出现。
- 学生课程任务总览显示已开放、迟交期和已关闭且本人属于应交名单的任务。未开放的课程级任务只显示标题、类型和开放时间，不返回题目；未开放的课时级任务只在学生正在学习对应课时时显示，其他未来课时任务完全隐藏。公共课程详情不得返回具体任务清单。
- HOMEWORK 迟交策略只有 `DISALLOW` 与 `ALLOW_UNTIL`，默认前者。`DISALLOW` 在 `closesAt` 到达最终截止；`ALLOW_UNTIL` 在 `closesAt` 后进入迟交期、到 `lateUntil` 最终截止，迟交窗口至少一小时。迟交只记录事实，不自动扣分。
- 教师可在最终关闭前提前或延后截止节点，但调整后的下一有效节点必须至少晚于服务端当前时间一小时，`lateUntil` 必须晚于 `closesAt` 至少一小时。调整写审计并使用 revision/`409`；延期可把落入新准时截止前的既有提交重新分类为准时。已关闭、归档或已公布的任务不能调整；发布后题目、分值、最大次数和迟交策略不可修改。
- 教师仍可执行 T11B 的不可撤销“立即结束”，必须展示影响人数并二次确认；自动或手动关闭后不得重新开放。服务端停机跨过截止时间时，恢复后仍按服务端时钟拒绝新答案并自动补偿关闭，不延长学生时间。
- 每场 HOMEWORK 可配置 1～5 次提交，默认一次；草稿、刷新和自动保存不计次数，正式提交才形成不可变 attempt。一次提交后可在有效窗口内立即开始下一次，无需等待主观题批改；最后一次正式提交或最终截止时自动结算的非空草稿是唯一有效版本。较早 attempt 只作内部审计保留，不进入正常结果、批改和成绩册接口，知道旧 ID 也返回不得枚举；页面只展示最后一次。
- `ALLOW_UNTIL` 到 `closesAt` 时不结算当前草稿，只开始迟交标记；最终 `lateUntil`、`DISALLOW.closesAt` 或教师立即结束时才锁定输入，并从最后成功保存的非空草稿形成一次提交。完全空白草稿不消耗次数并记为缺交。准时提交后又提交迟交版本时必须提示新版本将成为最终版本并保留迟交标记。
- 截止前已有非空成功草稿但自动结算尚未物化时，显示“已交，系统处理中”，绝不能显示缺交；输入保持锁定。系统后台有限重试并持续自动补偿，不要求教师操作。处理完成前禁止人工批改、成绩/统计、公布和导出；完全无答案才可记缺交。
- 客观题仍可在每次提交时由服务端自动判分，但 HOMEWORK/EXAM 最终关闭前，教师不得进入人工批改，也不得通过结果投影看到答案、正确性或分数。关闭且结算完成后只批改最终有效 attempt；PRACTICE 保持既有行为。
- 学生任务状态使用时间状态 `NOT_OPEN/OPEN/LATE_WINDOW/CLOSED` 与本人状态 `NOT_STARTED/IN_PROGRESS/SUBMITTED/MISSING` 两个维度，并返回已用/最大次数、最后提交时间和迟交事实。作业/考试结果路由始终解析最后一次有效提交，提交回执、成绩和参考答案继续服从 T11B 的独立公布规则。
- T16.1 的系统课程暂停是领域操作，与普通服务停机不同：暂停期间阻止新的课程内容授权、作答与保存，受影响 HOMEWORK/EXAM 停止计时和自动结算。恢复时将未结束任务及未提交草稿截止时间按实际暂停时长自动顺延；已经关闭、提交或批改的事实不重新开放。旧课程任务/attempt 深链仍必须检查暂停事实。学生只看到课程暂不可用及支持邮箱，不暴露教师审核原因；前端对新状态的完整交互由后续 T17 页面任务消费生成契约。

### 3.5 顶部题库与课程练习纠偏（T10C.1/T10C.2）

- 顶栏第四槽已通过 T10C.2 改为“题库”并保留原位置，只展示公开系统题目的自主浏览；不是所有课程练习汇总。公共单题作答和无课程自主组题尚未交付，不得用浏览页面伪装完成。
- `/courses/:courseId` 增加“课程练习”按钮，已报名且有权学习者进入 `/learn/:courseId/tasks?type=PRACTICE`，只展示教师为这一课程发布且当前用户可见的练习。沿用已有作业/考试总览与结果路由，不复制整套测评器。
- courseId 由路由表达但不是授权依据；Java 再查访问与归属事实，禁止拿其他课 assessmentId 拼接越权。无权限、未发布、尚未开放的内容按领域规则隐藏；作业和考试的公布规则原样保留。
- 原顶部课程筛选控件及全课程测评汇总在 T10C.2 收口。课程关联 PRACTICE 的旧 `/practice/:assessmentId` 深链只有经服务端确认归属和权限后才跳转本课程目标；保留既有数据，不把它们删除或静默改成无课程练习。
- 公共题浏览复用 ACTIVE SYSTEM 安全列表/详情，不显示教师私有题；教师题库管理页保持原有职责。T10C.1 必须先审计已有单题练习能力，Agent 任务不补自动判分/提交行为。

### 3.6 独立 AI 与临时题目答疑（T15A/T15B）

- 独立页复用 `/ai` 和 `/ai/conversations/:conversationId`。历史可继续，无 30 分钟换新限制；权限按本人会话，公开保留说明与 180 天默认消息期限相符。
- T15A 的两条独立路由必须复用同一个对话工作区：桌面左侧为固定宽度的会话侧栏，承载新建会话和按最近消息排序的历史；中央为单一主聊天区，消息纵向连续展示，输入区固定在聊天区底部。`/ai` 在同一工作区中央显示欢迎与使用边界，进入会话后只替换中央内容，不能让用户在“会话卡片首页”和“无侧栏聊天页”之间来回切换。手机和平板将同一侧栏折叠为可关闭抽屉，关闭后焦点返回触发按钮；不得复制第二套会话状态或路由。
- “重新生成”只属于最后一条可重新生成的 AI 回答操作栏。会话空闲、最后一问已有完整或中断回答且服务端允许重新生成时才显示，文案统一为“重新生成回答”，辅助说明明确会创建一次新运行并可能消耗额度。它不得作为聊天区与输入框之间长期悬浮的全局按钮，不得让用户误解为重新执行“最后一步”；生成中、没有 AI 回答或目标不是最后有效用户消息时必须隐藏或禁用。
- 悬浮入口仅在普通自主练习题区域启用；桌面右下角按钮/面板，手机近全屏，支持键盘与关闭焦点恢复。不开启课程播放器、HOMEWORK/EXAM、结果页/错题本入口。
- 临时会话只按默认 30 分钟空闲换新，真正发送才创建；不按 attempt/题目划分，不因切题取消当前生成。跨题持续对话，只有关闭窗口/实际离开答疑承载区域才取消；前端必须维持题目路由切换期间的实例，不把每次卸载当业务关闭。
- 每条消息绑定发送瞬间的题目版本。输入区与历史用默认折叠“附带题目”卡片展示真实题干/选项/组合/题图；不显示虚构题序。题目变化不能修改历史或正在回答的上下文，重新生成沿用原快照。
- 历史消息的“附带题目”由 OpenAPI 0.23.3 `questionContextProjection` 按已保存 `questionVersionId` 返回安全投影；`UNAVAILABLE` 时不得用公共题目当前版本替代或渲染空题。历史题图只使用本人会话＋messageId 绑定授权端点，前端不得提交题目身份或实现平行 DTO。
- 默认不附学生作答；明确“附上我的作答”才发送草稿。已有输入切题后保留原关联并提示，可主动切换。未发送草稿只在页面存活期间保留。
- 同会话仅一轮生成；多标签并发冲突明确提示。关闭停止、保存部分并标为中断；恢复不自动重新生成。进入完整页恢复同一会话但先停止原流。悬浮超时不删旧记录，历史仍能从完整页打开。
- 按已授权来源展示引用与可理解阶段；不输出内部推理/隐藏画像/完整工具返回。默认分步引导，当前明确请求和偏好可改为完整解答；无证据不编来源。
- 学生主动问课程时可查经 Java 授权的课程文字，普通聊天不跟随浏览课程。无文字资料明确看不到视频。
- Agent 只答疑，不自动批改或提交。T14.3 已提供待确认动作和本人自主练习契约；T13.5.1/T13.5.2 完成标准 Skill Runtime 与组题迁移后，T15C 的建议卡须显示真实数量并支持明确确认、修改条件、取消、过期与未知结果恢复，成功后展示“开始练习”而不强制跳转。
- T15C 必须让 `/practice/:assessmentId` 同时承接本人自主练习直接作答和既有课程练习旧链接安全迁移：前端不得仅凭 URL 猜归属，应先使用服务端事实判别；自主练习复用既有 `PracticeAttemptPage`，课程练习仍迁移至课程任务路由，不创建第二套答题器。
- T15D 收口人工验收缺陷：生成期间底部发送按钮原位切换为“停止生成”，页面标题栏不再放远离输入区的停止按钮；两个 AI 输入区使用“＋”菜单承载题图选择和当前可公开选择的 Skill，题图同时支持粘贴 JPG/PNG/WebP 并继续走既有 `AI_QUESTION_IMAGE` 上传。菜单与选择项必须可键盘操作、Escape 关闭并恢复焦点。
- 两个 AI 输入框统一以 Enter 直接发送、Shift+Enter 换行；中文输入法仍在 composition 时的 Enter 不得误发。发送、上传或会话尚不可用时沿用按钮相同门禁。
- 来源默认展示两个轻量编号标签，其余用淡化“还有 N 条”入口展开；悬停/键盘聚焦可展开，指针移到列表仍保持、离开整个区域收起，Escape 或关闭按钮收起并回焦，触屏点击展开、点外部关闭。完整列表有界滚动，靠近聊天顶部时向下展开，避免被滚动区裁切。回答弱化重复边框，练习卡突出真实数量及操作，条件编辑默认折叠；移除学生不需要的内部运行/幂等术语，但保留错误、额度及数量不足说明。未指定难度的自主练习优先中等，不足可用同主题其他难度的可评分题补齐；明确难度仍严格遵守，卡片显示真实难度分布。本期不生成 AI 新题。
- 最近会话每项右侧提供“三点”菜单，首期只有“重命名”和“删除对话”。重命名使用服务端 title、expectedRevision 和稳定 requestId，冲突保留输入；删除需要二次确认，对用户立即从列表消失并不可再打开，底层复用既有 `ARCHIVED` 状态和保留策略而非级联物理删除审计/用量/记忆事实。活动 run 先停止或由服务端返回 409，不允许边生成边静默删除。
- 自主练习卡只在当前消息/恢复结果含至少一道经 Java 复核、候选数与实际数一致的真实 `PendingPracticeAction` 时出现；零候选、计数不一致、没有 action 的 404/空会话都不渲染标题、边框或“等待建议”空卡。成功、失败、取消或过期的合法动作可随其所属消息恢复，但不能在每轮普通问答底部显示一个全局常驻卡片。
- 组题 Skill 有三种合法入口：学生在“＋”菜单为下一条消息显式选择；本轮文字明确要求出题/组题/生成若干练习并由规则或一次结构化意图识别命中；讲解完成后 Runtime 基于本轮明确困难或有效证据只返回结构化“是否需要巩固练习”建议，学生下一轮明确确认后才选择 Skill。建议本身不得执行脚本、检索候选或创建 action；拒绝、转移话题或过期均清除建议。
- 显式 Skill 只作用于下一条发送消息，发送后恢复“自动”；界面展示面向学生的“生成自主练习”，不暴露内部 Skill 名称/版本/脚本。浏览器只能提交 OpenAPI 枚举，Java 映射并白名单校验后传给 Python；Runtime 仍执行 eligibility、工具 grant、预算、审计和 Java 两次题目复核，不能因显式选择绕过安全边界。当前只公开组题 Skill，不制作通用 Skill 商店。
- T15A 不得猜测当前 OpenAPI 中无类型的 SSE `payload`，不得把再次发送相同文本伪装为“重新生成”，也不得用对话消息间接冒充明确偏好设置。T14.2.4 必须先提供可判别事件、本人明确偏好读写、最后一问幂等重新生成，以及 `learning:access` 的 `AI_QUESTION_IMAGE` 上传闭环；合并后 T15A 才只消费生成客户端和统一流适配层。

公共题目正文图片继续通过 Learning 领域授权和短期 Blob 展示，不把签名 URL 写入 DOM、缓存或日志。首次加载必须保留骨架并区分授权失败、限流、服务故障、OSS/网络失败与用户取消；仅对网络、`502/503/504` 或授权过期执行一次有界重试，`429` 遵守 `Retry-After`，`403/404/422` 不自动重试。相同题目和 `mediaId` 的并发授权/下载须合并，会话内使用有数量/内存上限的 Blob 缓存避免返回页面立即重复下载；失败不进入缓存，并提供明确的手动重试。组合题多图可以小并发加载，禁止无上限并发或逐图无限重试。只有真实测量证明原图字节或解码是瓶颈时，才另行评审题图展示派生版本，不能仅凭“加载中”文案新增媒体契约。

### 3.7 课程公告与消息稳定工作流（T16.4/T17A）

- 公告正文为标题＋纯文本，保留段落换行，普通 https 地址仅显示文本。课程介绍后、目录前的公告区只有当前 ACTIVE 报名者可读；游客、试看者、退课者不可获取正文。新报名者可读仍有效的旧公告，但不补旧提醒或产生未确认置顶；归档课程不发新公告，仍有课程访问权者可读历史公告。
- 最新未确认公告突出显示，同时显示“还有 N 条未确认”，可展开逐条确认。只有点“我知道了”才同时取消突出与清消息未读；加载课程页或从消息进入均不自动确认。已确认公告仍收纳在列表；已撤回公告从学生列表和可打开消息移除，旧链接不返回正文。
- 已发布公告改动保存新审计版本，学生只看最新版；同一公告在同一学生消息列表只有一条，更新标题、重置未读及确认，不堆重复消息或显示“修改过”。教师首期不查看个人已读名单或催读。
- `/notifications` 只承载课程公告、课程 HOMEWORK/EXAM 开放/截止变更/立即结束、教师审核结果、课程暂停/恢复四类消息。新任务提醒按真正开放且 ACTIVE 学生有权访问时触发，不因发布草稿或后报名补发。PRACTICE、公共题库和 Agent 自主练习不通知。
- 普通消息成功进入目标页后标已读；公告须明确确认。“全部标为已读”只处理普通消息，并提示尚余几条待确认公告。消息列表按时间分页，首期不能手动删除且不按统一 TTL 自动清理；服务端打开前再次验权，退课/撤回后不保留可打开入口。
- 消息预览只给必要标题和状态：审核理由在受保护申请详情显示，课程暂停/恢复不暴露资质或撤权原因。申请人从结果消息进入 `/apply-teacher` 时刷新真实账号能力，通过后提供进入教学空间；不能只靠前端按钮授予权限。

### 4.1 题库页面稳定工作流

- `/teacher/questions` 是题库聚合入口，不把新建、编辑或导入任务详情塞进不可深链接的临时弹层。页面刷新后必须从 URL 和服务端恢复分页、筛选、当前题目或导入任务；主导航的“题库”在上述六条路由中保持同一高亮组。
- 题目作用域固定为 `SYSTEM` 与 `TEACHER`。`SYSTEM` 题由管理员及其系统媒体资产持有，所有教师可检索、查看并在后续组卷契约中引用，但教师不得修改版本、状态或媒体；`TEACHER` 题只对创建教师可见和可写。教师列表必须提供来源筛选，并明确显示只读系统题标识。
- 新建和编辑支持单选、多选、判断、填空、简答与有序组合题。组合题父题及每个子题的题干、选项、答案、解析、知识点和媒体必须通过 T09B 的结构化契约提交；禁止前端把多个子题拼成一个自由文本答案，也不得直接修改历史版本。
- 组合题详情按一张完整试题展示：父题题干、连续编号的小问和题图共用题干区域，答案与解析分别统一展示并在小问之间换行。内部仍保留子题结构用于后续逐问作答/评分，不得因展示合并丢失顺序、答案或知识点。
- 题目编辑与筛选支持小学一至六年级、初中七至九年级；学段切换必须同步约束年级并清除不匹配的知识点，组合题子题继承父题学段/年级。高中知识点保留为平台数据但保持禁用，不得出现在教师选择器或题目写契约中。
- 详情页默认只读展示当前版本并可查看历史版本；版本切换只改变预览，不移动聚合当前指针。发布、归档和编辑均携带当前 revision，`409` 时展示服务端新版本并保留尚未提交的本地内容，由教师决定重新应用。
- 题目内容按受控 Markdown/LaTeX 和安全富文本渲染，禁止直接使用未经清洗的 `v-html`。图片、音频和附件复用 media-service 上传会话及短期访问授权；业务请求只保存 `mediaId`，内联图片使用与当前版本 `QUESTION_IMAGE` 列表一致的稳定占位符恢复原文位置；离开页面时中止上传/轮询、撤销临时 URL 并清理定时器。
- `/teacher/question-imports` 只创建和展示教师本人 CSV/XLSX 私有题导入。历史 JSON 由管理员通过受控脚本和 `/api/v1/admin/**` 契约进行有界 dry-run、筛选、正式导入与精确清理；浏览器和后端均不得扫描服务端绝对路径。
- 管理员历史 JSON 导入仍保持单任务/单批次上限、稳定检查点、`VALID/NEEDS_REVIEW/SKIPPED/FAILED` 投影、明确图片白名单与精确清理，不得用管理员身份绕过格式、知识点、媒体或幂等校验。正式导入的题目及图片分别保存为 `SYSTEM` 题和 `SYSTEM` 媒体资产。
- T09B 未提供的查询、解决或组合题写入能力在 T10 中不得以浏览器内存、Mock 成功或手写 DTO 补齐；发现契约差异时停止对应交互并回报总控。

### 4.2 教师测评稳定工作流

- `/teacher/assessments` 是唯一测评管理入口，在同一路由内通过可恢复的查询参数表达当前 assessment、列表筛选、编辑、题目配置、发布、结果和人工批改面板。课程编排页只携带课程/课时上下文跳转到这里，不复制测评编辑器或发明平行详情路由。
- 教师主动结束整场测评是不可撤销的高风险操作。页面必须先展示仍在作答的影响人数并二次确认；关闭后立即禁止新建或继续写入 attempt，服务端只按各学生最后成功保存的草稿进行有界、幂等结算。
- 参考答案与解析的公布规则固定为：普通练习可在个人提交后自动公布；作业和考试不得在整场关闭前公布；也可在整场关闭且批改完成后自动公布、关闭后由教师手动公布，或永不公布。仅某位学生已经提交不能成为作业/考试泄题的依据。
- 成绩可在整场关闭、草稿结算完成且全部人工批改完成后自动公布，或由教师手动公布。存在待结算草稿、待批人数或待批题目时，页面显示精确数量并禁用公布成绩；服务端必须执行同样校验。
- 成绩公布与参考答案/解析公布是两个互相独立、只能由未公布变为已公布的事实，均不支持撤回，不支持逐学生或定时公布。公布参考答案不要求主观题已经批完，但必须确保整场关闭且草稿结算完成。
- 首期人工批改只做逐份查看待批主观题、录入得分和评语并提交，不实现批量打分或复杂批注。已公布成绩允许重新批改并保留审计；`409` 时保留本地输入，重新载入最新 revision 后由教师确认，不得静默覆盖。
- 批改面板在 URL 含 `panel=grading&attemptId=<最终有效作答>` 时，必须通过 `GET /api/v1/teacher/attempts/{attemptId}` 读取这一份答卷。该接口只允许 owner 教师在整场已经关闭且草稿结算完成后读取最后有效 attempt，不要求整场全部批改完成；非 owner、旧 attempt、attempt 与课程或测评资源不匹配时统一按不存在返回。URL 中的 `courseId`、`assessmentId`、`learnerId` 只用于恢复页面上下文，服务端授权不得信任这些查询参数。
- 原整场 results 接口继续要求全部人工批改完成后才返回，不能因增加单份批改读取接口而放宽；成绩写入仍使用现有 revision 和 `409` 冲突保护。T11C.1.3 不新增批改页面、第二套结果 DTO 或历史 attempt 浏览能力。
- T11B 已建立上述服务端事实与安全投影；T12B 页面只消费 OpenAPI 0.16.0 重新生成的客户端，关闭、公布、资格和隐藏字段均来自服务端事实。

### 4.3 教师成绩册稳定工作流

- `/teacher/assessments` 继续负责创建、组题、发布、关闭、逐份人工批改和公布；`/teacher/gradebook` 只负责跨 HOMEWORK/EXAM 的矩阵、筛选、统计和导出。点击学生记录携带 `courseId/assessmentId/learnerId/attemptId` 深链回既有批改面板，不复制答卷或批改器；`attemptId` 使第一页之外的最终有效 attempt 也能直接定位，`learnerId` 等查询参数只用于导航和显示，不构成服务端授权事实。
- 作业开放时以课程报名事实建立应交名单；开放期间新报名者加入，最终关闭后冻结。退课者保留不可变应交/提交历史但标记 `WITHDRAWN`，不计缺交或平均分；有效窗口内重新报名可恢复应交。首期不支持免交或个别延期。
- 每门课程为报名者分配不回收的四位课程学生编号；既有报名按首次报名时间、再按 learnerId 稳定回填，新报名原子领取下一编号，退课后重新报名沿用。成绩册显示昵称和课程学生编号，不显示完整邮箱/手机号；昵称不可用时仍返回编号和成绩事实，并显示部分数据提示。
- 成绩册拆分提交状态、批改状态和迟交事实：提交状态至少包含未开始、作答中、已提交、缺交、已退课；批改状态至少包含无需人工批改、待批、部分批改、已批；迟交为独立布尔事实。缺交仅在最终关闭且确定无非空草稿后产生。
- 最终关闭前，教师只能查看应交人数、提交进度、已用次数、最后提交时间和迟交事实，不能查看答案、正确性或分数。初次批改期间，批改器可以显示当前答卷、单题得分和已保存内容，但结果列表、成绩册、统计和导出不得逐份暴露成绩；一场任务全部最终提交达到 `GRADED` 后才一次性显示该场所有成绩并允许导出。
- 已完成测评重新批改时不重新隐藏已显示结果；提交事务保留旧批改审计，以 revision/`409` 防覆盖，随后原子呈现最新成绩、最后更新时间及重算统计。教师完整统计不依赖学生端是否已经公布，学生可见性仍严格服从 T11B。
- 成绩册默认按课程学生编号稳定排序，可按最后提交时间、成绩和状态排序；隐藏成绩阶段不得按成绩排序。筛选至少包含 `courseId`、`assessmentId`、`type=HOMEWORK|EXAM`、提交状态、批改状态、迟交、昵称/课程学生编号关键词、页码和每页数量，并写入 URL。
- 单场全部批改完成后才返回已批平均分、所有学生平均分、应交人数、准时提交率、最终提交率、缺交人数、待批人数、最高分、最低分和分数区间分布；存在待结算、结算异常、待批或部分批改时，聚合状态为 `PENDING` 且不返回均分、极值或分布。所有学生平均分把缺交计为零，已退课不进入分母。
- 课程汇总只纳入已经关闭并完成批改的任务，尚未开放、仍开放、处理中或未完成批改的任务不进入且不按零分。HOMEWORK 与 EXAM 分别换算百分制后在各自类别内等权平均，PRACTICE 不进入正式成绩；首期不提供学生排名，只提供完成后的极值和分布。
- CSV 为同步 UTF-8 BOM 宽表：一次一门课程、最多 5,000 名学生和 100 场已关闭且完成批改的 HOMEWORK/EXAM。固定列为课程学生编号、昵称；每场任务分别生成数值成绩、提交状态和迟交三列，并附作业平均分、考试平均分。缺交成绩写零，已退课或不属于该场应交名单留空；不导出联系方式、题干、答案、解析或评语全文。
- CSV 只导出当前筛选，超限要求缩小类型或时间范围；服务端再次校验课程 owner，防公式注入，记录操作者、课程、筛选、行数、时间和 traceId，日志不记录文件内容，失败不遗留临时文件。本轮不上传 OSS、不使用 `REPORT_EXPORT`，异步 XLSX 后移到运营报表任务。

### 4.4 教师学情与课程分析稳定工作流

- `/teacher/students` 和 `/teacher/analytics` 使用同一组 Learning 持久事实但职责不同：前者回答“每名在读学生学了什么、看了多久、任务成绩如何”，后者回答“当前课程整体观看、完成和任务表现如何”。不得在两个页面复制同一张巨大明细表，也不得由前端跨接口拼接全班事实。
- 教师学情只展示当前 `ACTIVE` 报名者；`WITHDRAWN` 不提供页面筛选或常规接口投影，历史学习事实仍内部保留。重新报名恢复为 ACTIVE 后，才重新进入当前内容口径。没有已发布版本返回 `NO_PUBLISHED_VERSION` 空态；已发布但没有 ACTIVE 学生返回合法零值。
- 学生列表至少显示课程学生编号、昵称、当前发布版本完成度、已完成/总课时、当前内容累计观看时长、最后活动时间、HOMEWORK 平均、EXAM 平均、缺交数和待批数。默认按课程学生编号稳定排序，可按最后活动、进度、观看时长、作业平均和考试平均排序；支持 ACTIVE 范围内的进度、缺交、待批、昵称/编号、分页筛选，不增加风险或薄弱知识点筛选。
- 学生详情使用 `/teacher/students?courseId=...&learnerId=...&panel=overview|lessons|tasks` 恢复状态。概览只返回汇总；课时和任务明细分别分页、按需查询；每日趋势独立请求。联系方式、Agent 隐藏画像、笔记正文、完整答卷和旧 attempt 均不返回，答卷详情仍深链既有批改页。
- VIDEO 统计明确返回当前内容的全班累计观看秒数、观看人数、ACTIVE 学生人数、每名 ACTIVE 学生平均（未观看者按零参与）和每名实际观看者平均；逐课时还返回已开始人数、已完成人数、完成率及每名学生累计时长。ARTICLE 只返回已开始、已完成和完成率，不伪造阅读时长；ASSESSMENT 课时的作答只进入任务统计。
- “开始”和活动只使用成功持久化的领域事实：有效 VIDEO 进度/强制检查点、ARTICLE 完成、测评草稿保存、正式/自动结算提交、错题重做和正式报名。仅打开/刷新页面、Redis 尚未落库值、AI 对话和笔记编辑不计入。`lastActivityAt` 可由草稿保存更新；趋势活跃学生为当天至少有一项成功持久化学习行为的去重 ACTIVE 学生。
- HOMEWORK/EXAM 沿用 T11C 的最后有效 attempt、关闭/结算/全部批改统计门禁和已批平均/缺交计零全体平均。整场已关闭且草稿结算完成后，owner 教师在**单个学生任务明细**中可看到该生最后有效 attempt 已正式批改的原始得分、总分和百分制，即使班级仍有待批；该生未批时分数字段为 `null`。班级门禁打开前只另显示应交、已交、缺交、迟交和待批计数，不返回班级均分、极值、分布、排名、排名人数、领先比例或按隐藏成绩排序；整场全部批改完成后才返回竞赛排名 `1、1、3`、排名人数和 `rankingPercent=(rankedStudentCount-rank+1)/rankedStudentCount*100`。成绩册和整场 results 接口保持原有全部批改门禁。
- 课程 PRACTICE 与正式成绩分开，只统计真实完成提交者；每名学生使用历史最高有效百分制成绩，班级返回参与/提交人数、平均、最高、最低、分布、竞赛排名和同一 `rankingPercent`。公共题库和 Agent 自主练习不进入课程分析。归档任务保留统计并返回 `ARCHIVED`，页面默认折叠。
- 快照指标使用当前 LIFETIME 事实；时间窗口固定为全部、最近 7 天和最近 30 天，按 `Asia/Shanghai` 自然日计算。7/30 天按日；ALL 跨度不超过 180 天按日，超过则按月，并返回 `granularity=DAY|MONTH`。趋势至少包含有效观看秒数、活跃学生数、首次开始课时数、完成课时数、正式提交次数、去重提交学生数和自动结算提交次数。
- T12C.1 增加幂等的 MySQL 日聚合事实；Redis Worker 与强制检查点以服务端已校验 `occurredAt` 计算有效增量并使用同一口径，重试不得重复累计。上线前只保留既有 LIFETIME 累计，不伪造日历史；当前内容更换后，当前 7/30/ALL 趋势也只统计新修订。月度去重指标必须按月重新聚合，不能直接相加每日去重数。
- 所有响应返回 `periodStart`、`periodEnd`、`zoneId`、`generatedAt` 和 `dataThrough`。正常页面不显示机械的更新时间横幅；只有数据延迟或依赖降级时提示。IAM 不可用时保留课程学生编号和 Learning 统计并标记昵称依赖失败；Course 不可用时因无法确认当前发布内容返回 503；Redis 不可用时继续读取 MySQL 已落库事实。
- 学生、课时和任务列表使用有界分页：学生默认 20/最大 100，学生课时与课程课时默认 50/最大 200，学生任务和课程任务默认 20/最大 100；趋势接口不分页。T12C 不提供导出、AI 总结、薄弱知识点、风险/预警、课程转化、观看达标、提醒或历史内容观看页面，也不复制 T11C 成绩册和批改器。

### 5.1 教师审核与账号权限工作流（T16.2/T16.3/T17C）

- 管理员主动打开申请详情才标审核中，列表加载不触发；审核中不独占，显示首次查看者/时间。材料经 IAM 授权后复用 Media 的短期图片/PDF 预览，必要时下载；材料打不开禁止批准。批准须确认材料，驳回须填写申请人可理解的原因；最终决定使用 revision/409，冲突刷新并保留输入，不能覆盖旧决定。
- 申请人等待审核时不可任意修改/撤回，驳回后可上传新材料重提。学生只看最新申请与必要决定；管理员可查看历次材料标识及审计。被驳回文件决定后七天清理，替换旧文件从替换起七天清理；待审核及当前已批准资质材料持续保留，包括后来撤权时。决定文字和审计不随文件删除。
- 账号权限页只允许学生、学生＋教师或两者皆无（封禁）；教师勾选首次授予必须已有资质批准。管理员独立身份不进入普通能力勾选；受控邀请创建管理员，不能公开注册或申请。各管理员同权，自封禁及停用最后一名可用管理员由服务端禁止。
- 教师撤权/恢复、封禁/解禁需理由、影响人数和二次确认；操作后旧会话按安全规则失效。恢复仅恢复本次系统暂停课程，不将主动下架/草稿/归档意外公开。正确账号密码之后才给封禁说明，未知账号或错密码维持统一登录失败。

## 6. 页面状态与交互最低要求

| 状态 | 统一要求 |
|---|---|
| `loading` | 使用稳定骨架，避免布局跳动；长操作显示阶段而非无限转圈 |
| `empty` | 说明为什么为空，并只提供真实可执行的下一步 |
| `partial-error` | 保留已成功区域，允许定向重试失败区域 |
| `401` | 统一登录或单次刷新；禁止循环刷新 |
| `403` | 解释缺少的业务条件，不把越权资源细节泄露给用户 |
| `404` | 资源不存在、未发布或不可见使用不可枚举表达 |
| `409` | 展示版本/状态冲突并要求刷新，不静默覆盖 |
| `422` | 映射字段错误并保留用户输入 |
| `429` | 尊重 `Retry-After`，有限退避，禁止无限重试 |
| `offline/5xx` | 区分网络与服务故障，提供安全重试，不伪造成功 |

所有页面都必须支持刷新和深链接。播放器、上传、考试和 SSE 页面离开时清理实例、请求、定时器和临时 URL。学生端优先适配手机、平板和桌面；教师与管理端优先桌面并保证平板可操作。

## 8. 总控验收门禁

每个涉及前端的 PR 在合并前至少回答：

1. 是否修改了本文分配之外的路由或页面职责？
2. 是否把未实现后端能力伪造成可用按钮、成功数据或占位工作台？
3. 课程详情、课程学习、我的学习、教师课程管理是否仍保持独立？
4. 当前用户如果同时有多种能力，是否能选择或切换到正确工作台？
5. OpenAPI、页面规格、Mock、实现和交付文档是否一致？
6. 是否执行了对应页面的组件测试、深链接/权限测试和真实用户流程验收？
7. 三端品牌、主导航标签/顺序和账号工具区是否在页面、身份与响应式状态之间保持稳定，未启用入口是否明确禁用而非进入占位页？

任一答案不明确时，PR 不能仅凭构建通过标记为产品功能完成。
