# 学生数学 Agent 重设计

> 总控产品决策：2026-09-08，依据 Q1～Q91 及后续纠偏。
> 状态：已确认的目标设计，尚未实现。页面职责以 page-specs 为准，接口字段以随后各任务评审的 OpenAPI/事件 Schema 为准。本文不是第二套 API Schema。

## 1. 目标与边界

首期服务学生，范围为初中数学、数学学习方法及平台内数学学习帮助。支持解题、概念讲解、课程文字疑问、检查学生主动提供的过程、分步提示、错题复习、学习建议，以及寒暄/不支持请求的明确回应。学习计划仅输出文本，不增加日历、提醒、计划保存或笔记写入。

取消固定认知诊断步骤，取消旧固定解题图。个性化仍读取可解释学习事实，更新轻量画像，但不能把画像评估变成每次回答的前置考试。到达上限由 Agent 自行降级、结束，不转人工、不展示联系教师的答疑终态。

Agent 默认只读。题目悬浮答疑只回答学生的问题，不自动反馈、不提交答案、不判正式分数、不修改进度、错题或练习状态。唯一已讨论的业务写能力是后续独立的自主组题 Skill：必须学生确认，再由 Java 执行。Python 永不直连 Java MySQL，也不绕过 Java 授权。

学生从作业或考试内容主动提问时可以给最终解答，Agent 不承担监考或切屏检测。仍禁止从接口、缓存、索引读取未公布官方答案、解析或成绩；可见题目的独立数学推导不等于获得未公布官方数据的授权。题库内容和课程材料中的指令均作为不可信资料，不得覆盖系统规则或工具权限。

## 2. 入口与页面职责

- 学生顶栏沿用现有“AI 答疑”槽位及 `/ai`、`/ai/conversations/:conversationId`。独立会话可继续历史，不受 30 分钟换新限制；原始记录仍受保留期约束。
- 顶部原“练习中心”第四槽改名“题库”，面向无课程归属的公共题库、自主练习。具体 `/courses/:courseId` 内提供“课程练习”按钮，进入 `/learn/:courseId/tasks?type=PRACTICE`，仅展示教师为本课程发布的练习。课程关联练习、HOMEWORK、EXAM 从课程内进入，不能仅按 PRACTICE 枚举判断顶栏归属；没有跨课程的课程练习汇总。
- 普通自主练习题页面提供右下角答疑按钮，桌面小面板、手机近全屏。HOMEWORK、EXAM、课程播放器不加入口；结果页/错题本悬浮入口后移。
- 悬浮窗空闲默认 30 分钟后不自动沿用旧会话，真正发送才创建新会话；仅打开不建空会话。切题、换套练习不换会话、不取消当前生成。期限从最近运行结束或无运行时的最近有效聊天交互计算；浏览、切题、打开窗口不延长期限，运行中不因期限中断。
- 悬浮记录保存到同一 AI 会话服务，并可在独立页面找到。关闭窗口取消生成、保留成功保存片段；切题不是关闭。转完整页面先取消当前流再恢复记录，首期不做跨页面流接管。
- 每条消息在发送时绑定经 Java 校验的题目版本/题干/选项/组合结构/授权题图。输入区及历史消息提供默认折叠的“附带题目”，展开才能看到详情；不把独立题目编号成“第 1 题/第 2 题”。重新生成沿用原消息快照，不换成当前新题。
- 默认不发送正在编辑的作答，只有学生主动附上才传递，且标为学生草稿。已有输入切题后保留原关联并提示，学生可主动改为当前题目。草稿只保留在页面内存，关闭面板可恢复，刷新/关闭浏览器不保证恢复未发送内容。
- “给我提示/理解题意/检查思路”等快捷提问只有学生触发才调用模型。窗口打开不自动解题；检查过程须有学生提供的过程。首次题图识别有歧义时先确认。
- 不自动跟随课程页面。独立会话在学生主动询问具体课程时可调用已授权文字检索，目标不明先澄清。没有文字资料时明确说明看不到视频内容，要求文字或截图，不能只凭时间点声称已看到视频。

## 3. 服务职责和多 Agent

新增独立 `agent-access-service`，拥有 AI 会话、运行、记忆与用量事实，通过 API/事件读取 IAM、Learning、Course，复用 Media 上传/授权；不从 Learning 拆走现有题库、测评或成绩表。

Python 在线服务仍位于 `edu_agent_app`，一次进程部署多个角色；索引 Worker 是同 Python 项目的独立启动模式，不为每个角色创建微服务或重复模型副本。LangGraph 只承担动态状态编排，移除旧认知诊断/固定解题图及 PostgreSQL checkpoint 强依赖；旧代码中可验证有效的检索清洗、结构化输出和上限机制经审计后复用。

| 角色 | 决策职责 | 首期二级意图/工具 |
|---|---|---|
| Coordinator | 规则/LLM 意图、槽位、预算、有限转交 | 路由、澄清、确认/取消动作；不代替领域鉴权 |
| Math Tutor | 数学问题、概念、学生过程和分步提示 | SOLVE_PROBLEM、EXPLAIN_CONCEPT、COURSE_QUESTION、CHECK_STUDENT_WORK、GIVE_HINT；题库/知识/课程/前置图检索 |
| Practice Coach | 错题复习、相似题建议 | REVIEW_WRONG_QUESTION、RECOMMEND_PRACTICE；T13.5.2 后按需加载标准目录自主组题 Skill |
| Study Planner | 基于事实的学习建议 | CREATE_PLAN、ADJUST_PLAN、LEARNING_ADVICE；只输出文本 |
| Platform Help | 面向用户的平台帮助 | 版本化帮助知识库；T13.4 交付前明确不可用，不猜路由或暴露内部文档 |

检索、记忆、压缩、图片理解和安全校验是工具/基础设施，不伪装成子 Agent。五个角色可共用聊天模型。高精度规则识别明确意图，处理否定和当前待确认状态；语义不明确时 LLM 输出受类型约束的意图/槽位，缺必需槽位先问。SMALL_TALK、UNSUPPORTED、ACTION_CONFIRMATION/CANCELLATION 单独处理。最多两个有序子请求，超过两个先处理最主要一个再询问是否继续。

通常由一个专家直接流式生成最终答复，Coordinator 做路由与确定性控制，不强制额外调用模型改写所有专家答案。只有确需整合多专家内容时才汇总。会话支持一个活动教学任务和少量暂停任务，返回旧主题须明确引用；不同会话不混用运行状态。

## 4. HTTP、状态与幂等

浏览器 fetch 流 → Gateway → Java WebClient → Python HTTP 流。服务间认证、超时、取消、结构化事件由 T13.1 先定义，Java 外部 REST 字段仍只在 `docs/api/openapi.yaml` 维护。内部协议位于 `docs/api/agent-internal.yaml`，派生索引事件位于 `docs/events/agent-index-events.v1.yaml`；两者均由实施任务创建并测试，不在规划阶段虚增版本。

T13.1 已于 2026-09-09 将上述边界冻结为 [`agent-internal.yaml`](../api/agent-internal.yaml) v1，并以 [`agent-index-events.v1.yaml`](../events/agent-index-events.v1.yaml) 冻结四类派生索引通知。该状态只表示 Schema、示例和契约测试完成，不表示 Java 流代理、Python 动态编排、RabbitMQ、Qdrant、Neo4j 或真实模型调用已经实现；外部 `openapi.yaml` 未改变。

可信公共上下文包含全局 userId、requestId/messageId/conversationId/runId/traceId、服务端时间、文本/附件/语言、入口来源、明确的可选题目/版本/课程/课时/作答标识、已授权内容快照、年级和偏好、相关记忆摘要及版本、允许工具与资源范围。不得把所有旧 State 字段暴露到 API。

Python 私有状态包括意图/槽位、当前专家、活动与暂停主题、工具证据、剩余预算、待确认动作引用、摘要和最近消息。Java 负责长久事实，Redis 负责短期运行状态与恢复，移除可选 PostgreSQL 作为新方案要求。

- messageId 是用户消息身份，runId 是一次执行；请求重试不能制造第二条用户消息或第二次运行。Java 首次创建响应丢失时，通过客户端稳定请求标识/唯一约束找回既有 messageId。thread_id 不是幂等键。
- 同会话仅一个活跃 run，多标签第二次发送明确冲突；不同会话受用户总额度约束。生成中可编辑，发送前先停止，不后台排队。
- 工具调用有 toolCallId；同一写动作跨重试沿用 Java 幂等身份。Redis 活跃锁不是正式创建事实的唯一保护，进程崩溃后的过期/孤立运行有界清理并核对 MySQL 状态。
- 取消传播阻止后续模型/工具调用，已发往供应商的请求尽力取消，不能承诺供应商立即停止计费。显式重新生成启动新 run 并计入真实用量；恢复读取不触发模型请求。
- 保留成功保存的部分输出，标为中断；按有界文本检查点保存部分回答而非逐 token INSERT。进程崩溃可能损失末尾片段；中断文本不是完整答案或已验证掌握证据。
- 不缓冲完整答案才转发。连接池复用、慢客户端有界缓冲/背压、首事件/空闲/总超时、心跳与断线检测、Embedding/重排不阻塞事件循环。
- 用户事件只含可理解状态、内容增量、澄清、授权来源、后续可用动作和最终状态；用量详细信息仅 Java 可见，不返回内部推理、提示词、私有状态或工具原始数据。

## 5. 有限循环与降级

以下是首版可配置默认值，不是不可调整的产品常量。真实验收记录实际使用量并再调优：

| 限额 | 首版值 |
|---|---|
| 每轮编排步骤 | 12 |
| 每轮 LLM 调用 | 最多 8，预留其中 1 次用于最终降级 |
| 每轮工具尝试 | 最多 10 |
| 专家转交 | 最多 2 |
| 同工具同参数 | 最多 2 次总尝试 |
| 每轮总时限 | 约 90 秒 |
| 同一教学步骤补救 | 换表述 → 简单例子 → 前置知识，最多 3 次 |

失败重试、图片理解和汇总均计入预算。一个对话不能靠新建 run 重置当前教学步骤的重复补救状态；新数学主题有独立教学状态。全会话不设置永远耗尽的 30 次总调用上限；用户分钟/日 Token、并发和费用配额由 Java 配置治理。摘要/记忆提取有独立有限预算，也计入用户总量；不可无限开后台任务逃逸预算。

到限额时用可靠已得证据给简化答复；检索故障可给明确标注未引用题库的一般数学说明；路由失败可由 Coordinator 有界回答；全模型不可用时固定失败说明并保留问题。状态区分 DEGRADED、LIMIT_REACHED、CANCELLED、FAILED 与正常完成，首期不转人工。空召回不是非数学的充分条件；领域判断独立于索引命中。

## 6. 记忆与学生画像

使用全局 IAM userId，不使用 enrollmentId 或课程学生编号。只读年级、进度、真实作答/错题、已公布成绩/知识点、明确偏好和历史摘要；不编造精确能力百分比。

讲解方式优先级：本轮明确表达 > 明确保存的偏好 > 有效历史推断 > 默认分步指引。明确要求完整解答时可以完整回答。学生说“我不会”立即调整当前讲法，不能单凭求助永久判弱，也不能拿旧画像否定学生。

画像采用少量宏观能力维度（计算、推理、逻辑等）与有证据的主题级状态，附少量具体卡点；不为所有知识点预建状态。精确知识点关系仍归原始作答事实。首期分等级，不作未经校准的精确评分；枚举由契约任务结合现有事实定义。

正式作答/教师批改是强证据，练习/错题重做次之，聊天中提供的解题过程更弱；“懂了”不等于掌握。模型只提出候选证据，Java 校验来源/公布权限/版本并按可解释规则聚合。原批改更正时更新证据效力，不把旧分数和新分数重复累加。

有效轮次结束后按增量决定是否提取；正式作答或批改变化更新对应主题。寒暄不更新，不每句重写整份画像；失败保留上一版，不影响当前答复。

| 层 | 内容及保留 |
|---|---|
| MySQL 事实 | 原始消息默认 180 天可配置；摘要、记忆、偏好、证据和用量按类型管理 |
| Redis 活跃状态 | 最近轮次、run 状态/租约/预算、短期事件和待确认动作缓存；TTL 后从持久事实恢复或明确终止 |
| Qdrant 活跃记忆 | 有价值经历、未解决卡点、相关摘要；不存寒暄、重复工具日志、签名 URL |

按 token 预算压缩，通常保留最近约 6 轮，并保留当前未解决问题、公式、题目上下文与待确认操作；摘要记录覆盖范围和版本，不能把总结当原始事实。用户不查看内部画像或记忆管理页；只可修改讲解偏好，首期无手动删除/忘记记忆功能。

普通经历随时间降低召回优先级，已解决困难退出活跃层；实际再次讨论/验证才能延长有效性，仅检索不能续命。明确偏好持续到用户修改，推断偏好可衰减。曾掌握的历史证据保留，长期未验证降低当前可信度，新证据可修正当前判断，不单凭时间判未掌握。普通低价值过期向量分批清理，原始会话期限单独治理。正式清理须处理可解释证据快照与媒体引用释放；本地可关闭自动清理。

## 7. 数据模型所有权

T14.1/T14.2 在 agent-access 自身 Schema 向前建立所需表，不预建其他领域表。逻辑表职责如下，具体字段/索引/迁移号在任务开始时核对，禁止猜测已用迁移号：

| 表 | 事实 |
|---|---|
| ai_conversation / ai_message | 会话 owner、入口、标题、消息内容和逐消息上下文 |
| ai_run / ai_tool_call | 执行终态、预算、模型、耗时；工具 ID、脱敏参数/结果摘要 |
| ai_skill_execution | T13.5.1 向前新增的 Skill 名称/版本、选择来源、相对 reference/脚本、状态、耗时与安全失败码；脚本前先落审计，崩溃残留收口为 ABANDONED |
| ai_pending_action / ai_pending_action_audit | T14.3 已落地的练习建议、确认/取消/过期、Java 执行结果及脱敏状态审计；MySQL 是唯一事实源 |
| ai_conversation_summary | 覆盖消息范围、摘要版本 |
| ai_memory / ai_memory_evidence | 类型、来源、有效性、保留期、证据 |
| ai_profile_topic / ai_preference | 主题与宏观维度的轻量判断、明确/推断偏好 |
| ai_usage_record / ai_safety_event | 调用/Token/成本事实及脱敏安全审计 |

跨服务只保存稳定 ID，不跨 Schema Join/外键。MySQL 唯一约束、事务、revision 和普通测试优先，不额外引入 hash、第二套 baseline/gate。Outbox 和消费幂等复用项目规范。

## 8. 检索与知识图谱

新方案停止使用旧 FAISS；旧文件不在本次删除。Qdrant 是向量/词法派生索引，Neo4j 是知识关系派生图，MySQL 中已有的知识点、关系、题目、课程和记忆分别由所属 Java 服务作为事实源。T10B 已导入知识图谱；实施时先核对已存 ID/来源映射，不因找到原 JSON 就再次全量导入。

| Qdrant collection | 内容 | 强制范围 |
|---|---|---|
| math_questions | 正式题目版本的安全可检索投影 | ACTIVE SYSTEM 初中数学；教师私有/未公布答案不得混入普通学生结果 |
| math_knowledge | 知识点说明、别名、关系文本 | 启用学段、主题、有效版本 |
| course_content | 已发布允许检索的文字片段 | 经 Java 授权的课程版本和课时范围 |
| student_memories | 各学生活跃长期记忆 | 服务端注入全局 userId、有效期和来源访问范围 |

不为每个学生建 collection；共享集合建立 payload 索引，容量增长后分片/副本扩展，实测后规划迁移与备份。collection 不是只能放在一台机器上的容量边界，本期不搭 Kubernetes 集群。

Java 事务 → Outbox → RabbitMQ confirm/return → 独立 Python Index Worker → Qdrant/Neo4j。消费者按 eventId 幂等并拒绝旧业务版本覆盖新版本；删除/归档也同步，失败有限重试与 DLQ。全量重建从分页内部 API/受控导出读取，有界批量、检查点和对账，不跨库读表、不自动删除旧数据。T13.2 先验证内容索引与记忆事件协议替身；真实个人记忆事件源和事实表由 T14.2 接通后才能宣称四类真实同步闭环。索引积压明确可观测，不把检索投影延迟伪装成源数据不存在；在线数据最终仍由 Java 校验。

课程检索先由 Java 解析可信范围，Python 强制过滤；索引中不得保存用户名单作为唯一 ACL。候选进入模型前再次核验当前资源版本/可见性，防止退课、下架、索引旧数据泄露；重新取授权正文或剔除失效候选。权限服务失败时停止该受限检索，不退化为全库搜索。公共数学知识可继续使用。

会话摘要可保留过去合法对话，但不复制大段受限课程正文/课件/答案；来源受限记忆带访问范围，退课后不可继续召回该专有内容。原始历史不会成为重新获取课程原文的通行证。

意图分路：解题优先精确题目/题库再知识补充；概念优先知识；主动课程问题先授权课程再公共知识；检查过程使用题目与相关知识；错题用本人事实；学习建议通常不查题库；寒暄不检索。图片/公式识别不确定先澄清，不能把不可靠 OCR 当事实。

Dense 复用本地 `bge-base-zh`（768 维），查询按模型说明加检索指令，文档不加；Sparse 使用具备中文/多语言分词的 BM25；RRF 融合后由本地 `bge-reranker-base` 重排约 20～30 条候选，普通回答最终约 3～8 条。T14.3 的 `RECOMMEND_PRACTICE` 为满足 1～20 道主问题的业务上限，可保留最多 20 个仅含稳定身份与安全元数据的候选，仍由 Learning 逐项复核后才形成待确认动作；其他意图继续保持 8 条上限。各集合/意图的阈值通过真实题目验证，不能沿用旧 0.42/0.38。BGE-M3 暂不下载，同向量字段不混模型；模型升级须重建索引。实现时核对 Qdrant 服务端 BM25 和客户端版本，不能把英文默认分词或仅全文过滤冒充 BM25 排序。

Neo4j 仅按需查询有界前置/后续关系，主要用于前置知识回退和学习路径；不存学生画像，不每次解题都查。故障时省略图关系增强，继续公共知识讲解。仅执行受控参数化查询，模型不得自由生成无界 Cypher。知识图可从既有 Java 事实重建。

## 9. 图片、模型和安全日志

图片经 Media 正常上传、类型/大小/READY/用途校验，Java 校验 owner 后传递 mediaId、MIME、大小与短期读取投影。Python 不接收学生任意 image_url，不接 OSS SDK；临时读取只限批准媒体地址，检查重定向、响应大小、超时并及时清理。默认使用多模态模型，不另建 OCR 微服务；低确定性题意需要学生确认。

聊天与视觉分别配置，可指向同一支持视觉的模型；只有图片需要时才调用视觉，故障时允许改用文字。Embedding/重排本地运行，聊天模型是否远程沿用供应商配置，不把“本地检索模型”误写成“全部聊天完全离线”。模型调用计入真实预算。

工具审计只保存名称、状态、耗时、traceId、资源 ID 和脱敏摘要。默认不记录全量参数/结果、提示词包、完整答案/正文、令牌、签名 URL 或二进制；local/test 诊断同样不得输出秘密，有限保留。对学生仅显示可理解阶段和授权来源，不伪造来源或暴露隐藏画像。

## 10. 后移能力

### 标准 Skill Runtime：T13.5.1 → T13.5.2 → T15C

T14.3 已于 2026-09-13 实现，外部契约为 OpenAPI 0.23.4，内部 Agent 契约为 1.3.0。当前 Python 的 `public-practice-generation@1.0.0` 实际是硬编码 `PracticeGenerationSkill` 单例，运行时没有 `SKILL.md` 发现、注册、渐进加载或通用脚本执行，名称/版本和权限还重复散落在 Python、Java 与描述性 YAML 中。该实现可工作但不满足平台确认的标准 Skill 形态，因此 T15C 暂停，不把现状继续扩展为第二套机制。

T13.5.1 建立项目自身的标准目录 Runtime，固定从 Python 包内 `edu_agent_app/skills/*/SKILL.md` 启动扫描，只发现 Git 审查并随 wheel 发布的一层内置目录；禁止用户目录、在线安装、热加载、符号链接和路径逃逸。标准入口只要求 `name`、`description`，可选 `metadata.version` 与 `metadata.script-timeout-seconds`；其他专家、意图识别、记忆压缩和基础工具不改成 Skill。未来只有用户明确要求或总控评审认为适合时才新增 Skill，且不得再创建 Python `SomethingSkill` 类或全局单例。

选择顺序为显式开发测试调用优先，其次规则/一二级意图筛选，再在多个允许候选中用一次计费、计预算的 LLM 结构化选择；唯一候选直接使用，无匹配走普通专家回答，不反复选择或并行试跑。学生界面不展示 `$skill-name`、内部名称或脚本路径。每个子请求最多一个 Skill，一轮最多两个；Skill 指令优先级低于平台安全、用户明确要求和 Runtime 公共规则，不能扩大工具 grant、资源 scope、调用预算或 Java 写确认权限。

Skill 选中后才加载完整 `SKILL.md`，模型只能通过 Runtime 的 `read_skill_reference` 读取当前目录 UTF-8 文本，通过 `run_skill_script` 执行当前 `scripts/` 内的 `.py`；绝对路径、`..`、符号链接、二进制和其他 Skill 均拒绝。默认每轮最多 3 个 reference、单文件 128 KiB、总量 256 KiB；脚本默认 10 秒、Skill 可在全局 30 秒上限内申请，输出最大 64 KiB，全局并发默认 4。上述均为可配置默认值并计入现有上下文、工具、模型和总时限预算，取消/断线/耗尽立即终止，不遗留后台进程。

脚本属于受信生产代码，但仍以只读 Skill 目录、独立临时工作目录、清理后的非秘密环境和 JSON stdin/stdout 运行；首期只支持 Runtime 已安装依赖中的 Python，不自行安装包、不访问网络/数据库、不启动子进程。Runtime 使用 `yaml.safe_load`，因此 PyYAML 进入正式依赖；本地仍可用既有 `D:\Anaconda\envs\langgraph\python.exe`，部署与 CI 只依赖仓库声明，不依赖该绝对路径。

Runtime 为成功脚本输出生成模型不可伪造的 `skillName`、版本、script、executionId、resultType 和 payload 信封。Skill 选择后、脚本执行前必须经 Agent Access 私有接口落 `ai_skill_execution`；记录失败则 fail closed，不执行脚本且不产生组题动作。审计只存内部 ID、顺序、名称/版本、选择来源、相对 reference/脚本、状态/耗时和安全失败码，不存指令正文、输入输出、题干答案、秘密或绝对路径；Python 崩溃或 run 终态时将遗留 RUNNING 收口为 ABANDONED/RUNTIME_INTERRUPTED，不自动重跑。该私有事实需要向前迁移和内部协议，不通过浏览器 OpenAPI、SSE 或 RabbitMQ 暴露。

T13.5.2 使用 Codex skill-creator 生成骨架后精简为 `edu_agent_app/skills/public-practice-generation/SKILL.md`、`scripts/validate_proposal.py` 和 `references/practice-rules.md`；无消费者的 `agents/openai.yaml` 删除。新版本为 `1.1.0`，部署时 Java 先兼容新版本再切换 Python；历史 `1.0.0` 记录继续可读，但旧 Python 类、单例和专用执行分支全部删除。组题脚本只处理主题/难度/数量默认与边界、组合题计数、候选去重和结构校验；Qdrant 继续只经 `QUESTION_SEARCH` 工具，Java 继续复核和创建，模型文本伪造的 proposal 不得进入 pending action。

迁移后主题仍从明确请求/当前对话取，缺失澄清；默认中等、5 道，1～20 主问题，组合题不拆。只选 ACTIVE SYSTEM 初中公共题，套内去重、尽量避开近期题；数量不足先说明，不静默放宽。Agent Access 在写入 `ai_pending_action` 前调用 Learning 复核，确认时再次复核并以 `sourceActionId` 调用 Learning；Learning 以唯一约束事务化创建 `AUTONOMOUS` PRACTICE。T13.5.2 必须以真实 Qdrant→Java 复核→确认→创建→作答→清理长链证明行为不退化，且保持 T15C 所需 OpenAPI 0.23.4 浏览器契约兼容。

Java 保存经过校验的 pendingAction，默认 10 分钟过期，绑定用户、参数、revision、候选版本/条件和确认身份。学生明确确认后由 Learning 创建普通自主练习，无倒计时，复用作答/评分。条件或数量实质变化重新确认；修改条件使旧建议失效。文字“好的”仅在唯一、明确待确认动作时适用。重复确认/超时重试必须返回同次结果，未知结果先查询；数据库事务和唯一约束负责最终幂等。

T13.5.1/T13.5.2 合并后重新准备 T15C。成功卡片显示主题/实际题数/开始练习，不强制跳转；失败保留条件。模型小例题只用于聊天，不自动成为正式题目、试卷或评分答案。Skill 创建练习不授权 Agent 替学生提交或打分。

### 平台帮助：T13.4

建立平台维护、面向用户、可版本化的帮助知识库，由 Java 提供。首期可用随 agent-access-service 发布的版本化帮助文件和只读查询 API，不为尚无编辑后台的内容另建管理系统。稳定问题规则优先，复杂问题再检索/模型；不暴露 page-specs 原文、不猜路由。首期不做帮助内容编辑后台，未交付前不宣称该专家能执行完整平台帮助。
