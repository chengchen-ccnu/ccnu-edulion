## 3. 产品与授权边界

- Operation 拥有公告稳定身份、不可变审计版本、确认事实、消息投递/未读和有界工作事实。Course/Learning/IAM 保持各自事实源，跨域只经版本化 API/事件；消息只保存必要标题及目标稳定 ID，不另复制一份公告正文或资质理由。
- 公告只有当前 owner 教师可在已发布课程创建/改版/撤回，草稿和归档课程不发新公告；仅标题＋纯文本，保留换行，普通 https 只作文本，无附件/HTML/Markdown/定时发布。管理员不代发，不做阅读名单或催读。
- 当前 ACTIVE 报名学生可读仍有效公告；owner 不作为学生收件人，游客/试看/退课者不可读。新报名者可读旧公告但不补旧提醒/置顶。归档历史仅在领域仍授权时可读，不能凭 Operation 自己的缓存制造课程访问权。
- 发布/改版时定向通知当时有资格的学生。同一公告/学生仅一条消息，改版更新标题并重置未读/确认，历史版本供审计。旧版本确认必须带版本/revision校验，不能在并发改版后静默确认学生尚未见过的新正文。撤回后列表和旧链接不再提供正文，投递/决定历史不删除。
- 最新未确认项及其他待确认数量由有界查询提供；只点“我知道了”才同时确认公告并清对应消息未读，加载列表/打开消息不确认。“全部已读”只处理普通消息并返回剩余待确认公告数量。
- 四类消息：课程公告；课程 HOMEWORK/EXAM 新开放/最终截止变更/教师立即结束；本人教师资格结果；课程暂停/恢复。不通知 PRACTICE/公共题库/Agent 练习，不发 SMTP/SMS/营销，不提供用户删除或统一7天TTL。
- 任务只在服务端真正开放且有访问权时提醒一次；重试时重新判断是否仍可作答，结束/暂停不补发误导性的新任务提醒。普通消息成功进入授权目标后才标已读；不能把消息列表 GET 当已读，或凭任意前端目标 URL 绕过领域校验。
- 退课/撤回等失去资格后，可打开列表及未读统计应使用一致的当前访问口径，保留内部投递审计。课程暂停/恢复系统消息必须仍可告知 ACTIVE 学生通用不可用状态/支持邮箱，但不得因此授权访问暂停课程正文；审核消息不带资质材料或完整驳回原因。
- 暂停/恢复继续沿用 T16.1/T16.3 的区间顺延与旧令牌安全边界，不重新解释为暂停期间判缺交。头像菜单和 `/notifications`、课程公告区/教师管理区的页面职责不改变，Vue 留 T17A/T17B。

## 4. 必须先评审的实现难点

1. **收件人时间口径**：当前 enrollment 重报会更新 enrolled_at，Course 访问投影是异步且只保存最新状态。不能按异步消费者执行时的当前名单给后报名者补发历史提醒。契约需定义公告发布时间/真正开放点的有界收件人事实或可靠快照，并区分触发时资格与读取时资格；仅在 Operation 加一个“当前名单缓存”不足。
2. **到时触发与恢复**：开放调度需持久化幂等标识、有限批次/领取与失败事实，处理发布已到时、未来开放、宕机恢复、截止变更和课程暂停。消息失败不回滚作业/公告/审核事实；截止/结束事件在原领域事务内写 Outbox。
3. **大名单与乱序**：fan-out 分页/批次有界且可恢复，禁止在一个 HTTP 事务逐学生跨服务查询。版本、水位和唯一约束防重复/旧改版覆盖新确认，撤回、退课和暂停到来后不继续错误发信。复用普通事务/索引/类型/测试，不新增通用工作流或 hash/baseline/gate。
4. **权限与失败**：内部 caller 不由浏览器伪造；依赖失败应503或明确可重试，不能返回空名单/假零/读取成功。跨域响应保持最小安全投影，未授权资源安全404；未读缓存不能替代 MySQL事实或实时访问判断。
5. **RabbitMQ拓扑**：独立消费按 eventId 持久幂等、confirm/return、有限重试和DLQ，原队列属性兼容，禁止purge/抢占/改造现有队列。使用既有事件时先核对 schema和兼容新增，不改写已发布版本。

这些补口属于 T16.4 契约设计，不要求已有接口凭空满足。若实施任务发现必须改变已确认产品规则或页面职责，停止对应扩展并向总控报告，不自行引入平行页面或第二套通知系统。
