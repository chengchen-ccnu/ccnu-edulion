## 3. 必须落实的产品和安全边界

- 列表读取不改状态。管理员明确进入详情时才从 SUBMITTED 进入 UNDER_REVIEW；记录首次查看者/时间但不独占，其他管理员可接手。最终决定按 revision/409，已批准/驳回决定不得改写；重提创建新轮次，学生只见最新安全投影。
- 列表支持四状态、申请时间排序和申请编号/规范化账号身份精确查询，有界分页与稳定次级排序；不直接返回联系方式/资质文件。管理员详情才返回必要数据及审计，禁止学生读取他人或管理员完整投影。
- 批准必须显式确认当前资质材料已核对；材料失效、不可授权或无法打开不得当成批准成功。驳回原因需能被申请人理解。审核决定、角色授予与安全审计在 IAM 一个事务内完成，重复请求不重复决定/授权；批准不得产生仅教师或管理员混合身份。
- 待审、通过材料持续保留，包括后来撤权。被新材料替换且不再作当前依据的旧文件从替换起 7 天清理；被驳回文件从决定生效起 7 天清理。若同一 mediaId 仍有有效引用不得误删；到期只失效文件，保留轮次/决定/审核人/原因。须明确 IAM 保留截止、引用释放与 Media 原有回收宽限期的实际关系，不把“已释放引用”虚报为“文件已删除”。消息不套用 7 天 TTL。
- 资质仅经 Media 签发短期图片/PDF 预览或授权下载；响应/事件/日志不保存 Bucket、Object Key、秘密或永久地址。普通用户不得靠猜申请/材料 ID、伪造角色头或重放服务授权绕过领域审批。
- 审核决定事件与事实同事务 Outbox，失败不回滚已批准资格，也不假称消息已送达；仅传稳定标识和必要状态，不传文件、联系方式或完整驳回原因。实际站内消息留 T16.4。
- 不新增 OCR、多级审批、课程审核、资格撤销页面、复杂 manifest/hash/gate。分页/查询和清理必须有界，不引入申请×文件 N+1 扫描。

## 4. 环境与验证前置

共享 `Invoke-WithLocalEnvironment.ps1` 能加载配置。只检查配置存在布尔值：MySQL、IAM Schema、Course/Media 服务秘密、OSS endpoint/bucket/AccessKey、RabbitMQ 用户/密码已配置；本机 3306/6379/5672 TCP 可达，未打印秘密。该检查不等于 IAM/Media 真实 HTTP、OSS 或审核认证已经验收；功能任务须通过包装器自行启动并验证。无需额外安装 Neo4j、Qdrant、Python 模型或 FFmpeg。

IAM 当前迁移 V3，Media V6；下一版本在实施时重新核对。需要的新 IAM Outbox/历史表及 Media 授权支持是本任务内容，不提前创建。JDK 17/Maven 及现有 Node/pnpm 基线可用。T16.1 无 BOM 中文脚本在 Windows PowerShell 5.1 下解析失败，已用 PowerShell 7.6.5 完成复验；新验收脚本须明确支持版本及编码，不扩大成无关脚本改造。

验收应覆盖：管理员/普通账号/错主体权限，列表不变状态，详情首次查看/多人审核，409 和幂等决定、事务回滚，批准保留学习并刷新教学能力，驳回重提和旧历史不改写，材料错 owner/用途/非 READY/授权失败/重放，7 天边界及持续保留，同媒体有效引用保护，Outbox 失败/重试/DLQ，真实 Gateway→IAM→Media→OSS 与 RabbitMQ 引用链。不能用 H2/假存储冒充真实资质文件可读。
