# T16 已确认范围与实施拆分

> 2026-09-29 总控产品决策。本文确定范围、边界与依赖，不替代 OpenAPI、事件 Schema 或实现验收；T16 功能任务仍须先冻结相应契约。历史代码事实见 [T16 前置审计](T16-precontract-audit.md)。

## 1. 首期范围

首期交付教师资格审核、管理员账号与普通账号权限管理、教师撤权后的课程暂停与任务时钟处理、课程公告、四类站内消息，以及 Redis 派生的首页热点课程。前后端都完成才能称为闭环。课程收藏/评价/评论/点赞/举报、课程审核、首页人工运营位/Banner/专题、营销消息和报表导出不在本期。既有安全校验不能因范围收缩而删除。教师仍按 Course 已有规则直接发布，无课程审核关卡。

## 2. 账号、审核与课程暂停

- 普通账号只能是学生、学生＋教师、或两者均无（封禁）；不允许仅教师。首次授予教学能力必须有通过的资质审核事实，后续可由管理员按既有批准记录恢复。管理员是独立身份，不具有学习/教学能力，不可公开注册、申请教师或通过普通角色勾选获得。正式首位管理员由受控初始化创建，后续管理员由现有管理员按已验证邮箱邀请、受邀者自行设密码；现有本地管理员仅作测试。管理员同权，不额外分教师审核员层级。不能自封禁或停用最后一名可用管理员；管理员互相操作须说明原因、二次确认和审计。
- 教师申请由 IAM 拥有。管理员主动打开详情时才从待审核转为审核中；列表浏览不变更。审核中不独占，首次查看者和最终决定者分开记录，最终决定用 revision/409 防覆盖。列表可按待审核/审核中/通过/驳回筛选、时间排序和精确查找。材料仅授权管理员短期预览图片/PDF，若浏览器预览不可行可提供授权下载；无法打开材料不得批准。批准必须确认材料，驳回必须填申请人能理解的理由。决定与同账号能力授予在 IAM 可靠事务内完成，学习能力保留；申请人打开申请页后刷新会话能力，无须重新注册。批准/驳回历史、审核人和时间不被新决定覆盖；驳回后可替换材料重提，不允许待审时任意撤回。误驳回通过重提处理，普通撤权另走权限管理。
- 待审材料和通过后的资质材料持续保留，包括教学能力后来被撤销时；被新文件替代且不再作审核依据的旧材料从替换起 7 天后清理，驳回申请的资质文件从驳回决定起 7 天后清理。状态、理由、审核人/时间和安全审计不随文件清理。IAM 负责媒体引用并通过 Media 短期授权读取，避免未绑定资产被现有 24 小时回收器误删。不能将“7 天”扩展到站内消息或其他数据；站内消息首期不按 TTL 自动删除。
- 管理员可单独撤销/恢复有历史批准记录的教师能力，也可按合法组合禁用普通账号。撤权、禁用均需原因、影响人数展示、二次确认和审计，立即使旧教师令牌失效。正确密码之后才向被封禁者提示“账号已封禁，请联系管理员”；未知账号/错密码仍统一响应；已登录会话立即失效。管理员不能用勾选代替首次资质审核。
- 撤销教师能力或封禁教师时，该教师**所有已发布课程**进入独立系统暂停状态；已主动下架、草稿或归档课程不变。学生、游客和教师均不能继续读取暂停课程内容、发起新作答/保存或取得新媒体授权；已有短期 OSS URL 只保证原有效期届满失效。列表不推荐，已有链接只显示“课程暂不可用”和配置的支持邮箱，不泄露审核原因。报名、进度、作答、草稿、成绩均保留；Redis 尚未落库进度必须在明确暂停边界结算或舍弃并提示，不可继续悄悄累计。不得只封住课程详情而漏掉旧 attempt ID 直达接口。
- 权限恢复时仅自动恢复由**本次撤权**暂停的课程，不恢复原本下架/未发布/归档课程。课程暂停期间受影响 HOMEWORK/EXAM 停止计时和自动结算，不生成缺交、零分或排名变化；恢复后将受影响任务及未提交草稿的截止时间按**实际暂停时长自动顺延**，保留剩余作答时间，教师随后可按已有规则再调整。暂停前已关闭、提交或批改的事实不变，不新增“重开已关闭测评”。对已公布答案、任务状态和重复事件需先定义安全迁移与幂等边界，不能简单修改当前截止字段。

## 3. 课程公告与站内消息

- 仅课程 owner 教师可在本人**已发布**课程教学管理区发布、改版、撤回公告。标题＋纯文本正文，保留换行，不支持 HTML、Markdown、图片、附件或定时发布。学生公告区位于 `/courses/:courseId` 的介绍之后、目录之前，但必须独立受保护：只有当前 ACTIVE 报名者可读，试看者/游客不可借公共课程详情响应读取；owner 从教学管理区管理。归档课程不发新公告，仍有课程访问权者可看历史有效公告。
- 发布时当前 ACTIVE 学生收到提醒。公告改动产生保留审计的新版，对这些学生重置未读/确认并更新**同一条**消息的最新标题，不堆重复投递；学生只看最新版、不显示“已修改”。撤回立即从学生公告区及可打开消息中移除，旧链接不可读，教师仍可见撤回与审计。新报名者能读仍有效的旧公告，但不补发过去的通知或置顶未读。退课者无权再看正文或打开旧消息；投递事实仍保留审计。
- 学生首次进入课程页突出显示最新未确认公告及“还有 N 条未确认”，可展开逐条点击“我知道了”；只有明确确认才同时清除公告置顶与对应消息未读，页面加载/点开消息不算。已确认公告仍在列表。教师首期不看个人已读名单或催读。公告确认事实不能随消息副本清理而丢失。
- 头像菜单唯一“消息”入口与未读角标打开 `/notifications`；三端取消独立通知工具槽位，不产生重复入口。消息首期仅四类：课程公告、课程 HOMEWORK/EXAM 新开放/最终截止变更/立即结束、教师资格审核结果、课程暂停/恢复。普通任务/审核结果在成功进入授权目标后已读；公告仍需“我知道了”。“全部标已读”只处理普通消息，返回剩余待确认公告数。列表分页；用户不能删除，**没有统一 7 天消息 TTL**。链接打开前重新验权；退课、撤回等使旧入口不可打开。审核消息不泄露完整驳回原因或材料；课程暂停消息只说明状态和支持邮箱。
- 任务消息以服务端真正 `opensAt` 到来、且当前 ACTIVE 学生可访问时发一次，不以教师预先发布作为开放。后报名者不补旧提醒。仅课程 HOMEWORK/EXAM，排除 PRACTICE/公共题库/Agent 自主练习；任务最终截止变更或教师立即结束再发相应消息。重试时再次检查任务与课程访问状态，已结束/暂停不得发误导性的“新任务可作答”。业务决定先可靠提交，再由 Outbox/发布确认/有限重试/DLQ 异步送达；消息失败不回滚审批/公告/任务事实，须可监控补偿。作答权限永远由 Learning 实时裁决，不依赖通知。

## 4. 首页热点

首页展示 6 门视觉完整的公开课程卡片。最近 7 天去重学习人数为主信号、有效报名人数为辅助；不用原始观看秒数、收藏、评价、点赞或举报。数据不足时展示明确标为“新课”的近期公开课程，不能伪称热门。首页**只读取 Redis 派生排名**，领域 MySQL 是事实源，可由可靠事件和受控重建恢复；Redis 故障时热点区单独显示暂不可用，普通搜索/课程列表照常，不在首页请求中同步扫库重算。

## 5. 实施顺序与验收边界

| 任务 | 主要交付与依赖 | 不包括 |
|---|---|---|
| T16.1 课程暂停与任务时钟后端契约 | Course 发布可见性、Learning 访问/作答/进度门禁、暂停区间和 HOMEWORK/EXAM 顺延；基于 T05/T11C/T12G 已合并事实，先解决撤权依赖 | 管理页面、通用停服补时、已关闭测评重开 |
| T16.2 教师资格审核后端契约 | IAM 审核决定/历史/能力授予、资质 Media 引用与短期授权、申请人安全投影；依赖 T12D/T07 | Vue、课程审核、自动 OCR |
| T16.3 账号权限与管理员邀请后端契约 | 管理员独立身份、邀请、普通账号权限组合、撤权/封禁与 T16.1 暂停协调、会话失效；依赖 T16.1/T16.2 | 随意直接授予首次教学能力、用户注销 |
| T16.4 公告与站内消息后端契约 | Operation 公告/投递，Course/Learning/IAM 可靠触发、任务到时开放与补偿；依赖 T16.1～T16.3 | 前端、邮件/SMS/营销、课程审核 |
| T16A Redis 热点派生 | 7 天去重学习/报名信号、Redis 排名/重建/隔离故障；依赖 Course/Learning 可靠事实，消息未读可有短期派生缓存 | Redis 业务事实源、收藏/评价打分、请求时 MySQL 热榜回源 |
| T17A 学生首页与消息/公告前端 | 热点卡、课程页受保护公告区、头像菜单与消息页、申请结果及会话刷新；依赖 T16.2～T16.4/T16A | 收藏评价、通用反馈入口 |
| T17B.1 教师公告管理前端 | 在本人课程教学管理区发布/改版/撤回、分页审计和显示状态；依赖 T16.4 与已合并 T17A；2026-10-03 总控拆分后的优先任务 | 工作台/媒体中心/资料、管理员代发、课程审核 |
| T17B.2～T17B.4 旧教师规划独立审计 | 分别对应工作台、媒体中心、资料；须先明确最小范围及缺口契约，不能与公告任务混做 | 占位成功页、虚构摘要、猜测引用/账号写接口 |
| T17C 管理端审核与权限前端 | 管理壳、教师资格审核、账号权限/禁用/邀请；依赖 T16.1～T16.3 | 课程审核、治理/运营位/报表空页面 |

每个切片须先评审 OpenAPI/事件契约，再实现生产者和消费者，并按已有数据规则做真实验收与精确清理。审核后端不等于管理端审核完成；消息后端不等于公告及消息前端完成。T18 负责跨端回归和故障演练，不替代上述业务功能。T12H 账号注销需另订跨领域保留/匿名化规则，不能借此擅删资格决定、公告确认或消息审计。

## 6. 仍需在功能任务中验证的实现难点

现有 Course 只有草稿/发布/下架，Learning 的旧 attempt 深链、自动关闭和 Redis 进度缓冲未感知“暂停”；必须以端到端授权和时钟用例验收，不能仅改课程列表。现有 IAM 申请只提供提交/本人查询，Media 未绑定资格材料可能提前回收；审核必须补可靠引用。Operation 仍是骨架，通知、任务开放事件与热点投影都不存在。管理员邀请、暂停时长顺延和消息四类契约目前未进入 OpenAPI/事件 Schema；本文仅冻结产品语义，不宣称实现前置已全满足。
