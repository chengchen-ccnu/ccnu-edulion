## 1. 结论与依赖

**基础依赖满足，首个 T16 实施任务暂不可启动。** T06 的角色中立课程列表/详情和教师本人课程管理已合并；T12D/T12D.1 的教师申请提交、同账号能力基础、管理员账号命令及安全会话已合并；T07 的通用媒体上传、短期授权、引用台账和可靠消息基础已合并。T12E 已提供申请人页面，但不含审核决定。证据见 [backlog](backlog.md)、[verification](verification.md)、T06/T07/T12D 交付文档及当前代码。

阻断的是产品与跨域语义：教师审核由谁记录决定及何时授予/撤销能力、课程审核如何与现有立即发布命令兼容、互动可见性与资格、举报处置、通知触发和保留、运营内容发布规则及 T12H 注销后的归属/匿名化。OpenAPI 目前仅有教师申请提交和本人查询、现有课程直接发布与通用媒体接口；没有这些新业务接口。`docs/events/` 也没有对应的审核、互动、通知或运营事件 Schema。不得依据媒体枚举或管理端既有路由推定业务契约已就绪。

## 3. 领域归属与待补契约清单

以下“候选归属”遵守现有服务边界，具体写模型和流程仍待确认。所有对外接口必须先进入 `docs/api/openapi.yaml`，跨服务事件先进入 `docs/events/*`，再实现生产者/消费者；不能跨服务查表。

| 能力 | 候选事实归属与授权来源 | 当前缺口及需定义的状态/边界 |
|---|---|---|
| 课程收藏、最近浏览 | 收藏可由 `operation-service` 保存用户与课程的互动事实；Course 提供当前发布/可见事实，IAM 提供主体能力。最近浏览在页面规格中属 T17A，但是否服务端持久化及保留期限未定 | 收藏/取消/本人分页/公开计数与下架后的显示、重复命令、账号注销处理均无 API。不要把 Learning 报名当收藏；最近浏览不能从课程详情请求凭空推断。 |
| 课程评价与摘要 | 互动事实候选归 Operation；评价资格必须调用 Learning 报名/学习事实，课程当前状态由 Course 裁决；公开摘要可在 Operation 聚合后供课程详情消费 | 评分尺度、是否仅一人一课、修改/撤回、资格点、版本归属、审核/隐藏与反刷、已下架课程及空样本语义均无契约。前端已要求服务端判断评价资格。 |
| 评论、点赞、举报 | 内容、反应和举报/处置事实候选归 Operation；课程/教师内容的可见性需领域 API 校验 | 评论挂载对象、回复层级、编辑删除期限、点赞幂等/计数、举报对象/理由、重复举报、待审/隐藏/驳回/恢复、申诉、滥用限流和公开投影均未定义；不能把“点赞”默认等同课程收藏。 |
| 公告、通知 | 公告/运营发布候选归 Operation；站内通知的投递及已读事实亦可归 Operation，触发源由领域事件/API 提供最小事实 | 公告发布/撤回/生效窗口/受众，通知类型、触发源、目标跳转白名单、本人分页/已读、去重、失败补偿、未读计数重建、注销保留均无 API/事件；T16A Redis 未读数只能是派生缓存。 |
| 教师审核 | 申请与账号能力事实已在 IAM；Operation 可提供审核工作台投影，但不能写 IAM 表。审核决定与 `teaching:access` 授予/撤销必须由 IAM 权威地完成或通过经确认的协议协调 | 管理角色与数据范围、领取/并发、资质短期预览、通过/驳回理由、重提、申诉、复审、禁用/注销后的行为和审计保留待定；不得由 Operation 伪造已授予能力。 |
| 课程审核 | 课程草稿、不可变版本、公开发布及 owner 均属 Course；审核队列/决定可由 Operation 管理，但 Course 必须以权威审核事实裁决是否发布 | 审核对象是课程还是具体版本、首次发布与再发布、修改后重审、驳回/撤回/下架、旧版本继续公开与否、老课程迁移、审核时媒体/题目预览和并发 revision 均未定义。现有直接发布命令必须有兼容方案。 |
| 运营位、Banner、专题 | 配置/排序/时窗/发布候选归 Operation；课程/教师候选的公开资格由各自领域复核 | 首页楼层/推荐位/专题的对象类型、槽位与排序、定时生效、过期/下架回源、受众、草稿/发布、缓存失效、资产替换和审核待定；T17A 只能消费真实公开投影。 |
| 媒体、导出 | Media 独占二进制与短期授权；IAM 持有资质引用，Operation 持有运营图引用；报表由发起导出的领域持有任务事实 | 需逐用途启用上传策略、`READY`/owner/用途校验、绑定与释放 Outbox、审核前私有预览和发布后公开授权。`REPORT_EXPORT` 不能套用已有 Learning 同步成绩册 CSV；先确认首期报表口径、任务归属、权限、期限和清理。 |

事件缺口至少覆盖决定后能力/课程可见性变化、通知触发、公开互动计数/热点缓存失效、运营位发布变更及媒体引用；哪些需要可靠跨服务事件、哪些用受控同步 API，应在逐项契约评审时确定。若采用事件，沿用 ADR-0005 的 Outbox、publisher confirm、有限重试/DLQ 和 `eventId` 幂等，事件只传最小稳定事实，不传资质正文、评论隐私、签名 URL 或完整用户资料。

## 4. 需要产品负责人确认的决策

### 首个实施任务之前必须确认

1. **首个切片的优先级**：先做教师审核闭环、课程审核兼容，还是较独立的课程收藏？建议先做收藏最小闭环，以免在课程发布和 IAM 权限语义未定时跨域改动；此建议不是自动授权。
2. **收藏规则**：哪些登录能力可收藏公开课程；课程下架后本人是否仍可见；是否允许重复收藏/取消及是否展示公开收藏数；最近浏览是否纳入首切片。
3. **T12H 最小保留原则**：注销请求/冷静期内互动是否继续可见；注销后收藏、评价、评论/点赞/举报、通知、审核记录分别保留、匿名化还是删除；被举报内容及审核审计是否需要保留证据。具体期限和法律依据须单独确认，不能从 AI 消息 180 天期限类推。

### 后续切片进入契约评审之前必须确认

4. **评价/评论**：评价资格采用报名、完成还是有效观看/作答事实；评分范围及每人每课规则；课程版本变化后的归属；评论对象、回复深度与编辑/撤回规则。
5. **内容治理**：普通敏感词与冒充治理的适用对象；举报受理、隐藏、恢复、申诉、重复举报和管理员数据范围；自动规则与人工决定边界。
6. **教师审核**：审核决定事实归 IAM 还是 Operation 编排；资质访问范围和失效；通过后同账号授权的原子/补偿语义；驳回重提、复审、申诉及已获教学能力后禁用/注销处理。
7. **课程审核**：审核粒度与版本生命周期；既有可直接发布课程及旧客户端如何迁移；教师修改/再发布时当前公开版本是否继续可见；管理员通过/驳回是否自动发布。
8. **公告/通知**：系统消息首期触发清单、受众、公告与个人通知区别、已读/过期、目标跳转、安全去重和管理员撤回规则。
9. **运营位与报表**：首期实际槽位、目标资源、排序/时间窗/下架回退；是否需要限期导出、导出的数据口径、导出者和可下载者。
10. **媒体安全**：资质、头像、Banner/专题和导出用途何时启用；未接恶意文件/内容安全外部服务前允许在哪些环境/场景使用；公开 CDN 只针对哪个已批准业务版本。
