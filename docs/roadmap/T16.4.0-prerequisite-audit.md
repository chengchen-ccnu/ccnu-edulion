# T16.4.0 Learning Outbox 索引一致性诊断、修复与发布回归

> 2026-10-02 总控准备。基线 `main@199c66ef95d310632ebb7f1ad1a1ed825966cc7d`，T16.3 已由 PR #82 普通合并。本任务是本地数据库可靠发布基础的维护补口，不实现课程公告、通知或其他新产品功能。

## 1. 为什么插入本任务

T16.3 完整真实验收已经记录 Learning 存量 Outbox 的主键/二级索引状态不一致，因而关闭全量发布器，只精确发布本轮报名事件。总控本轮再次通过共享环境包装器、只读 MySQL 查询复现该现象。T16.3 权限/邀请代码及其真实联动通过，不因旧数据异常阻止合并；但 T16.4 不能沿用“只发布验收指定 ID”来宣称真实全量消息发布健康。

在启动 T16.4 公告与消息后端前，先完成本维护任务。修复对象限定 `edu_platform_learning_dev.learning_outbox_event` 的已证实异常，禁止借机清空旧导入任务、检查点、题库或历史失败事件。

## 2. 实际证据与未查明事项

本轮只返回索引元数据、状态和数量，不输出事件正文/题目/答案/身份/秘密：

| 只读查询口径 | 实际结果 |
|---|---:|
| FORCE INDEX(PRIMARY)，按状态统计 PUBLISHED | 5,734 |
| FORCE INDEX(PRIMARY)，按状态统计 FAILED | 6,896 |
| FORCE INDEX(PRIMARY)，WHERE status='PENDING' | 0 |
| FORCE INDEX(idx_learning_outbox_pending)，WHERE status='PENDING' | 1 |
| 二级索引 PENDING ID 对应的 PRIMARY 行 status 不为 PENDING | 1 |

现有 V1 创建 `idx_learning_outbox_pending(status,next_attempt_at,occurred_at)`，没有新的任务索引或第二张 Outbox 表。`QuestionRepository.pendingOutbox` 按 PENDING/到期排序读最多 50 条，`LearningOutboxPublisher.publishPending` 使用这一生产查询，成功确认才写 PUBLISHED，失败有限退避后 FAILED。

这些证据确认查询结果不一致；尚未执行 CHECK TABLE、引擎诊断、备份或索引重建，尚未确定物理损坏原因、故障是否仅限二级索引，也不能把 6,896 条 FAILED 自动解释成需要重发的消息。功能任务应先在受控窗口做同一一致性视图下的只读复核，排除并发/连接/查询计划影响，再决定最小修复。

## 4. 最小实施方案

1. 先读 AGENTS、此审计、T16.3 交付/风险和 Learning Outbox Repository/Publisher/V1。确定开发库与本轮进程，不终止用户其他服务；若共享写入或发布器无法安全停下，报告并等待维护窗口。
2. 只读核对 MySQL 版本、引擎/DDL、主键/二级索引查询计划与一致视图结果，必要时运行有界完整性诊断。日志只保留状态/数量/安全失败码，原事件数据仅用于本机受保护备份，不进 Git 或聊天。
3. 修改前建立并验证这张表的可恢复备份，记录原结构与关键事实。若确认只损坏二级索引，优先在停止相关写入/发布的维护窗口重建这个原索引，定义与名称不变；这是物理维护，不改已合并 Flyway V1，不新增无必要业务迁移。
4. 若发现主键/数据页损坏，或备份无法验证，不做删表/重建库/全表覆盖；报告具体风险和恢复选择，取得进一步授权后再处理。不得用批量改状态掩盖异常，不把 FAILED 全改 PENDING，不自动重放历史消息。
5. 修复后复核主键/二级索引的状态、数量和目标行一致，验证旧事件 ID、载荷和尝试/时间/状态等事实未改；核对执行计划仍可使用既有索引。不要新增永久 baseline/hash/gate。
6. 使用最小随机合法事件和本轮隔离 RabbitMQ 测试绑定，真实运行既有 `publishPending` 批量查询/发布路径（而非只调用指定 ID publish），验证确认成功、return/NACK/故障有限重试、失败留痕与 eventId 幂等消费。清理仅限本轮事件/绑定/消息，不能 purge 共用队列，也不能重放或删除存量 FAILED。
7. 若只需一次性物理维护，不强行改生产 Java；保留最小安全诊断/维护脚本及回归测试和文档。只有诊断证实代码缺陷才提出小范围修复，不扩展成通用修复框架或第二套事件系统。
