## 2. 已发布契约与代码边界

| 接口/生成operation | 页面可以依赖的行为 |
|---|---|
| POST `/api/v1/admin/invitations` / `inviteAdministrator` | 当前有效管理员；`clientRequestId/email/reason`，原因10～500字。202返回单条安全投影；原请求精确重放不再次发信，改载荷同ID409。已绑定任意账号的邮箱409，不能转换普通账号 |
| GET `/api/v1/admin/invitations/{invitationId}` / `getAdministratorInvitation` | 当前有效管理员可按非秘密ID读取，不限原操作者；无全量列表、按邮箱或clientRequestId查找契约。只返回脱敏邮箱及发送/接受状态、revision、次数和时间，不返回凭证 |
| POST `/api/v1/admin/invitations/{invitationId}/resend` / `resendAdministratorInvitation` | 原逻辑请求ID和当前expectedRevision、10～500字理由；60秒冷却、总发送最多6次。新发送先作废旧凭证，重新起24小时有效期；已接受/冲突/次数耗尽不重发 |
| POST `/api/v1/auth/admin-invitations/accept` / `acceptAdministratorInvitation` | 精确公开入口；正文含invitationId/email/43字符URL安全secret/password/displayName；201仅返回userId、不签发会话。凭证、邮箱、到期、SENT和邀请者当前资格由服务端核验；错误主体/过期/未SENT/已用统一422，不可枚举 |

Gateway的IAM路由、邀请管理权限、公开accept精确白名单、会话版本过滤例外及分布式限流已存在；不能把 `/api/v1/admin/**` 公开。IAM V5已有 `administrator_invitation`、`administrator_invitation_command` 和安全审计，接受事务原子创建账号/验证邮箱/仅ADMIN角色并消费邀请；审计失败回滚。无需迁移、新DTO、MQ、缓存或后端补口。

发送状态 `PENDING/SENT/FAILED` 与接受状态 `AWAITING/EXPIRED/ACCEPTED` 是两个维度。202不能推断SENT，SENT只表示SMTP服务接受，不保证收件箱送达；PENDING可能因进程中断保持，不承诺后台会自动再次发送。服务端投影的expiresAt/resendAfter/revision为事实，浏览器倒计时只展示；429尊重Retry-After，409重读后再由操作者决定。

创建/重发已经有幂等请求ID，未知响应只重放原请求。**接受接口没有幂等请求ID**：已消费后再次提交422是设计行为，不表示第一次没成功；不得自动重试后得出“开户失败”，也不通过前端编造幂等字段或自动重复注册。

## 3. 邮件引导与页面收口

现有 `AdminInvitationDelivery` 复用标准SMTP，正文含邀请ID、一次性凭证、24小时/重发失效说明及“在邀请接受页输入”的文字，**没有可点击开户地址**。这不要求更改邮件服务：本轮管理面板显示、可复制既有student-web地址配置构造的固定 `/accept-admin-invitation` 通用地址，管理员将其提供给收件人；所有邀请信息由收件人手动从邮件填写。不得向URL加入邮箱、邀请ID、secret或hash片段，不硬编码另一个前端端口。

- 管理端在既有 `/admin/users` 内增加邀请面板；两项侧栏及默认审核落点不变，不复制权限页、不增加第三个邀请导航。
- URL形式 `/admin/users?panel=invite&invitationId=<UUID>`。当前共享 `sanitizeAccountPermissionsQuery` 仅认detail/coordination且无userId会删panel，故本轮须同步扩展共享过滤和页面过滤：invite不依赖userId，只保留合法invitationId及panel，移除无关userId/commandId；现有账号面板的白名单不放宽。刷新、登录回跳及浏览器返回都恢复同一非秘密目标。
- 没有邀请列表API，不做全表/浏览器持久化列表或按邮箱查找。支持新建后查看本条、输入已知ID查询。页面存活时响应丢失保留原请求且有限重放；页面关闭后没有ID/原载荷就明确不能自动找回，可由收件邮件取得ID。不能声称“无查询结果所以未创建”，不能自动另建一封。
- 学生应用在同一 `AccountFrame` 增加公共 `/accept-admin-invitation`；不在普通注册页把ADMIN当可选角色。该路由当前未实现，属于本轮页面工作，不是后端缺口。
- 表单为邀请ID、邮箱、邮件一次性凭证、昵称、新密码/确认密码。邮箱规范化沿既有规则；凭证必须严格43字符，不解码为业务文本。首期昵称1～30个可见字符，复用已有账号规则（接受契约允许至80，取兼容子集避免与CurrentUser展示约束冲突）；密码至少12字符、UTF-8至多72字节，确认密码仅前端。
- 邀请ID/邮箱/secret只能手动输入并放POST正文，不能从URL/持久存储读取。当前已登录时，明确提示退出或使用独立浏览器上下文，不自动登出或覆盖现有会话；未登录访问不得要求先登录才能开通。公共接受调用不附管理Authorization，也不拿旧账号刷新会话冒充受邀者。
- 成功201后清除secret/password，展示“已开通，请登录”，进入已有统一 `/login`。不自动登录、不用userId假造能力。正常密码登录后按真实ADMIN能力落到既有教师审核；如提供回跳，只用现有允许的管理目标，不开放任意redirect。
- 接受请求网络/5xx/超时保留“结果未确认”，不自动再次消费，给“尝试正常登录”和“联系邀请人查询状态”说明；统一422不拆分成“邮箱不存在/凭证正确”等泄露性文案。409邮箱已绑定不能引导账号转换。错误保留适当非秘密字段，密码/凭证在成功、身份变更或卸载时清除，不输出完整响应到日志。
- 管理写请求有原ID/载荷快照和未决离页提示、有限重放；SMTP可能慢于常规查询，创建/重发应设置明确有界等待（可沿既有真实验收45秒），查询保持短超时，超时只表示未知。PENDING低频有限查询（如默认2秒最多30次），到限手动查询；FAILED/EXPIRED可在服务端允许时由管理员明确重发，不后台循环。
