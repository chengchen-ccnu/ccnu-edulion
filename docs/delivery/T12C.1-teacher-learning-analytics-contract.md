# T12C.1 教师学情与分析后端契约交付

## 目标与边界

本分支 `codex/t12c1-teacher-learning-analytics-contract` 从 `main@1c981d5` 开始。T12C.1 为后续 T12C.2 提供 owner 范围内的 ACTIVE 学生学情、当前发布课时统计、课程任务成绩和按上海自然日的趋势。只通过 Course API 取得课程 owner 与当前 `contentRevisionId`，通过 IAM 内部昵称接口补充显示名；Learning 只查询本 Schema 的 MySQL 持久事实。未实现 Vue、页面、导出、AI 总结、风险等级、薄弱知识点、课程转化、观看达标、提醒或历史内容观看。

`enrollment.status=CANCELED` 是 Learning 当前持久模型中的退课状态，T11C 的 `assessment_participant.enrollment_status=WITHDRAWN` 是任务参与者状态；常规教师学情统一只查询 `enrollment.status=ACTIVE`，这两种退课事实都不出现在结果里。

## 接口与调用流程

OpenAPI 从 `0.25.0` 向前升级到 `0.26.0`，客户端由 `pnpm.cmd --dir web-apps run generate:api` 生成。Gateway 已有 `/api/v1/teacher/learning/**` 路由。所有接口要求 `teaching:access`，Learning 调用 Course 教师编辑 API 验证 owner；其他 owner 安全 404，Course 超时/5xx 为 503，本人未发布课程返回 `NO_PUBLISHED_VERSION` 空态。学生详情仅 ACTIVE 可读。

兼容性迁移：原 `/students` 是尚无教师页面消费者的粗略汇总，包含无门禁的跨任务 `averageScore` 和退课行。0.26.0 在同一路径改为安全 ACTIVE 当前内容响应，移除不安全的原始平均与旧字段；旧调用者须重新生成客户端并改用 `homeworkAverage`/`examAverage`（门禁未就绪时为 null）、`completedLessons` 等字段。该变更的旧投影不可作为兼容读接口继续暴露，否则会绕过 T11C 成绩门禁。生成客户端与页面使用本版唯一契约。

| 接口后缀（前缀 `/api/v1/teacher/learning/courses/{courseId}`） | 返回 |
| --- | --- |
| `/students` | ACTIVE 学生分页、编号/昵称、当前进度、观看秒数、最后活动、正式平均、缺交/待批；进度/缺交/待批/关键词筛选，白名单排序 |
| `/students/{learnerId}/overview` | 单生汇总与课程 PRACTICE 真实提交次数 |
| `/students/{learnerId}/lessons` | 单生当前发布课时分页，VIDEO 秒数、ARTICLE 完成，不虚构阅读时长 |
| `/students/{learnerId}/tasks` | 单生课程任务分页、正式最后有效 attempt 或 PRACTICE 最高有效成绩、竞赛排名 |
| `/students/{learnerId}/trend` | 单生 7/30/ALL 趋势 |
| `/analytics/overview` | ACTIVE 人数、整课完成人数、VIDEO 总秒数/实际观看人数与两种人均 |
| `/analytics/lessons` | 当前课时分页的开始、完成、完成率与 VIDEO 两种人均 |
| `/analytics/tasks` | 课程任务分页的提交、缺交、迟交、待批及安全成绩统计 |
| `/analytics/trend` | 课程或指定当前 `lessonId` 的 7/30/ALL 趋势 |

学生、任务默认 20/最大 100；课时默认 50/最大 200。课时分页顺序来自 Course 当前发布目录，HTTP 投影保留目录原有次序。查询只取当前面板的一页并在数据库聚合，不生成全班学生×全部课时×日期矩阵。昵称按批向 IAM 读取；失败时仍返回课程学生编号与 Learning 事实，学生列表/详情有 `nicknameDependencyFailed` 标志。教师读取不依赖 Redis，已落库事实可在 Redis 不可用时继续使用。

## 统计与安全口径

- Course 当前发布目录中的 `contentRevisionId` 是课时内容身份；课时进度、完成和时长都必须连接当前投影。旧修订保留在 MySQL 内部，不显示在当前快照或趋势。`ASSESSMENT` 课时作答计入任务，不从通用进度伪造课时开始或观看。
- VIDEO 返回全班当前累计秒数、实际观看人数、ACTIVE 学生人数、对所有 ACTIVE 学生平均和对实际观看者平均；ARTICLE 只有开始和完成。零分母为 0，不伪造时长。
- HOMEWORK/EXAM 只用 T11C `assessment_participant.final_attempt_id` 的最后有效 attempt。关闭、草稿结算和所有 ACTIVE 已交者批改完成前，只返回提交/缺交/迟交/待批计数；学生分数字段、课程均值/极值/分布与按正式成绩排序都不可用。门禁打开后使用百分制聚合；缺交在正式平均中计零，课程 PRACTICE 从不进入正式平均。
- 课程 PRACTICE 仅 `ownership_type=COURSE`、真实已提交且有效评分的 attempt；每人最高有效百分制用于平均、分布和排名。`AUTONOMOUS` 与公共练习不进入课程分析。竞赛排名由高于本人分数的人数加一得到 `1、1、3`；`rankingPercent=(rankedStudentCount-rank+1)/rankedStudentCount×100` 是产品定义的“领先比例”，并非统计学百分位。
- 快照为当前 `LIFETIME`，7/30 天按日，ALL 跨度超过 180 天按月。月度去重在 SQL 中重新 `COUNT(DISTINCT learner_id)`，不累加每日去重数。响应携带 `periodStart`、`periodEnd`、`zoneId=Asia/Shanghai`、`granularity`、`generatedAt`、`dataThrough`。趋势区分正式提交次数、去重提交学生数与自动结算提交次数。
- `lastActivityAt` 来自真实报名、当前进度、成功草稿保存、正式提交和错题重做；仅打开页面、Redis 未落库值、AI 会话及笔记编辑不计入。

## V18 迁移和幂等写入

Learning `V18__add_teacher_learning_daily_facts.sql` 新增 `lesson_learning_day`（课程、学生、内容修订、自然日唯一）、`learning_activity_day`（课程、学生、自然日唯一），为 `assessment_attempt` 增加 `auto_settled`、`submission_day` 和趋势索引。没有改写已合并迁移，也没有跨服务外键。MySQL 行锁事务中，强制检查点按本次实际增加的累计秒数写日事实；Redis Lua 按上报的上海日期保存每天有效增量，Worker 用 `bufferVersion` 去重，重复 ACK/重试不重复累计。可读的 Redis 待落库快照会先合并到强制检查点事务。Redis 故障造成较新的 MySQL 检查点先于旧快照时，无法精确拆分重叠日期的差额只保留在 LIFETIME，不伪造某一天的历史。

上线前已有的 `lesson_progress.watched_seconds` 继续是 LIFETIME 事实；V18 不把旧累计时长、旧提交和旧活动反推成每日历史。ALL 趋势因此从 V18 之后第一条真实日事实起算，可能短于课程实际历史。新提交日由 Java 根据 `Asia/Shanghai` 写入，避免 JDBC/数据库会话时区影响趋势归属。

## 环境、演示与清理

沿用现有 Course、IAM、MySQL 与 Redis 配置；没有新增环境变量或改动用户目录 `local.env`。本地命令需经 `scripts/Invoke-WithLocalEnvironment.ps1`；生产秘密继续由部署 Secret 管理。启动 Learning 的现有 local 模式后，以有 `teaching:access` 的 owner 经 Gateway 调用上述接口；用非 owner 验证 404，用已发布零 ACTIVE 与本人草稿验证零值/空态，按学生编号和页码翻页，再验证任务门禁与趋势窗口。T12C.2 只消费生成客户端，不复制排名计算。

真实验收只连接明确的 `edu_platform_learning_dev` 与 Learning Redis DB 4。没有新建数据库、课程、账号、媒体或永久 Seed；只新增 V18 的表/列/索引。随机 UUID 测试课程投影、报名、学生编号、课时进度和日事实用于当前修订、幂等、1,000 人分页场景，测试 `finally` 按本轮 course/learner ID 删除，Redis Hash 与 dirty 成员按精确 Key 清理，最终断言测试报名/日事实/Key 为零。没有修改用户手工《线性代数》课程的结构、发布版本或媒体绑定，也没有使用其视频。

重跑：通过包装器确认 `LEARNING_MYSQL_DATABASE=edu_platform_learning_dev`、`LEARNING_REDIS_DATABASE=4`，设置临时 `T12C1_MYSQL_ACCEPTANCE=true` 后执行 `mvn '-Dmaven.repo.local=.m2/repository' -f java-platform/pom.xml -pl learning-service -am '-Dtest=T12C1MysqlAcceptanceTest' '-Dsurefire.failIfNoSpecifiedTests=false' test`；JUnit `finally` 自动精确清理。测试数据不要求手工清库。
