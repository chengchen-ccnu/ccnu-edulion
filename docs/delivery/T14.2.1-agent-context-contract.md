# T14.2.1 Agent 授权上下文与恢复契约前置审计

日期：2026-09-10。状态：前置审计完成，尚未实现、测试或创建 PR。

## 目标与边界

T14.2.1 是从旧 T14.2 拆出的第一个任务，只补齐真实 Agent 接入前不可缺少的授权和恢复契约：课程检索候选再次授权、Java 持久消息的有限最近窗口、Learning 学习事实读取，以及 Python 向 Java 上报实际用量和候选记忆的协议。任务不得建立长期记忆表、Redis 运行治理、Vue 页面、自主组题或帮助知识库，也不得让 Python 直连 MySQL。

## 前置审计结论

1. T13.1、T13.2、T13.3 和 T14.1 已合并，动态运行时、Qdrant/Neo4j 检索、Agent Access 会话表与基础 SSE 均可作为实现基线。
2. 课程候选再次授权尚未冻结。Python 当前只接受可注入 `course_verifier`；未注入时会安全剔除全部课程候选。T14.1 只有发送消息时的单课时授权，没有候选批量复核端点。
3. Agent Access 已能对浏览器分页返回历史消息，但构造内部 `AgentRunRequest` 时只发送当前用户消息和当次可信上下文；T13.1 内部协议也没有 Java 持久最近消息窗口。Python 的进程内最近轮次在重启后丢失，因此不能宣称跨进程多轮恢复。
4. 内部协议预留了 Learning 事实引用与四个只读工具，但 Agent Access 尚未授予这些工具或提供实际读取适配器；Python 未注入 `student_fact_reader` 时返回空。
5. Python 已统计模型、视觉、工具与 Token 用量并生成候选记忆，但现有公开 SSE 契约故意不携带这些 Java 私有事实，Agent Access 也没有受控、幂等的运行结果上报入口。不得把内部用量或隐藏画像塞进浏览器事件解决。
6. Agent Access 当前没有 Redis 依赖、租约、用户总并发或分钟/日额度；这些属于 T14.2.3。MySQL 的同会话活动槽唯一约束已经存在，应继续作为并发事实保护而不是被 Redis 替代。
7. Java→Python 已使用 WebClient 逐事件代理，公开事件先持久化再发送，也已有断线取消和部分检查点；但真实跨实例租约、背压、供应商取消、Redis 故障和端到端模型链路尚未验收，属于 T14.2.3。

因此 T14.2 的原范围不满足一次性开工条件，已拆分为 T14.2.1、T14.2.2、T14.2.3。当前分支只准备 T14.2.1，不得提前实现后两项。

## T14.2.1 待冻结方案

- 向前演进现有内部协议，保持 v1 已有请求仍可解析；新增字段或端点必须有正反例 Schema 测试，不建立平行的浏览器 DTO。
- 课程候选复核由 Agent Access 根据 `runId` 取得可信 owner，并核对候选 `entityId/courseId/courseVersionId/lessonId/sourceRevision`。浏览器或 Python 提供的 userId 不能作为授权依据；Course 不可用、版本变化、退课或下架时逐项剔除，不能退化为全课程搜索。
- 最近消息窗口由 Agent Access 从 `ai_message` 按 sequence 读取，限制轮数和字符数，保留 COMPLETE/PARTIAL 语义；当前用户消息不得重复注入。长期摘要和记忆仍留给 T14.2.2。
- Learning 事实读取只复用或新增最小的 owner 安全投影，覆盖错题、真实作答、已公布成绩和进度；未公布答案/解析/成绩、旧 attempt、他人事实和浏览器自报资源一律不可进入 Agent。
- 冻结服务间认证的幂等结果上报，字段仅含实际调用数、Token、阶段耗时、终止原因和有限候选记忆；Java 必须依据 run 校验身份、终态、字段范围和重复请求。实际持久化、证据校验和画像更新属于 T14.2.2，T14.2.1 不建立临时丢弃结果的伪实现。
- 不新增 Redis、RabbitMQ 记忆事件、Qdrant 写入、长期清理任务、Vue 或新微服务；不修改现有题库/课程/测评业务事实。

## 验收门禁

- 旧内部请求兼容、新最近窗口顺序与大小上限、PARTIAL 消息标记及重复当前消息防护。
- 课程候选当前授权、退课/下架/旧版本剔除、Course 超时 fail-closed、跨用户与伪造 userId 拒绝。
- 四类 Learning 事实只返回本人且只返回已允许字段；成绩与参考答案仍受既有公布策略保护。
- 用量/候选上报重复幂等、错误 run/字段/调用方拒绝，且浏览器 SSE、日志和错误响应不出现用量明细、候选画像、Token、提示词或签名 URL。
- Java、Python、内部 Schema 与受影响的生成/契约检查全部通过；真实外部依赖未执行时必须如实标记。

## 数据与环境

本次总控审计没有连接或修改 MySQL、Redis、Qdrant、Neo4j、RabbitMQ 或 OSS，没有创建表、伪数据、消息、索引点或对象。T14.2.1 实施时只允许使用专用 local/test 数据并提供精确清理方式；秘密继续通过本地安全包装器注入。
