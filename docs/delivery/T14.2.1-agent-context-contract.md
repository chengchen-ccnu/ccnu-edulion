# T14.2.1 Agent 授权上下文与恢复契约闭环

日期：2026-09-10。状态：实现完成，等待 PR review；不得自行合并。

## 目标与边界

本任务向前演进现有 Java↔Python v1 内部协议，闭合四项真实接线：课程检索候选再次授权、Agent Access 持久消息最近窗口、Learning 四类本人只读事实，以及 Python→Java 幂等私有运行结果报告。既有不含 `recentMessages` 的 v1 请求仍然合法，没有新增浏览器接口或第二套会话 DTO。

实现未建立长期记忆/画像/衰减/Outbox/Qdrant 记忆写入，未引入 Redis 租约、额度或多实例治理，未修改 Vue、帮助知识库、自主组题和公开 OpenAPI。Python 不连接 MySQL、Learning/Course 表或 OSS。

## 架构与调用流程

### 课程候选复核

1. Python 的 `COURSE_TEXT_SEARCH` 只把 Qdrant 候选的 `entityId/courseId/courseVersionId/lessonId/sourceRevision` 和 `runId` 发给 Agent Access，不发送或信任 `userId`。
2. Agent Access 通过 `runId` 从自身 `ai_run.owner_user_id` 取得唯一可信 owner，再用服务身份调用 Course。
3. Course 逐项核对当前课程为 `PUBLISHED`、当前 published version 仍为 `PUBLISHED`、版本/课时/实体/revision 完全一致、ARTICLE 正文可用，并检查 PUBLIC 或当前 ACTIVE 报名投影。
4. 退课、下架、旧版本、revision 或资源不匹配会剔除对应候选；Course/网络/响应异常统一映射为 `AGENT.DEPENDENCY_UNAVAILABLE`，Python 不回退为全课程搜索。

### 最近消息恢复

Agent Access 在创建新 run 的同一事实链路中，从 `ai_message` 读取当前用户消息之前的记录，按 `sequence_no` 倒序取最近值、应用轮数和字符预算后恢复为升序。默认 6 轮/16000 字符，代码硬上限为 12 轮/32000 字符。窗口保留 `COMPLETE/PARTIAL`，排除当前用户消息及其助手占位消息；只投影角色、正文、完整度和 sequence，不读取 `context_json` 或工具结果。跨进程前再次清除 URL、Token、signature、AccessKey、Authorization、OSS 查询字段和原始工具结果标记。Python 收到 Java 窗口时不再叠加可能过期的进程内最近消息。

### Learning 四类工具

Agent Access 为四个只读工具授予 `USER_SELF`，Python 只传 `runId`、工具名、可选资源 ID 和上限。Agent Access 仍以 `ai_run.owner_user_id` 覆盖身份，再调用 Learning：

- `STUDENT_WRONG_QUESTIONS`：只读当前 learner 错题事实，不返回题目快照、官方答案或解析；
- `STUDENT_SUBMISSIONS`：只连接 `assessment_participant.final_attempt_id`，仅返回本人最终有效 attempt 的本人提交摘要，旧 attempt 不可见；
- `STUDENT_PUBLISHED_GRADES`：除本人最终 attempt 外，还要求 `grade_publication_status=PUBLISHED`；
- `STUDENT_PROGRESS`：只按当前 learner 读取课时进度。

浏览器或模型提供的资源 ID 只会缩小 owner 查询结果，不会改变 owner，也不能命中其他用户、旧 attempt 或未公布事实。所有摘要再次删除 URL/秘密模式并限制到 4000 字符。

### 私有结果报告

Python 在每个 run 终止时上报一个固定 `reportId` 的有界结果：模型名、模型/视觉/工具调用数、prompt/completion Token、最多 32 个阶段耗时、终止原因和最多 8 条/每条 500 字符的候选记忆。Agent Access 要求 run 已终态并保存请求 JSON；同 `reportId` 且正文精确相同返回 `replayed=true`，不同 ID 或内容返回 409。Python 针对“终态传播稍晚”的 409 使用同一 `reportId` 有限重试，因此不是接收后丢弃的伪上报。

上述字段不进入公开 SSE、`ai_message`、浏览器响应或 INFO 日志。T14.2.2 将负责把已保存报告校验并规范化到正式用量、审计与记忆事实；本任务没有提前创建这些表。

## 内部 API 与 Schema

`docs/api/agent-internal.yaml` 升至 1.1.0：

- `AgentRunRequest.recentMessages` 为可选字段，缺省空数组，保证现有 v1 请求兼容；

- `POST /internal/v1/agent-access/course-candidates:verify`；
- `POST /internal/v1/agent-access/student-facts:query`。

两端只接受 `X-Internal-Caller: agent-access-service` 与 `AGENT_ACCESS_DOMAIN_TOKEN`，Gateway 不路由这些路径。外部 `docs/api/openapi.yaml` 未变，因此没有新增或重生成浏览器 DTO。

## 安全回环 HTTP 验收

自动化在随机 localhost 端口启动真实 Spring/Tomcat HTTP 入口和 H2：

- Runtime→Agent Access：有效服务身份得到 200，正文无 userId，Fake Domain 实际观察到的 owner 等于 `ai_run.owner_user_id`；
- Agent Access→Course：有效身份和精确候选得到 200，错误 token 得到 401；
- Agent Access→Learning：本人进度通过新内部 HTTP 得到 200，响应不含其他用户、答案或解析字段。

该验收不连接本地 MySQL、RabbitMQ、Qdrant、Neo4j、OSS 或收费模型，也不冒充三服务加真实模型的 T14.2.3 端到端验收。依赖超时 fail-closed、退课/下架/旧版本、跨用户、旧 attempt、未公布成绩和幂等报告由同一批集成测试覆盖。

## 人工演示

1. 运行初始化脚本并以包装器分别启动 Course、Learning、Agent Access、Python。
2. 经现有 Gateway/Agent Access 创建会话并发送消息；不要直接从浏览器调用 internal 路径。
3. 在测试课程仍发布且报名 ACTIVE 时触发课程检索，确认只引用精确命中；退课、下架或发布新版本后重试，旧候选应消失而不是扩大搜索。
4. 创建两次测评 attempt，仅最终 attempt 可由提交工具读取；成绩未公布时成绩工具为空，公布后才出现。
5. 重启 Python 后继续同一会话，确认 Agent Access 持久窗口仍按序携带 COMPLETE/PARTIAL，且当前问题只出现一次。
6. 对同一终态 run 重放相同结果报告，确认 `replayed=true`；改变内容确认 409，公开消息和 SSE 不出现报告字段。
