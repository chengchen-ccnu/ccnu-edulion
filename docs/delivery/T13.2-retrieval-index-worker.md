# T13.2 Qdrant/Neo4j 检索与独立索引 Worker 交付说明

## 目标与边界

本任务把 T13.1/T14.1 已冻结的索引协议落为独立 Python Worker，并建立 Qdrant 混合检索与 Neo4j 派生知识图。Worker 通过 `python -m edu_agent_app index-worker` 独立启动，不启动在线 Agent HTTP，可单独停止和增加单活备用实例。

本任务没有实现 T13.3 动态多 Agent、T14.2 真实长期记忆、T13.4 帮助知识库、Vue 页面或自主组题。旧在线 Agent 仍保留原 FAISS 代码，T13.2 新入口不导入或使用它；移除旧运行时属于 T13.3，不在本任务扩大范围。

## 实现与调用流程

增量链路为：Java 领域事务与 Outbox → RabbitMQ `edu.agent.index.events.v1` → Python Worker 严格校验 v1 信封 → 按稳定 ID 调用 Java 内部安全投影 → 本地 BGE 编码 → Qdrant/Neo4j 派生写入 → SQLite revision/eventId 状态提交 → 手动 ACK。消息中不包含题干、答案、解析、课程正文、签名 URL 或秘密；投影请求固定 `X-Internal-Caller: agent-index-worker`，令牌只由包装脚本注入。

消费语义是 at-least-once，不宣称恰好一次。`eventId` 重复为 no-op；同 `entityType + entityId` 只接受更高 `sourceRevision`；DELETE 写 tombstone，旧 UPSERT 不能复活。外部写入失败时不提交 processed 状态；消息经 publisher confirm 后进入有限 TTL 重试，耗尽后进入 DLQ。主队列使用 RabbitMQ single-active-consumer，使多个独立进程可作为单活/备用扩缩并保持全局投递顺序。

全量重建只调用 T14.1 的稳定分页 API，每页最多 200，默认 100；三个事实源最多三路并发，单页批量编码。SQLite 检查点只在整页成功后推进，中断重启从最近完整页恢复。增量与重建在同一状态库上按 revision 串行裁决，旧分页结果不能覆盖较新事件。对账只报告差异，不自动删除来源不明数据。

## Qdrant 与混合检索

实际服务端为 Qdrant 1.19.1，客户端锁定 `qdrant-client==1.19.0`。四个 collection 均带 `owner=edu_agent_app-index-worker`、`schema_version=1`、dense 模型版本、768 维和 BM25 配置元数据：

| collection | T13.2 事实源与权限 | 主要 payload 索引 |
|---|---|---|
| `math_questions` | Learning 当前 ACTIVE、SYSTEM、JUNIOR、MATH 安全投影；无答案/解析/教师私题 | namespace、entity/entityType、recordType、modelVersion、revision、学段、学科、PUBLIC_SYSTEM |
| `math_knowledge` | Learning 启用的初中数学知识点 | namespace、entity/entityType、recordType、modelVersion、revision、学段、学科 |
| `course_content` | Course 当前已发布且非空 ARTICLE；返回 Agent 前仍须 Java 当前用户复核 | namespace、entity/entityType、recordType、modelVersion、revision、course/version/lesson、bool 重授权标志 |
| `student_memories` | 仅 T13.1 协议替身与全局 userId 隔离测试；真实事实留给 T14.2 | namespace、entity/entityType、recordType、modelVersion、revision、userId |

Dense 使用本地 `bge-base-zh`，文档保持原文，只有查询增加模型要求的检索指令。Sparse 使用 Qdrant 1.19 服务端 `qdrant/bm25`、IDF modifier 与 `multilingual` tokenizer；关闭语言相关 stemmer/stopwords，未使用英文默认 tokenizer、字符串过滤或手写关键词包含判断冒充 BM25。两路各召回 30，RRF `k=60`，本地 `bge-reranker-base` 重排 25 条，再按 collection/意图阈值过滤并最多返回 8 条；无可靠命中时返回空，不补齐低质量结果。

有限代表样本的初始阈值为：题目 0.58、知识 0.54、课程 0.60、记忆替身 0.62；`EXPLAIN_CONCEPT` 下调 0.02，推荐练习/检查过程分别上调 0.03/0.02。它们不是旧 FAISS 的 0.42/0.38。真实样本结果见“验证结果”。模型版本被写入 collection 元数据和 payload；版本不一致会抛出 `RebuildRequired`，禁止混写。升级模型前须停 Worker、备份、确认四集合均由本 Worker 拥有、精确清理旧 namespace，并显式重建，不能直接改版本继续写入。

## Neo4j

Worker 只创建受控标签 `EduAgentIndexKnowledge`、关系 `EDU_AGENT_PREREQUISITE_OF` 和 `(namespace, entityId)` 复合唯一约束。Cypher 固定且参数化，不接受模型生成的 Cypher；查询输入最多 20 个节点、深度 1～3、返回最多 200 个节点并有事务超时。Neo4j 不保存学生画像。图故障时 `related` 返回 degraded 空增强，Qdrant 公共检索可继续。

清理仅匹配 Worker 标签和精确 namespace。T13.2 开始前已有 3,671 节点/2,107 关系均未加 Worker 标签，也未被修改或删除。

## 启动、重建、恢复与清理

所有需要凭据的命令都通过包装脚本执行：

```powershell
# 初始化四集合、payload 索引和 Neo4j 约束
& .\scripts\Invoke-WithLocalEnvironment.ps1 -ScriptBlock {
  & python -m edu_agent_app index-worker --mode init
}

# 独立消费进程
& .\scripts\Invoke-WithLocalEnvironment.ps1 -ScriptBlock {
  & python -m edu_agent_app index-worker
}

# 从检查点继续有界重建；默认不会重新从零开始
& .\scripts\Invoke-WithLocalEnvironment.ps1 -ScriptBlock {
  & python -m edu_agent_app index-worker --mode rebuild
}

# 明确重置三类分页检查点后重新遍历 Java 当前投影；revision/tombstone 仍保留
& .\scripts\Invoke-WithLocalEnvironment.ps1 -ScriptBlock {
  & python -m edu_agent_app index-worker --mode rebuild --restart-rebuild
}

# 只读对账，不自动删除
& .\scripts\Invoke-WithLocalEnvironment.ps1 -ScriptBlock {
  & python -m edu_agent_app index-worker --mode reconcile
}

# 仅精确清理当前 namespace 点、Worker 图节点和该 namespace 专属状态行；不删除 collection 或其他数据
& .\scripts\Invoke-WithLocalEnvironment.ps1 -ScriptBlock {
  & python -m edu_agent_app index-worker --mode cleanup `
    --confirm-namespace ccnu-edulion-t13.2-v1
}
```

恢复状态默认位于 `.m2/agent-index/worker-state.sqlite3`，包括 processed event、实体最高 revision/tombstone 和分页检查点；一个状态库只能对应一个 `AGENT_INDEX_NAMESPACE`。`cleanup` 在四集合与图 namespace 均清理成功后清空这三张状态表，使同 revision 的 Java 当前投影可以重新建立；SQLite 文件本身保留。执行前必须停掉使用该 namespace/状态库的全部 Worker，且不能让其他 namespace 共用同一状态文件。

## 实际验证结果

真实 Java 重建第一次以三路并发运行时，开发机 Learning 连接池被后台任务占满并返回一次 HTTP 500；知识点页已完成并保存检查点，题目页未越过失败页。随后以并发 1 重启，Worker 从检查点跳过已完成的 1,386 个知识点和空课程源，只继续 648 道题并成功完成。实现随后增加 Java 5xx/连接错误最多 3 次的有限退避重试。该过程验证了失败不伪装成功与中断恢复。

最终保留的真实索引：`math_questions=648`、`math_knowledge=1386`、`course_content=0`、`student_memories=0`。题目 20 条有界 payload 抽查不存在 answers/answer/analysis/articleMarkdown/URL/token/password 字段。Neo4j Worker namespace 为 1,386 节点/2,054 关系；全库为 5,057/4,161，恰等于原有 3,671/2,107 加本任务派生数据。

代表检索样本未输出题干或正文：

## 已知风险与后续依赖

- `student_memories` 仅有协议替身和 userId 隔离结构，真实记忆事实、过期/删除和证据访问范围必须由 T14.2 接通。
- 在线 Agent 尚未调用本检索服务；T13.3 只能消费安全候选，并在课程候选进入模型前再次调用 Java 校验当前用户、当前课程版本和课时。权限失败、退课、下架或旧版本必须丢弃受限候选，不能退化为全库课程搜索。
- 本机开发库没有真实可索引 ARTICLE，故本任务不宣称已完成真实用户报名/退课/下架课程命中闭环。
- 默认三路重建在小连接池环境可能触发瞬时 5xx，现有客户端会有限重试；本地资源紧张时将 `AGENT_INDEX_SOURCE_CONCURRENCY=1`，生产值需按 Java 连接池和 Qdrant 压测调整。
- SQLite 状态库适用于当前单活消费/备用实例和同主机重建。不能把多个主机各自的 SQLite 配置成 active-active；若未来要求并行多活吞吐，须先设计共享 CAS/revision 状态，不能只移除 single-active-consumer。
- 当前阈值基于有限代表样本，不是最终离线评测集；T13.3 接入前应增加按意图标注的更大但仍受控样本，保持无可靠命中可返回空。
- 当前本机尚未生成 `rabbitmq.credential.clixml`；真实验收使用的进程级凭据未持久化。再次启动消费器前需交互运行初始化脚本，不能回退到仓库、命令参数或 `local.env` 明文保存密码。
