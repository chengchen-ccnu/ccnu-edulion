## 架构与调用流程

`TeacherCourseAnnouncementsPage` → 教师 AuthStore（内存 Token、已有401一次刷新重放）→ 生成类型及 `announcement-api.ts` → Gateway → Operation owner 公告 API。Course owner 详情与公告列表分别加载，审计按需加载；区域失败保留同身份成功内容，授权失败清除正文及草稿。

写资格需要当前 TEACHER + `teaching:access`、Course owner 详情成功、`publicationStatus=PUBLISHED`。TeacherCourse 契约没有暂停字段，实际 Course owner 详情投影调用 `requireActive`，暂停返回 `COURSE.SUSPENDED`；页面因此关闭写操作，公告历史仍以独立 owner 公告接口授权为准。Operation 最终校验当前能力、owner、发布和暂停，按钮不能替代服务端判断。

共享登录 redirect 白名单加入既定公告路由，防止未登录深链接被丢弃。没有新角色页面或任意返回 URL：`from=edit|curriculum`、`coursePage`恢复来源；`page`、`announcementId`、`panel=create|edit|audit`、`auditPage`恢复当前定位。页码只接受1～999999十进制整数，固定每页20，非法参数降到第一页；正文只留内存。选中公告不在当前页时明确提示定位分页，不遍历全部页，也不借学生单公告接口验证教师权限。

发布/改版按 Java 一致的 UTF-16 字符长度校验：标题非空1～120且无控制字符，正文非空1～20000，控制字符仅允许换行/回车/制表符。Vue 文本插值保留换行，HTML/Markdown/链接都不执行。打开新面板先完成快照加载再允许输入，避免慢加载覆盖刚输入正文；手机新面板加载后移焦点，长正文区域可键盘滚动。

每个逻辑命令保存稳定 `clientRequestId` 及发送时的输入/revision快照；未知结果期间冻结编辑，只能从“重试原命令”手动发送，累计最多三次，刷新后的 revision/状态不改原命令。用户明确结束未决命令后，输入或 revision 变化使用新 ID，适配器不自动重试其他错误。成功只说明公告事实已保存，不承诺消息同步送达。改版/撤回携带发送快照的 `expectedRevision`；409保留草稿并刷新事实，改版须明确采用新 revision；新建的课程状态冲突须明确核对当前可写事实后再次提交。撤回冲突必须重新核对并二次确认，不自动撤新版。曾出现未知结果的命令随后收到409等明确失败，也不能据此证明前次请求未生效，仍须明确核对或放弃。

422同时展示标题、正文及 request 等其他错误；429尊重 `Retry-After`，冷却只恢复手动按钮，无后台重发。`dirty`（草稿变更）、`busy`（请求进行中）和 `unresolved`（写入结果未决）独立保护路由离页及 beforeunload。取消离开保留原 ID及次数；成功、明确核对处理结果或确认放弃才结束未决命令。仅刷新列表不自动判断成功；三次上限之后仍可核对/放弃/确认离开，不永久困住用户。结束未决状态不自动丢弃编辑草稿、不假报成功。确认离开后取消请求，卸载清理监听与冷却计时器；身份、sessionVersion或教学能力变化清除私有正文及发送快照并禁用旧命令重试，仅保留未决标记、ID及次数供用户确认处理。相同身份的普通令牌刷新不清草稿。取消浏览器请求不能撤销服务端已提交事务，未知结果应先刷新列表核对；没有持久化草稿或新增契约。
