# T11C.1.2 Learning Course 事实适配器向前兼容修复

## 任务目标与功能边界

本任务修复 Learning 调用 course-service 公开课程详情时的向前兼容读取问题。Course 当前合法响应包含 title、sequence、previewable 以及其他课程展示字段；Learning 的事实适配器只读取课程 ID、发布版本、访问类型、教师 ID、课时 ID 和课时类型，但此前会因未知字段触发严格 Jackson 反序列化失败并返回 LEARNING.COURSE_DEPENDENCY_UNAVAILABLE。

本任务只修改 learning-service 的 HttpCourseFactsClient 及其 HTTP 测试，不修改 Course 对外响应、OpenAPI、页面职责、T11C.2 分支或 PR #50，不新增接口、迁移、缓存、Redis、数据库对象或第二套 DTO。

## 主要架构与调用流程

HttpCourseFactsClient 继续通过既有 GET /api/v1/courses/{courseId} 和 owner 校验接口读取 Course 事实：

1. Course JSON 由 Learning 内部四层私有响应 DTO 读取。
2. Published、Teacher、Chapter、Lesson 四层 DTO 局部使用 JsonIgnoreProperties(ignoreUnknown = true)，只忽略新增展示字段。
3. fact() 只接受必需字段为非空字符串、访问类型为 PUBLIC/ENROLLMENT_REQUIRED、课时类型为 VIDEO/ARTICLE/ASSESSMENT 的响应；数字、对象、缺失字段、空白值和非法枚举均视为无效响应。
4. 无效 JSON/响应、超时和依赖 5xx 继续返回安全 503；公开课程 404 继续返回 Learning 404；owner 接口 404/403 继续隐藏为 Learning 404。
5. 全局 spring.jackson.deserialization.fail-on-unknown-properties=true 保持不变，未放松其他 HTTP 请求或服务的 Jackson 检查。

## 数据库、环境变量与启动方式

生产和本地持久化数据库均未连接、创建或修改；没有新增环境变量。正常启动和 Course 地址配置仍使用既有 COURSE_SERVICE_BASE_URL 与 LEARNING_COURSE_REQUEST_TIMEOUT。

HTTP 验收测试在 JVM 内启动本机随机端口的 Course 响应端点，并使用临时 H2 Schema learning_course_facts_http 运行 Flyway V1～V14。测试只创建一条合成报名、一条已发布 HOMEWORK、一条课程分配和一条参与者记录，使用固定 00000000-0000-4000-8000-00000000020x 标识；每次测试按精确 ID 清理，进程退出后 H2 自动释放。未创建 MySQL/Redis/RabbitMQ/OSS 数据、生产数据或真实用户隐私。

1. 在当前分支运行 HttpCourseFactsClientTest，确认完整 Course 详情字段和四层额外字段不影响事实读取。
2. 运行 LearningCourseFactsHttpAcceptanceTest，确认随机端口 Learning 任务列表返回 200，且响应中的任务 ID、课程 ID、课时 ID、任务类型正确。
3. 检查 application.yml 的全局未知字段失败配置仍为开启，确认本任务没有全局放松 Jackson。
4. 以实际 Course 进程联调时，保持既有 COURSE_SERVICE_BASE_URL 和服务间认证/网关配置；本任务不改变外部 Course API。

## 已知风险与后续依赖

- 自动化 HTTP 验收使用当前 Course CourseDetail 的真实字段形状和本机端点，未连接共享 Course/MySQL 环境；发布环境仍应在已有多服务验收中确认 Course 进程、网络和认证配置。
- Course 未来新增 Learning 必需字段不会被本适配器自动接受；必须同步增加私有读取 DTO、完整性校验和回归测试。
- T11C.2 PR #50 保持 Open，本任务未修改、合并或关闭它；T11C.2 Vue 页面仍由其原任务负责。
