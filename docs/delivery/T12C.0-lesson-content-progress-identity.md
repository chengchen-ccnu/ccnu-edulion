# T12C.0 课时内容身份与进度继承交付说明

## 目标与边界

本任务让 Course 成为“当前发布课时内容修订 ID”的唯一事实源，并使 Learning 的 MySQL 进度、进度事件、ARTICLE 完成事实、Redis Hash、dirty ZSet、Lua 合并、Worker 与强制检查点都按该身份隔离。`contentRevisionId` 不替代 `lessonId` 或 `mediaId`，也不是内容 Hash。任务已通过 [PR #73](https://github.com/chengchen-ccnu/ccnu-edulion/pull/73) 合并到 `main@1c981d5f32f559d0f246f06035b4fffb57847c36`。

本任务没有新增学习页、路由、导航、播放器布局、教师学情接口或统计页面，也没有实现 T12C.1/T12C.2。旧修订事实继续保留供审计，但学生当前投影、课程完成度与后续教师常规统计只能读取当前发布修订。

## 修订规则与调用流程

Course 在草稿目录中保存服务端签发的 UUID：

- 新课时、课时类型变化、VIDEO 主视频替换/解除/重新绑定都会生成新 `contentRevisionId`；A→B→A 因每次绑定变化都生成新 UUID，不会恢复第一次 A 的进度。
- 标题、排序、说明、海报、普通课件、附件以及 ARTICLE 正文/正文图片变化沿用原 ID；ARTICLE 不累计阅读时长。
- 删除后新建由教师生成客户端显式发送 `lessonIdentityMode=EXPLICIT` 与保留课时 `id` 区分，新课时没有旧 ID，因此生成新修订。缺少该模式的旧教师客户端仍保留按位置更新的兼容语义，升级后客户端才具备删除/重建的精确定义。
- 发布事务在 Course Outbox 写入完整当前课时映射；RabbitMQ 失败不回滚课程发布，由既有确认、有限重试和失败状态继续投递。

Learning 的读取/写入流程如下：

1. `PublishedLessonContentChanged` v1 消费者按 `eventId` 幂等，并按单调 `publicationRevision` 忽略乱序旧事件。
2. 正常请求仍通过 Course 公开发布投影校验访问权，并以一次受控 HTTP 当前事实补齐尚未到达的事件；同代正式事件优先于 HTTP 补齐。
3. 浏览器只回传内容投影中取得的 `contentRevisionId`。旧播放器携带的历史三元组通过 Course 内部精确接口校验；无法校验或 Course 暂时不可用时返回通用 404/503，不写入猜测的修订。
4. Redis Key 为 `edu:learning:progress:{learnerId}:{courseId}:{contentRevisionId}`，Hash 仍记录 `lessonId`；Worker、强制检查点和 MySQL UPSERT 使用相同修订身份。新页面加载当前修订，已经打开的旧页面可继续保存旧事实但不会污染当前投影。

## 契约与事件

- OpenAPI 升级为 `0.25.0`。`CourseDetail` 增加单调 `publicationRevision`；课程目录、受保护课时内容、课时进度与 ARTICLE 完成响应增加服务端 `contentRevisionId`。
- 进度与 ARTICLE 写请求增加可选 `contentRevisionId`。新生成客户端必传；缺失字段的旧学生客户端暂按请求时当前修订处理，不能恢复或猜测历史修订。
- 教师整目录请求增加可选 `lessonIdentityMode=EXPLICIT`，课时输入增加可选 `id`；当前教师页面显式使用该模式。
- 新事件契约：`docs/events/course-lesson-content-events.v1.yaml`，exchange `edu.course.lesson-content.events.v1`，routing key `course.lesson-content.published.v1`，事件类型 `PublishedLessonContentChanged`、版本 1。payload 是某次发布的完整课时映射，不携带正文、媒体 URL 或学习事实。
- Learning 队列 `edu.learning.lesson-content.v1` 串行消费，最多三次总尝试，耗尽进入独立 DLQ `edu.learning.lesson-content.dlq.v1`，不自动回流。
- 内部校验：`POST /internal/v1/courses/{courseId}/lesson-content-identities:verify`。它只接受 Learning 调用方与 DPAPI/部署注入的既有服务密钥，只验证精确三元组，不枚举历史目录。

## 数据库迁移

- Course `V6__add_lesson_content_revision_identity.sql`：为 `lesson` 增加非空 `content_revision_id`；既有行以 `lesson.id` 回填为初始修订。
- Learning `V17__isolate_progress_by_content_revision.sql`：为 `lesson_progress`、`lesson_progress_event`、`article_lesson_completion`、`article_completion_request` 增加修订身份并以前置 `lesson_id` 回填；进度和 ARTICLE 唯一约束改为修订维度。
- V17 新增 `published_course_content_projection`、`published_lesson_content_projection` 与 `consumed_course_content_event`，只保存 Course 的最小当前映射与消费幂等事实。
- 两个迁移均是向前新增，没有修改任何已合并迁移。真实 MySQL 8 已从 Course v5→v6、Learning v16→v17 成功执行。

## local/test Seed

Seed 只操作 `edu_platform_learning_dev`、Redis DB 4，以及固定测试标识：

- course：`00000000-0000-4000-8000-00000000c120`
- learner：`00000000-0000-4000-8000-00000000c121`
- 6 个当前课时投影、8 条课时进度及对应事件、1 条 ARTICLE 完成事实。

它覆盖未改变 VIDEO、A→B、A→B→A、普通元数据变化、ARTICLE 正文变化、类型变化和删除后新建。它不连接 Course Schema，因此不会修改《线性代数》。Initialize 是幂等重建；Cleanup 只按固定 course/learner/revision 清理。

```powershell
# INITIALIZE、CLEANUP、REBUILD 三选一
& scripts/Invoke-WithLocalEnvironment.ps1 -ScriptBlock {
  $env:T12C0_DEMO_SEED_ENABLED = 'true'
  $env:T12C0_DEMO_SEED_ACTION = 'REBUILD'
  $env:RABBITMQ_ENABLED = 'false'
  mvn.cmd '-Dmaven.repo.local=.m2/repository' -f java-platform/pom.xml `
    -pl learning-service -am '-Dtest=T12C0ProgressIdentityDemoSeedTest' `
    '-Dsurefire.failIfNoSpecifiedTests=false' test
}
```

2026-09-22 已先调用既有 T12F.1 Seed 自带的精确 `CLEANUP`，删除其固定 `f401` 图文 0% 进度及关联完成事实；随后实际执行 T12C.0 `REBUILD` 并保留上述最小固定 Seed。若需要完全清除，把 action 改为 `CLEANUP`；重复 `REBUILD` 不会增加记录。来源不明、无法绑定明确 seed/run ID 的数据没有被删除。

## 人工演示

1. 启动 Media、Course、Learning、Gateway 与 student/teacher web，使用 `scripts/Invoke-WithLocalEnvironment.ps1` 注入本地凭据。
2. 学生打开既有 `/learn/:courseId/:lessonId`，播放 VIDEO 并确认心跳为 `BUFFERED`、暂停为 `PERSISTED`，刷新后恢复当前修订进度。
3. 在测试课程（禁止使用手工《线性代数》）中由教师替换主视频并发布；学生刷新或重新进入后当前进度为零。保留旧页面继续播放时可保存旧修订，但新页面当前进度不变化。
4. 再绑定第一次的 mediaId 并发布，确认仍得到第三个修订且不恢复第一次 A；只改标题/海报/附件或 ARTICLE 正文时确认原完成事实保留。
5. 演示结束运行 Seed `CLEANUP` 或 `REBUILD`，只处理上述固定测试标识。

## 风险与 T12C.1 前置

- 发布事件和 HTTP 补齐提供最终一致性；Course 完全不可用时 Learning 返回通用同步失败，不接受浏览器猜测身份。DLQ 需要运维查看与人工重放，没有自动无限重试。
- 历史进度事实有意保留，后续容量治理应按审计/保留策略处理，不能由 T12C.1 物理删除。
- 旧教师客户端没有稳定课时 ID，只能保留升级前按位置修改语义；精确“删除后新建”依赖本次生成客户端的 EXPLICIT 模式。旧学生客户端只会写请求时的当前修订。
- T12C.1 所需的当前发布内容映射、修订隔离 MySQL 持久事实、事件幂等与 owner 校验已经具备；待本 PR 合并后即可开始。T12C.1 仍须只读 MySQL 持久事实，不读取 Redis 未落库值，也不得重新实现内容身份。
