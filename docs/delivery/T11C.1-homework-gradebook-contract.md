# T11C.1 作业规则、成绩册与 CSV 导出后端契约

## 任务目标与边界

本任务在既有 `learning-service` 测评模型上补齐 HOMEWORK 的开放/截止/迟交/多次提交、应交名单、课程学生编号、自动关闭与草稿结算，并提供教师成绩册矩阵和同步 CSV。PRACTICE 保持原行为，EXAM 保持既有时限模型；不新增作业、答卷或批改服务。

本任务只交付后端契约和服务端实现，不实现 T11C.2 Vue 页面、路由、历史 attempt 查询、附件作业、免交、个别延期、自动扣分、学生排名、OSS 报表、异步 XLSX 或 RabbitMQ 导出。

## 契约与调用流程

OpenAPI 从 0.20.0 向前演进到 0.21.0，唯一事实源为 [`docs/api/openapi.yaml`](../api/openapi.yaml)，TypeScript 客户端由同一文件重新生成。

新增/扩展的外部接口：

| 领域 | 接口 | 作用 |
|---|---|---|
| 学生任务 | `GET /api/v1/learning/courses/{courseId}/tasks` | 返回已报名学习者可见的 HOMEWORK/EXAM 安全摘要、时间状态、提交/批改状态和最后有效 attempt 投影 |
| 学生任务 | `GET /api/v1/learning/courses/{courseId}/tasks/{assessmentId}` | 返回单任务；NOT_OPEN 时不返回题目快照，课时级任务按 `currentLessonId` 防枚举 |
| 学生作答 | `POST .../tasks/{assessmentId}/attempts` | 创建/恢复当前草稿或开始下一次 HOMEWORK attempt；草稿不消耗次数 |
| 学生结果 | `GET .../tasks/{assessmentId}/result` | 只按服务端 `final_attempt_id` 返回最后有效结果，不接受历史 attempt 选择 |
| 教师截止 | `PUT /api/v1/teacher/assessments/{assessmentId}/deadline` | owner 使用 `expectedRevision` 调整截止节点并写审计 |
| 教师成绩册 | `GET /api/v1/teacher/gradebook` | 按课程、测评、类型、提交/批改状态、迟交、昵称/编号关键词分页和稳定排序 |
| CSV | `GET /api/v1/teacher/gradebook/export` | 同步返回 UTF-8 BOM 宽表；上限和完整批改门禁在服务端复核 |
| IAM 内部 | `POST /internal/v1/users/nicknames` | 仅由 Learning 使用服务令牌批量读取 ID→昵称，不经 Gateway、不跨 Schema Join |

调用链为：Gateway 校验 `learning:access`/`teaching:access` 并注入可信身份头 → Learning 校验课程发布/owner 事实 → Learning 在本域事务内读取或更新报名、测评、参与者、attempt 和审计 → 成绩册按最终 attempt 指针聚合 → 仅在展示成绩册时调用 IAM 批量昵称接口。IAM 失败只影响昵称，课程编号和成绩事实仍返回并标记 `nicknameDependencyFailed`。

## 主要实现

- HOMEWORK 的 `opensAt` 可空、`closesAt` 必填；`DISALLOW` 在 `closesAt` 结束，`ALLOW_UNTIL` 在 `lateUntil` 结束，迟交只记录事实不扣分。
- `maxAttempts` 为 1～5。每次正式提交写入独立 `attempt_sequence`；参与者只保存一个 `final_attempt_id`，旧 attempt 不进入普通结果、教师结果、成绩册或 CSV。
- 开放/发布和成绩册读取会补齐 ACTIVE 报名参与者；退课保留历史并标记 WITHDRAWN，重新报名恢复 ACTIVE；课程学生编号不可回收、四位展示、并发分配使用数据库计数器和唯一约束。
- 关闭由教师立即结束或后台有界扫描触发。最终截止时，空白草稿记 MISSING，非空草稿沿用服务器最后保存内容结算；结算采用 PENDING/PROCESSING/COMPLETED/FAILED 和最多五次退避补偿。
- HOMEWORK/EXAM 关闭、结算和最终 attempt 全部达到 `GRADED` 前，教师结果列表、成绩册数值统计和 CSV 均不可见；关闭前只保留提交事实和计数。
- 成绩册单场提供已批平均、缺交按零的全体平均、应交人数、准时/最终提交率、缺交/待批、极值和区间分布；课程 HOMEWORK/EXAM 分类汇总只纳入已完成场次。
- CSV 不写临时文件，不写 OSS/MQ；固定编号/昵称列、每场成绩/提交状态/迟交三列及分类平均，退课/非参与者单元格留空，文本统一处理公式注入。

## Learning V14 数据库迁移

文件：`java-platform/learning-service/src/main/resources/db/migration/V14__add_homework_gradebook_contract.sql`。没有修改 V1～V13。

新增或扩展：

- `assessment.late_policy`、`late_until`、`max_attempts`，并向前替换 V10 的 EXAM-only timing check；新 API 仍强制新建 HOMEWORK 必须有 `closesAt`。既有无时间节点的 T11B HOMEWORK 可兼容读取。
- `assessment_attempt.attempt_sequence`、`late_submission`，唯一约束 `assessment_id + learner_id + attempt_sequence`。
- `assessment_participant`：报名状态、提交状态、批改状态、已用次数、最终 attempt 指针、最后提交时间和迟交事实；唯一约束 `assessment_id + learner_id`。
- `course_student_number` 与 `course_student_number_counter`：课程内不可回收编号及原子领取计数器。
- `assessment_deadline_audit`：旧/新时间、操作者、expected revision、原因、trace 和发生时间。
- `assessment_settlement_audit`：结算 operation key、处理数量、状态和安全错误摘要。
- `gradebook_export_audit`：操作者、课程、筛选 JSON、行数、测评数、trace 和时间；限制 5,000 行/100 场。

所有跨域关系仍然只保存稳定 ID；V14 不建立跨 Schema 外键或 Join。

## 配置与启动

Learning 新增：

- `IAM_SERVICE_BASE_URL`，默认 `http://127.0.0.1:8081`。
- `LEARNING_IAM_REQUEST_TIMEOUT`，默认 `1s`。
- `IAM_INTERNAL_SERVICE_TOKEN`，无仓库默认值；本机由 `Initialize-LocalEnvironment.ps1` 生成并写入用户目录 DPAPI 文件，再由 `Invoke-WithLocalEnvironment.ps1` 临时注入。IAM 和 Learning 必须配置同一令牌；令牌不得进入 `local.env`、命令行或日志。

标准启动仍按仓库约定从根目录执行：

```powershell
& .\scripts\Invoke-WithLocalEnvironment.ps1 -ScriptBlock {
    $env:SPRING_PROFILES_ACTIVE = 'local'
    mvn '-Dmaven.repo.local=.m2/repository' -f java-platform/pom.xml -pl iam-service,learning-service -am spring-boot:run
}
```

开发/测试数据库必须明确为 `edu_platform_learning_dev` 或 `edu_platform_learning_test`。本任务的真实验收只连接既有 `edu_platform_learning_dev`，没有创建 Schema，也没有触碰其他服务数据库。

## 伪数据与清理

已提供并实际初始化固定演示 Seed：`T11C1HomeworkGradebookDemoSeedTest` 只在显式 `T11C1_DEMO_SEED_ENABLED=true`、local profile 和 `edu_platform_learning_dev` 下运行；脚本为 `scripts/Invoke-T11C1HomeworkGradebookDemoSeed.ps1`，支持 `Initialize`、`Cleanup`、`Rebuild`。Seed 只创建 Learning 域固定合成报名、课程学生编号、两场测评、参与者、attempt/答案、题目快照引用和审计关联，不创建 IAM、Course、题库或媒体域数据，也不复制题目/媒体事实。

当前开发库保留两场演示：一场已关闭/结算完成的三次 HOMEWORK（准时客观最终提交、迟交最终提交、缺交、退课），一场已关闭但含主观题待批的单次 EXAM；固定学习者只使用合成 UUID/`student_test_*` 展示标识。已执行一次 `Initialize` 和一次幂等 `Initialize` 重跑，均通过。若需清理或重建，只能执行：

```powershell
& .\scripts\Invoke-T11C1HomeworkGradebookDemoSeed.ps1 -Action Cleanup
& .\scripts\Invoke-T11C1HomeworkGradebookDemoSeed.ps1 -Action Rebuild
```

临时真实验收仍使用随机 ID，按参与者/答案/attempt/分配/审计/测评的外键逆序精确清理；本轮 MySQL 随机 Fixture 已在 `finally` 中清理，未生成 CSV 文件、OSS 对象、RabbitMQ 消息或本机导出临时文件。

## 人工演示步骤

1. 通过本地环境包装脚本启动 IAM、Learning、Course 和 Gateway，确认 IAM/Learning 使用同一 DPAPI 注入的内部服务令牌。
2. 以 `teaching:access` 的测试教师创建 HOMEWORK，设置 `closesAt`、`DISALLOW` 或合法 `ALLOW_UNTIL`、`maxAttempts=1/3`，发布并确认参与者/课程学生编号生成。
3. 以 `learning:access` 的测试学习者打开课程任务；验证未开放课时的安全摘要、开始/恢复草稿、草稿不计次和第二次正式提交。
4. 教师关闭任务，确认关闭/结算完成前结果和成绩册数值为空；补齐最终 attempt 的客观/主观批改后确认成绩册一次性出现统计。
5. 下载 CSV，检查 BOM、动态列、缺交零、退课空单元格、课程编号和昵称降级；不得在终端或日志输出文件内容。
