# T12G.1 进度缓冲、强制检查点与可靠落库后端契约

## 任务目标与边界

本任务把播放进度上报从“所有请求同步写 MySQL”向前演进为显式事件契约：旧客户端缺少 `eventType` 时保持原同步行为；显式 `HEARTBEAT` 进入 learning-service 内部 Redis 缓冲；`PAUSE`、`LESSON_SWITCH`、`LEAVE`、`ENDED` 直接形成 MySQL 检查点事实。只有 `ENDED` 可以设置 `completed=true`。本任务不修改 Vue 播放器、不保存逐心跳 MySQL 历史、不引入 RabbitMQ/Redis Stream/DLQ，不把 Redis 当作完成事实源。

## 主要实现与调用流程

1. `POST /api/v1/learning/courses/{courseId}/lessons/{lessonId}/progress-events` 仍先验证 course-service 返回的学习访问事实和课时归属。
2. 旧请求或四类强制检查点使用现有 `lesson_progress_event` 幂等主键、MySQL 行锁和单调聚合；新检查点同时记录 `event_type`。
3. `HEARTBEAT` 使用 Redis Hash、dirty ZSet 和 Lua 原子脚本合并最新快照。Hash 保存完整累计值，ZSet 只保存待落库成员；重复/乱序心跳不增加时长。
4. 内部 Worker 约每 5 秒按 dirty 成员领取 Hash 租约，使用 `buffer_version` 在 MySQL 事务内幂等 UPSERT；提交成功后只有版本未变化才 ACK 并删除 Hash。MySQL 失败保留 dirty 并延后重试。
5. 学生读取合并 MySQL 聚合和 Redis 最新快照；Redis 读失败时只回源 MySQL，并为该投影标记 `PERSISTED_ONLY`。教师学情查询继续只读 MySQL。

## 实现的 API 与配置

- OpenAPI 从 `0.19.1` 演进到 `0.20.0`。
- `ReportLessonProgressRequest.eventType` 为可选枚举：`HEARTBEAT`、`PAUSE`、`LESSON_SWITCH`、`LEAVE`、`ENDED`。
- `LessonProgress.persistenceStatus` 返回 `BUFFERED`、`PERSISTED` 或 `PERSISTED_ONLY`。
- 真实配置位于 `application.yml`、`application-local.yml` 和 `.env.example`：
  `LEARNING_PROGRESS_BUFFER_ENABLED`、`LEARNING_PROGRESS_BUFFER_WORKER_DELAY`、
  `LEARNING_PROGRESS_BUFFER_BATCH_SIZE`、`LEARNING_PROGRESS_BUFFER_WORKER_CONCURRENCY`、
  `LEARNING_PROGRESS_BUFFER_LEASE_DURATION`、`LEARNING_PROGRESS_BUFFER_BACKLOG_THRESHOLD`、
  `LEARNING_COURSE_FACT_CACHE_TTL`。默认批次为 1000、Worker 并发为 16、课程事实短缓存为 1 秒，
  仅用于控制高频进度请求的依赖放大；课程事实仍由 course-service 提供。

## 人工演示步骤

1. 用安全环境包装脚本启动 local profile，并确认 `LEARNING_MYSQL_DATABASE=edu_platform_learning_dev`、`LEARNING_REDIS_DATABASE=4`。
2. 通过正常 Course API 解析已发布课程和课时 ID，并确认当前学生访问事实；不要按标题猜 ID。
3. 使用旧请求验证 MySQL `PERSISTED` 兼容路径；分别发送显式 `PAUSE`、`LEAVE`、`ENDED`，核对 `lesson_progress_event.event_type` 和完成门禁。
4. 连接 Redis 后发送显式 `HEARTBEAT`，核对 Hash、dirty ZSet 和 `BUFFERED`；等待 Worker 落库后核对 `buffer_version`、dirty 清理和读取合并。
5. 暂停 Redis，确认 HEARTBEAT 返回 503 且不返回成功；恢复 Redis 后确认 dirty/新心跳可继续处理。暂停 MySQL 时确认强制检查点返回 503 且 Redis 心跳仍保留待恢复事实。
6. 结束后按本轮 run ID 删除临时 Redis Key/租约和随机进度，复核验收前进度及专用库中的固定 Seed 未被改写。

## 已知风险与后续依赖

- Worker 仍是 learning-service 内部定时任务；真实验收已验证多实例租约竞争、MySQL 失败退避和版本变化 ACK 保护，但生产 Redis 重启/持久化策略仍需按部署环境持续演练。
- 本地 H2 覆盖了迁移、事务、幂等和事件门禁，但没有替代 Redis 原子脚本与 MySQL 8 的锁/时间精度验证。
- T12G.2 必须在本契约合并后，才可在既有学习页显式发送五类事件并展示三态反馈；本任务没有改变页面规格或播放器行为。
