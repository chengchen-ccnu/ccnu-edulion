# T14.2.2 长期记忆事实、画像与索引同步交付

日期：2026-09-10。状态：实现、自动化与真实长链验收均已完成，已通过 PR #61 合并。

## 目标与边界

本任务把 T14.2.1 暂存在 `ai_run` 的私有终态报告归一化为 Agent Access 自有事实，并把安全的学生记忆投影接入现有 RabbitMQ → Python Index Worker → Qdrant `student_memories` 链路。MySQL 始终是事实源；Python 不直连 MySQL，Qdrant 不参与授权或事实判定。

本次没有实现 Redis 租约/额度、多实例 SSE、Vue 页面、帮助知识库、自主组题 Skill，也没有新增微服务、collection、向量库或第二套消息链路。外部 `openapi.yaml` 和前端生成代码均未改变。

## 实现与调用流程

1. Python 每个终态 run 继续通过 T14.2.1 私有回调提交有界用量和最多 8 条候选；候选只从本轮真实用户消息产生，历史召回内容不能自我续期。明确偏好直接标记，推断偏好须在同一会话出现至少 3 次信号。
2. Agent Access 首次保存报告后，在同一外层事务中用 savepoint 归一化。成功时一次写入用量、摘要、记忆、证据、偏好/主题和 Outbox；失败则回滚全部派生事实，保留原报告并只记录脱敏 `FAILED` 状态供定时重试。
3. 聊天候选只形成 `WEAK` 证据。“我懂了”、单次“我不会”、未知类型、超长文本、秘密标记、工具原始结果和地址不会形成掌握画像；被拒候选只留下安全原因。
4. 正式作答和教师批改只能通过 Java 的结构化 `recordLearningEvidence` 入口写 `STRONG` 证据。入口接受可信 IAM userId、来源类型、稳定来源 ID/revision、宏观主题和等级；重复或旧 revision 为 no-op，新 revision 撤销旧判断的当前效力但保留历史证据。当前冻结契约没有 Learning 主动推送端点，因此本任务没有从聊天摘要反推成绩或自创跨域事件。
5. 明确偏好持续到同类偏好被修改；推断偏好、未解决卡点和自述重复卡点分别设置有界到期策略。到期把记忆转为 `EXPIRED` 并同事务写 DELETE tombstone。主题超过 90 天未被强证据验证只把当前可信度降为 `LOW`，不删除等级或历史掌握位。
6. 每次 ACTIVE 记忆新增、修正或删除都分配全局单调 revision，并写 `StudentMemoryIndexProjectionChanged` v1。Outbox 发布器使用持久消息、mandatory、publisher confirm/return、有限指数退避；达到上限保留 `FAILED`，供既有运维重投机制处理。
7. Index Worker 使用生产 `MemoryProjectionProvider` 从 Agent Access 分页或按实体读取，只接受字段白名单内的 `USER_PRIVATE` 投影，然后复用既有 eventId 幂等、实体 revision/乱序保护、retry/DLQ、重投、重建、SQLite 检查点和 `student_memories` collection。
8. 在线运行只从 Agent Access 注入 owner 本人的当前有效偏好和短记忆。课程来源记忆必须与本次刚由 Course 验证通过的 course/version/lesson 完全一致；上下文缺失、字段不一致或依赖失败均 fail-closed。索引 payload 仍标记 `requires_java_reauthorization`，不能作为访问凭据。

## 数据库与迁移

只新增 Flyway `V3__create_memory_profile_and_outbox.sql`，V1/V2 未修改。V3 向 `ai_run` 增加归一化状态、次数、脱敏错误类型和完成时间，并新建：

| 表 | 职责与关键约束 |
|---|---|
| `ai_memory_revision_sequence` | 单行全局 revision，保证增量事件与全量分页不会漏掉晚创建实体 |
| `ai_conversation_summary` | 消息 sequence 覆盖范围、安全摘要和会话内 revision |
| `ai_memory` | owner、类型、安全短文本、状态、访问范围、衰减/到期和投影 revision；owner+类型+文本唯一 |
| `ai_memory_evidence` | 稳定来源 ID/revision、强弱、支持/修正与是否当前有效；不复制答卷或成绩 |
| `ai_profile_topic` | 少量宏观主题当前等级、可信度、最近验证与历史掌握位 |
| `ai_preference` | owner 下同类明确/推断偏好的当前值、revision 与到期时间 |
| `ai_usage_record` | 每个 run/report 唯一的模型、调用次数、Token、阶段耗时与终止原因 |
| `ai_safety_event` | 候选拒绝等脱敏原因，不保存原候选、提示词或秘密 |
| `ai_agent_index_outbox` | 最小事件信封、发布状态/次数/下次时间；实体同 revision 唯一 |

所有业务事实使用 IAM 全局 `userId`。没有跨 Schema 外键、跨服务 Join 或共享 Mapper。

## 内部契约与隐私

- `docs/api/agent-index-source-internal.yaml` 向前升至 1.2.0，新增 `GET /internal/v1/agent-index/student-memories`。支持 `(afterRevision, afterEntityId)` 稳定分页与 `entityId` 单实体读取，页大小 1～200；固定调用方为 `agent-index-worker`，令牌使用常量时间比较，Gateway 不路由。
- `docs/events/agent-index-events.v1.yaml` 保持事件版本 1，只把记忆事件可用性从预留状态推进到 T14.2.2；事件只含稳定 ID、全局用户 ID、revision、操作、来源状态和最小授权元数据。
- 投影只包含安全短文本、记忆类型、USER_PRIVATE 范围、全局用户 ID、到期时间和必要课程范围。事件、索引、日志和错误响应均不保存完整聊天、答案、解析、成绩、隐藏画像、Token、提示词、OSS 地址或工具原始结果。

## 环境配置与启动

通过 `scripts/Invoke-WithLocalEnvironment.ps1` 注入 MySQL、RabbitMQ 和服务令牌后启动 Agent Access；不得读取或复制 DPAPI 凭据内容：

```powershell
& .\scripts\Invoke-WithLocalEnvironment.ps1 -ScriptBlock {
  mvn.cmd '-Dmaven.repo.local=.m2/repository' -f java-platform/pom.xml `
    -pl agent-access-service -am spring-boot:run
}
```

- `AGENT_INDEX_API_ENABLED=true`：开放仅服务间可见的记忆投影。
- `AGENT_INDEX_PUBLISH_ENABLED=true`：启用 Agent Access RabbitMQ exchange 声明与 Outbox 发布；默认关闭，避免无凭据环境误连。
- `AGENT_INDEX_SERVICE_TOKEN`：Agent Access 与 Worker 共用的专用内部令牌，只能由 DPAPI 或部署 Secret 注入。
- `AGENT_INDEX_AGENT_ACCESS_SOURCE_URL`：Worker 的 Agent Access 事实源地址，默认 `http://127.0.0.1:8086`。
- RabbitMQ confirm 超时与最大发布次数分别使用 `platform.agent-index.confirm-timeout`、`max-publish-attempts`；默认 5 秒、5 次。

完整本地约定见 `docs/development/local-environment.md` 和 `.env.example`。若人工曾把密码或令牌写入 `local.env`，流程结束后必须删除并迁入 DPAPI/部署 Secret；本轮没有向 `local.env` 写入秘密。

## 人工演示

1. 用包装器启动 MySQL、RabbitMQ、Agent Access 和 `python -m edu_agent_app index-worker`，开启两个 Agent Index 开关。
2. 以终态 run 上报一条“明确偏好：请先给提示”和一条未解决卡点，再原样重放报告；检查用量、证据和同 revision Outbox 均只有一份。
3. 调用记忆内部分页 API，确认只返回 USER_PRIVATE 安全短文本；换错误调用方/令牌应得到 401。
4. 等待 Outbox PUBLISHED，检查 Worker 主队列 ACK、SQLite eventId/revision 和 Qdrant `student_memories` 中的同一 `user_id` 点；以其他 userId 查询应为 0。
5. 写入更新 revision 和到期/DELETE，确认旧事件不能覆盖新状态、tombstone 后点被删除；清空临时 Worker checkpoint 后执行 rebuild，结果应从 Agent Access 恢复一致。

第 4～5 步已使用当前用户 DPAPI RabbitMQ 应用凭据完成。验收使用 `D:\Anaconda\envs\langgraph\python.exe` 启动真实 Index Worker；Agent Access 使用真实 MySQL、RabbitMQ 发布器和内部 HTTP，Python 使用真实 RabbitMQ、Qdrant 与 Neo4j 连接。

## 数据、清理与重建

- 本轮创建了用途明确的开发 Schema `edu_platform_agent_dev`，Flyway 已建立 V1/V2/V3 表；没有创建账号、课程、题目或长期业务伪数据。
- 真实 MySQL 专项及长链验收只写随机 owner/source 的会话、run、用量、摘要、记忆、证据、偏好和 Outbox；结束后按 owner、conversation、memoryId、eventId 精确删除，逐表复核均为 0。全局 revision 允许保留单调递增空洞，不影响幂等或分页。
- Qdrant 专项使用唯一临时 namespace；长链写入固定 `student_memories` collection 后按 3 个验收 memoryId 精确删除，复核该 owner 为 0。Worker SQLite 精确删除 4 个 eventId 和 3 个实体状态；RabbitMQ 主队列、DLQ 与 4 个 retry 队列共 6 个队列均为 0。未写 Redis、OSS 或 Neo4j 图数据；Neo4j 仅建立连接。
- 需要完全移除本任务本地 Schema 时，仅在确认它仍是专用开发库后执行 `DROP DATABASE edu_platform_agent_dev`；重新生成方式是创建空专用 Schema 后用 local profile 启动 Agent Access，由 Flyway 顺序应用 V1～V3。日常验收不应清空整个 Schema。
