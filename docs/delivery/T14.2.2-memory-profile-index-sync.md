# T14.2.2 长期记忆事实、画像与索引同步前置审计

日期：2026-09-10。状态：前置审计完成，尚未实现、测试、推送或创建 PR。

## 目标与边界

本任务把 T14.2.1 已暂存的私有运行报告规范化为 Agent Access 自己拥有的可靠事实，并接通学生长期记忆的 Outbox、RabbitMQ、Index Worker 与 Qdrant 派生投影。它负责会话摘要、记忆及证据、少量主题等级、明确/推断偏好、逐 run 用量、安全审计、按类型衰减和保留；不负责 Redis 活跃租约、用户分钟/日额度执行、多实例流治理或 Vue 页面。

Python 只提出候选并读取 Java 授权投影，永远不直连 MySQL。MySQL 是事实源，Qdrant 只是可删除、可重建的检索索引；不得把向量相似度当作掌握结论或访问授权。

## 已具备的基础

- T14.2.1 已合并，内部协议 1.1.0 能保存终态私有报告，其中包含有界模型/视觉/工具调用数、Token、阶段耗时、终止原因和最多 8 条候选记忆。
- Agent Access Flyway 当前只有不可改写的 V1、V2；V2 在 `ai_run` 暂存 `result_report_id/result_report_json/result_reported_at` 并保证跨 run 唯一报告 ID。
- `StudentMemoryIndexProjectionChanged` v1 已冻结最小事件信封和 USER_PRIVATE 边界，Index Worker 已支持对应 routing key、eventId 幂等、revision/tombstone、有限重试与 DLQ。
- Qdrant 1.19.1 的 `student_memories` collection 已存在，Schema 1 使用 768 维 BGE、multilingual BM25 和强制 `user_id` 过滤；当前没有真实记忆点。
- 当前缺口是 Agent Access 事实表/Outbox、记忆安全分页源和生产 `MemoryProjectionProvider`。这些属于本任务正常实现范围，不需要另立平行微服务。

## 数据边界

具体列名在实施时按现有 Repository 风格冻结，但职责不得混淆：

| 事实 | 最小职责 |
|---|---|
| `ai_conversation_summary` | 覆盖的起止 message sequence、摘要正文、revision 和生成来源；摘要不替代原始消息 |
| `ai_memory` | owner、类型、简短安全文本、ACTIVE/EXPIRED/DELETED、source revision、访问范围、衰减和保留时间 |
| `ai_memory_evidence` | 来源类型、稳定来源 ID/revision、强弱等级、支持/纠正关系；不复制完整答卷、成绩或课程正文 |
| `ai_profile_topic` | 少量有证据的主题或宏观能力等级、当前判断及历史掌握证据；不为每个知识点预建行、不保存未经校准百分比 |
| `ai_preference` | EXPLICIT/INFERRED 来源、偏好种类和值、revision；明确偏好持续到修改，推断偏好可衰减 |
| `ai_usage_record` | 每个 run 唯一的模型/视觉/工具和 Token 实际用量、模型名及终止原因；供 T14.2.3 额度治理读取 |
| `ai_safety_event` | 脱敏的候选拒绝、权限失败和安全处理事实；不保存提示词、原始工具结果或秘密 |
| Agent Access Outbox | 与记忆 UPSERT/EXPIRE/DELETE 在同一事务提交的最小索引事件 |

V3 必须向前新增迁移，不修改 V1/V2。私有报告的规范化必须事务化且按 run 唯一：重复任务不重复记账、不重复增强画像或发出第二份同 revision 事件；解析或校验失败保留原报告并记录可重试状态，不能伪装完成。

## 证据、衰减与权限规则

- 正式作答和教师批改是强证据，练习/错题重做次之，聊天中学生主动提供的过程是弱证据；普通寒暄不产生记忆或画像更新。
- “我懂了”不能直接形成掌握，一次“我不会”只能影响当前讲法；新作答或批改纠正可按 revision 修正当前判断，旧证据不得被重复累计。
- 画像只使用少量宏观能力和主题等级，不生成精确分数，也不让学生读取隐藏画像。学生可见的讲解偏好仍须遵守后续外部接口范围。
- 普通经历和已解决卡点按类型降低召回优先级并最终退出 ACTIVE；仅再次真实讨论或证据验证可延长，不因系统检索自动续命。历史掌握证据保留，但长期未验证只降低当前可信度。
- 来源受限记忆只保存必要稳定范围，课程退课、下架或版本变化后不得召回受限内容。Qdrant 查询必须注入全局 userId，候选进入模型前还要经 Java 当前授权；权限依赖失败时 fail-closed。

## 索引与消息链路

`agent-index-source-internal.yaml` 应向前增加 Agent Access 记忆分页和单实体安全投影，使用既有 Index Worker 调用身份与令牌，不暴露给 Gateway。投影只包含检索需要的安全文本、全局 userId、类型、revision、学段/科目和必要访问范围，不包含证据明细、隐藏主题画像或原始会话。

Agent Access 在记忆事实事务中写既有 `edu.agent.index.events.v1` Outbox；RabbitMQ 继续使用 confirm/return、有限重试、DLQ 和 eventId 幂等。Worker 只需实现生产 Memory Provider 并复用现有 collection、状态库、tombstone 与重建流程，不新增 Redis Stream、Kafka 或第二套状态库。

## 验收门禁

- V1/V2 checksum 不变，V3 在 H2 与专用真实 MySQL 正常向前迁移、重复启动无重复数据。
- 相同 run 报告重复归一化不重复用量、证据、画像或事件；非法候选、非终态、报告不匹配和解析失败安全保留。
- 强弱证据、纠正 revision、明确/推断偏好、主题等级、衰减、到期 tombstone 和摘要安全均有正反例。
- 真实 Outbox→RabbitMQ→Worker→Qdrant 覆盖 UPSERT、更新、EXPIRE/DELETE、重复、乱序、有限重试、DLQ、重投和分页重建；只清理本任务 namespace/消息/Fixture。
- 两个用户的记忆严格隔离，退课/下架/旧版本不能通过索引或摘要继续泄露；公开 SSE、消息、日志和错误不出现私有报告、隐藏画像、答案、Token 或签名 URL。
- Java、Python、事件/内部 Schema、wheel 和受影响的完整测试通过；真实环境没有执行的项目必须明确标记。
