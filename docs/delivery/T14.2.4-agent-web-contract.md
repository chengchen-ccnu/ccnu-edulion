# T14.2.4 Agent 浏览器消费契约补口

日期：2026-09-11。状态：实现、本机真实验收及 `a01131c` 的 push/pull_request 两轮 CI 均已通过；Ready PR 等待评审。

## 目标与边界

本任务补齐 T15A 只能通过生成客户端消费的四项后端契约：九类可判别 SSE、本人明确讲解偏好、最后一问显式重新生成，以及普通学习账号的 AI 题图上传。实现复用既有 Agent 会话/run/MySQL 事件、Redis 治理、Media 直传与 Python 动态运行时，没有实现 Vue、悬浮答疑、画像查看、自主组题或第二套流。

浏览器仍只能把稳定 ID 和公开输入交给 Gateway。Agent Access 负责重新授权题目、课程与媒体上下文，Media 负责 OSS 对象，Python 不访问 Java MySQL 或 OSS SDK。

## 架构与调用流程

1. 普通发送与重新生成都返回同一种 UTF-8 SSE。Agent Access 在事件写入 MySQL 及发送浏览器前，以字段白名单校验信封和九种 payload；缺字段、错类型、额外字段、非法路由、秘密字段或错误终态组合统一安全失败，原始非法内容不落库、不回显。
2. 偏好 GET 只返回当前用户显式设置；未设置时投影 `GUIDED_STEP_BY_STEP` 和 revision 0。PUT 使用 `expectedRevision` 做 CAS，并以 `(ownerUserId, clientRequestId)` 保存命令结果；相同请求重放同一结果，不同载荷复用 key 或旧 revision 返回 409。
3. 重新生成只接收稳定 `clientRequestId`。服务端读取指定会话的最后一条有效用户消息及其已保存文本/上下文，再按精确 ID 重新授权；成功时新增 assistant message 和 run，旧回答、消息与审计原样保留。Redis 继续执行并发、额度、租约和取消治理，同 key 重试恢复同一 run，不二次调用 Python。
4. `AI_QUESTION_IMAGE` 继续走 Gateway→Media 创建会话→OSS 单对象直传→complete/READY。策略要求 `learning:access`，只接受 JPG/JPEG、PNG、WebP，最大 10 MiB，资产 scope 为 `USER_PRIVATE`；读取和 Agent 绑定都校验 owner、用途与 READY。

## 外部 API 与契约

- `docs/api/openapi.yaml` 升级至 0.23.2。`AgentClientStreamEvent` 是 `RUN_ACCEPTED`、`STAGE_CHANGED`、`TEXT_DELTA`、`CLARIFICATION_REQUIRED`、`REFERENCE`、`PARTIAL_CHECKPOINT`、`HEARTBEAT`、`RUN_ERROR`、`FINAL_RESULT` 九种事件的 `oneOf`，每种 `eventType` 为字面量并绑定专属 payload。
- `GET /api/v1/ai/preferences/explanation`：读取本人显式偏好、revision、默认状态及允许值。
- `PUT /api/v1/ai/preferences/explanation`：按 `expectedRevision` 和 `clientRequestId` 幂等修改本人偏好。
- `POST /api/v1/ai/conversations/{conversationId}/messages/{messageId}/regenerations`：从已存最后一问启动新 run 并返回既有 SSE；请求不接受正文、媒体或页面上下文。
- Media 的既有上传会话契约现可实际接受 `AI_QUESTION_IMAGE`，并把返回资产投影为 `USER_PRIVATE`。
- `web-apps/packages/api-client/src/generated/schema.d.ts` 已由 OpenAPI 重新生成；类型级编译测试覆盖九类事件的逐类收窄和错误字段拒绝，没有手写并行 DTO。

## 数据库与迁移

## 环境、启动与真实演示

没有新增必须持久化的环境变量。标准本地凭据仍由 `scripts/Initialize-LocalEnvironment.ps1` 初始化，并只通过 `scripts/Invoke-WithLocalEnvironment.ps1` 注入；不得读取或打印凭据文件内容。真实验收使用既有 `edu_platform_agent_dev`、`edu_platform_media_dev`、Redis DB 6、开发 OSS、Gateway、Media、Agent Access、Python runtime 与百炼配置。

可在仓库根目录执行：

```powershell
scripts/Invoke-WithLocalEnvironment.ps1 -Command {
  scripts/Invoke-T14.2.4AgentWebContractRealAcceptance.ps1
}
```

脚本会检查专用 dev Schema，启动四个真实进程，创建并完成一张最小 PNG 上传，以该 `mediaId` 发送消息，修改明确偏好，再对最后一问执行一次显式重新生成；它只输出稳定 ID、状态和计数，不输出完整问答、Token、签名 URL、提示词或工具原始结果。`finally` 按稳定 owner/media/upload/object prefix 精确清理，不使用清库、`FLUSHDB` 或 OSS 枚举删除。

## 已知风险与后续依赖

- 重新生成会真实消耗模型额度；已发往供应商的请求不能因浏览器断线保证不计费。
- OpenAPI 3.1 的 `oneOf` 依靠每个分支的 `eventType const` 生成可收窄联合；当前生成器若升级，需继续以类型级编译测试防止退化。
- 生产上线前仍需确认 Redis 配额、Media 回收调度、OSS CORS/大小限制和数据库迁移窗口。大 chunk 警告不属于本任务，但前端后续应继续拆包。
