# T14.2.4 Agent 浏览器消费契约补口计划

日期：2026-09-11。状态：前置审计完成，规划分支已准备，尚未实现业务代码。

## 背景与目标

T13.4 已通过 PR #63 合并，Agent Access、Python 动态运行时、Redis 治理、帮助专家和真实 SSE 主链均已存在。但 T15A 是只消费生成客户端的前端任务；当前外部契约仍有四个会导致页面猜测或功能伪装的明确缺口，因此不能直接开工：

1. `AgentClientStreamEvent.payload` 仍是无字段结构的普通 object，生成的 TypeScript 无法按事件类型安全收窄阶段、增量、来源、错误和终态。
2. `ai_preference` 已保存明确/推断偏好，但没有本人可用的公开读写契约；学生不得通过查看隐藏画像或发送普通聊天来冒充设置。
3. 目标设计要求显式重新生成启动新 run 并计入用量，但外部 API 只有发送新消息和恢复旧事件；重复旧请求只会幂等恢复，使用新请求重发文本则会伪造一条新的用户消息。
4. OpenAPI 和 Agent Access 已接受 `AI_QUESTION_IMAGE mediaId`，但 Media 的用途策略并未启用该用途，普通学习账号实际无法创建上传会话。

T14.2.4 只补齐上述浏览器消费契约和最小实现，合并后 T15A 才能不手写 DTO、不猜事件字段地完成页面。

## 冻结范围

### 可判别 SSE

- 外部 OpenAPI 从 0.23.1 向前升级为 0.23.2，保留现有 9 个事件名、顺序、唯一终态、恢复和取消语义。
- `AgentClientStreamEvent` 使用可判别联合或等价的强类型结构，使生成客户端可根据 `eventType` 得到对应 payload；至少明确运行接受、阶段说明、文本增量、澄清、授权来源、部分检查点、心跳、安全错误和最终状态字段。
- Java 对进入 MySQL 和浏览器的每类 payload 做结构校验，仍拒绝提示词、推理、工具原始结果、Token、临时 URL 和隐藏画像。不得为前端另造第二套 SSE 或轮询事实。

### 明确讲解偏好

- 增加本人 `learning:access` 的明确讲解偏好查询和修改契约；首期只暴露“分步引导”和“完整解答”两种用户可选值，未设置时返回分步引导默认值。
- 修改携带 `expectedRevision` 并使用既有 `ai_preference`、事务和 revision；并发冲突返回 409，不新增偏好表或复制到 IAM。
- 接口只返回用户明确设置及当前可选值，不返回推断偏好、画像主题、证据、向量记忆或其他内部事实。明确设置持续到本人修改，并继续按既有优先级进入可信上下文。

### 显式重新生成

- 增加 owner 可用、带稳定 `clientRequestId` 的“重新生成最后一问”命令。只允许会话无活动 run、目标为当前会话最后一条有效用户消息，并始终沿用该消息已经保存的文本与授权上下文快照。
- 重新生成创建新的 assistant message 和新的 run，保留旧回答及审计，计入现有 Redis 并发/额度与最终 MySQL 用量；重复同一 `clientRequestId` 返回同一 run，不再次调用 Python。
- 不接受浏览器重传旧正文、mediaId 或上下文，不重新解析当前页面题目，不覆盖旧消息。终态、取消、部分回答和恢复仍复用现有协议。
- 现有 V1 `uk_ai_run_user_message` 不能表达同一用户消息的多次生成；若实现需要迁移，只能新增向前 Flyway 迁移并以请求唯一约束保护，不得改写 V1～V4。

### 学生 AI 图片上传

- Media 启用 `AI_QUESTION_IMAGE` 的 JPG/JPEG、PNG、WebP 单对象上传，单图最大 10 MiB，最多 8 张由 Agent 消息契约继续限制；禁止 SVG、GIF、外部 URL 和 `data:`。
- 授权按 `learning:access` 能力而非固定 `STUDENT` 角色，保证同时具备教学和学习能力的账号也可使用学习空间；其他既有用途的角色/权限策略保持不变。
- 继续走 Gateway→Media 上传会话→OSS 直传→complete/READY，Agent Access 只绑定当前 owner、正确用途且 READY 的稳定 mediaId。取消、失败和未绑定上传沿用 Media 回收，不新增 OSS 客户端。

## 明确不做

- 不实现 Vue、`/ai` 页面、悬浮答疑或公共帮助页。
- 不增加会话归档/删除、画像查看、记忆管理、人工转交或自主组题。
- 不修改 Python 多角色、检索、提示词或模型行为；除真实重新生成长链外不新增模型调用。
- 不新增第二套会话、SSE、Redis 状态、媒体上传客户端或数据库事实源。
- 不使用 RabbitMQ、Qdrant、Neo4j 或 OSS 枚举完成本任务；图片真实验收只操作明确开发前缀并精确清理。

## 验收门禁

- OpenAPI 生成 TypeScript 能按全部 9 类事件收窄 payload，非法或缺字段事件被 Java 拒绝；旧合法请求与恢复事件继续兼容。
- 偏好 owner、默认值、修改、重复、旧 revision 409、错误账号和隐藏画像防泄漏均有测试。
- 重新生成覆盖正常完成与中断回答、原消息快照不变、旧回答保留、同 key 幂等、并发 run 冲突、非最后消息或非 owner 404，以及恢复不二次调用 Python。
- 图片覆盖 `learning:access` 成功、仅角色无能力拒绝、类型/大小/用途/owner/READY 校验、上传失败与取消清理，并验证现有课程、题目和资质用途不回归。
- 使用安全包装器完成最小真实链：学生图片上传到开发 OSS 后随消息运行；一次显式重新生成只新增一个 run；明确偏好修改后进入下一轮可信上下文。记录稳定 ID 后精确删除 MySQL、Redis 和 OSS 验收数据，不读取或清空其他数据。
- Java 全仓 `clean verify`、前端 generate/check/typecheck/test/build、Python 回归、OpenAPI 兼容性与 `git diff --check` 全部通过；未执行项目必须明确记录。
