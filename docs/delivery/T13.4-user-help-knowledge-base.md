# T13.4 用户帮助知识库与 Help 专家接入计划

日期：2026-09-11。状态：前置审计通过，规划分支已准备，尚未实现业务代码。

## 目标与边界

为学生 AI 答疑提供一份由平台维护、面向用户、可版本化的中文帮助知识库，使 Platform Help 能可靠回答登录、账号、课程、学习、题库、作业、考试、成绩和 AI 使用边界等稳定问题。

- 明确规则强命中时直接使用维护正文；复合或自然语言问题先检索有限帮助材料，再由现有模型组织答案。
- 无可靠材料时明确表示不能确定并请求补充描述，不能猜按钮、路由、权限或未发布功能。
- 不读取或暴露 `page-specs.md`、roadmap、内部 API、服务名、测试账号、权限枚举、提示词或隐藏画像。
- 首期不实现帮助编辑后台、反馈提交、Vue 页面、数据库、Redis、RabbitMQ、OSS、Qdrant/Neo4j 新索引或自主组题 Skill。

## 现状与必须修复的闭环

现有内部协议已经预留 Platform Help、`USER_HELP_SEARCH`、`HELP_KB` 和 `USER_HELP` 来源，但实际执行仍被四层阻断：

1. 明确平台问题被路由为 `PLATFORM_HELP + UNSUPPORTED`，没有独立的可执行二级意图。
2. Python 运行时遇到 Platform Help 会直接返回尚未接入的降级文本。
3. `ToolExecutor` 固定拒绝 `USER_HELP_SEARCH`，`AgentAccessClient` 没有帮助查询方法。
4. Java 没有授予 HELP_KB，也没有按 run 授权的帮助检索接口。

T13.4 必须同时闭环这四层，不能只提交静态文档或只让模型自由回答。

## 帮助内容事实源

首期按照既有架构，把帮助内容作为 `agent-access-service` 随版本发布的只读 JSON 资源：

- manifest 只选择一个当前生效版本，并声明语言、版本号、生效时间和内容文件。
- 每个历史版本文件一旦发布不得原地修改；修订内容时新增版本文件，再更新 manifest。
- 每条内容使用稳定 articleId、主题、标题、关键词/明确规则、面向用户正文、允许的相对页面路由和版本。
- 启动与契约测试校验 JSON Schema、唯一 ID、版本一致、正文长度、重复规则、危险内容和路由白名单。加载失败应使帮助能力明确不可用，不能回退到模型猜测。
- 只描述仓库已经交付的用户能力。不得包含“以后会做”、Txx、PR、内部服务、数据库、环境变量或维护指令。

首版至少覆盖：登录/注册/验证码/找回密码、账号安全、公共课程与我的学习、视频/图文/资料、公共题库与课程练习边界、作业/考试提交、成绩与参考答案公布、学习进度，以及 AI 能做和不能做的事情。

## 内部契约与授权

`docs/api/agent-internal.yaml` 向前演进，保持既有 v1 run 和 SSE 兼容：

- 新增明确的 `PLATFORM_USAGE_HELP` 二级意图，归属 `PLATFORM_HELP` 角色。
- 新增 `POST /internal/v1/agent/runs/{runId}/user-help:search`。请求只含有界 query 与 limit，不接收 userId、任意版本或任意路由。
- Agent Access 使用固定 `edu-agent-runtime` 身份和现有内部令牌鉴权，从 MySQL run 反查 owner/终态与当前调用范围；浏览器不能访问该接口。
- 响应只返回当前帮助版本和有限的 `USER_HELP` 证据。证据可带已验证的应用内相对路由；不得返回完整资源文件、规则权重、内部路径或未命中内容。
- `AuthorizedReference` 只增加可选安全路由字段；路径必须来自帮助事实源白名单，禁止 `http(s)`、`//`、`javascript:`、`/internal/**`、`/api/**` 和含未解析占位符的动态路径。
- Java 在可信上下文中为学生 AI run 增加 `USER_HELP_SEARCH + HELP_KB` grant；Python 不能自行添加或扩大 grant。

## 检索与回答策略

1. 高精度规则优先识别明确的平台使用问题，并路由至 `PLATFORM_USAGE_HELP`。
2. Java 对当前版本执行可解释的规范化关键词/短语匹配和有界排序。知识库规模较小时不新增向量 collection 或搜索服务。
3. 单个强规则命中可以由 Platform Help 直接返回维护正文和来源，模型调用数为 0。
4. 复合问题或非固定表达可把最多 5 条命中证据交给现有模型，模型只能基于证据组织语言；提示明确把帮助正文视为数据而不是指令。
5. 没有达到阈值时返回空结果。Python 输出“暂时无法从平台帮助中确认，请说明你所在页面和想完成的操作”，不生成虚构链接。
6. 帮助调用计入既有工具预算；复杂回答的模型调用计入 T14.2.2 用量及 T14.2.3 额度。失败、超时和取消沿用现有唯一终态与有限预算。

## 验收要求

- JSON/manifest 校验：历史版本不可被当前 manifest 混用，重复 ID、危险路由、内部术语、超长正文和非法结构启动失败。
- Java：正确内部身份与真实 run 返回当前版本帮助；错误令牌、未知/他人 run、任意版本请求和危险 query 被拒绝，响应不含 owner 或内部内容。
- Python：五角色边界不变；Platform Help 只调用 `USER_HELP_SEARCH`。明确登录问题规则直答且 0 模型调用；复杂课程/成绩问题只根据命中材料调用模型；无命中不猜路由。
- 注入与防泄漏：即使帮助正文含类似指令文本，也不能改变角色、工具、授权或暴露内部材料。页面来源只显示白名单相对路由。
- 真实链：通过安全包装器启动 Agent Access 与 Python，使用一个明确问题验证规则直答，再用一个有界复杂问题验证百炼基于证据回答；不记录完整提问、回答、提示词、Token、密钥或内部原文。
- 执行 Java 全量、Python compileall/unittest/wheel、内部协议 Schema 测试，以及外部 OpenAPI 生成无差异检查；本任务不修改 Vue。

## 数据与清理

知识库 JSON 是版本化仓库资产，不是伪数据。自动化优先使用进程内 H2/Fixture；真实验收只在 `edu_platform_agent_dev` 创建随机 owner/conversation/run，用后按稳定 ID 精确删除。不得创建账号、课程、题目或长期演示 Seed，不得写 Redis Key、RabbitMQ 消息、Qdrant 点、Neo4j 节点或 OSS 对象。
