# T13.4 用户帮助知识库与 Help 专家接入

日期：2026-09-11。状态：实现与本机真实验收完成，等待代码评审与 CI。

## 任务目标与功能边界

本任务为学生 AI 答疑接入由平台维护的中文用户帮助事实，使 Platform Help 可以可靠回答登录、账号、课程、学习内容、题库边界、作业考试、成绩公布、进度和 AI 使用边界。

- 高精度规则命中直接返回维护正文，不调用模型；复合问题最多携带 5 条帮助证据，交给现有百炼模型组织语言。
- 无可靠命中时只说明无法从平台帮助中确认，并请学生补充所在页面和目标操作，不猜按钮、路由或未发布能力。
- 本任务不实现帮助编辑后台、反馈提交、Vue 页面、公共 `/help` 页面、数据库迁移、Redis Key、RabbitMQ 消息、OSS 对象、Qdrant/Neo4j 索引或自主组题。

## 主要架构与调用流程

1. Python 意图分类把平台使用问题固定映射为 `PLATFORM_HELP / PLATFORM_USAGE_HELP`；该意图只能申请 `USER_HELP_SEARCH`。
2. Java 在创建合法学生 AI run 的可信上下文时授予 `USER_HELP_SEARCH + HELP_KB`。Python 不能自行增加 grant、scope、owner 或版本。
3. ToolExecutor 使用现有调用预算，经 `AgentAccessClient` 调用 Agent Access 内部接口。固定 caller 与现有内部令牌先鉴权，Agent Access 再按 `runId` 从自身 MySQL 事实反查 owner 和运行边界。
4. `UserHelpKnowledgeBase` 由 manifest 选择当前版本，在启动时严格加载并执行结构、语义、唯一性、版本、正文和路由校验。正式 JSON Schema 由构建测试校验；任一失败都会明确阻止启动，不回退为模型猜测。
5. Java 只返回当前版本的有限 `USER_HELP` 安全证据，不返回匹配分数、规则、文件路径、owner 或未命中文章。应用内路由来自精确白名单。
6. Python 对直接命中使用维护正文；复杂命中把帮助正文明确作为不可信数据放入有界提示，禁止其改变角色、授权或工具；终态、SSE、取消、部分回答、超时与用量上报继续复用 T13.3/T14.2 既有实现。

## 帮助资源与版本规则

- `help-kb/manifest.json` 当前选择 `2026.09.1`，语言为 `zh-CN`。
- `help-kb/user-help.schema.json` 使用 JSON Schema Draft 2020-12，拒绝额外字段并约束文章 ID、主题、标题、关键词、规则、正文、版本和可选路由。
- `help-kb/versions/user-help-2026.09.1.json` 包含 11 篇文章。已发布文件按版本独立保存；后续修订必须新增版本文件并更新 manifest，不得原地覆盖历史版本。
- 首版路由白名单为 `/login`、`/register`、`/forgot-password`、`/profile/security`、`/courses`、`/my-learning`、`/practice`。外部 URL、协议相对 URL、`javascript:`、`/internal/**`、`/api/**`、路径穿越和动态占位符均被拒绝。
- 正文危险词检查拒绝内部任务号、PR、服务/数据库/环境配置、测试账号、隐藏权限和提示词注入式维护指令。正文只描述已交付的学生功能。

## 内部 API 与兼容性

`docs/api/agent-internal.yaml` 从 1.1.0 向前升级为 1.2.0，现有协议头、run POST、SSE 事件、取消、恢复和旧字段保持兼容。

- 新二级意图：`PLATFORM_USAGE_HELP`，固定归属 `PLATFORM_HELP`。
- 新接口：`POST /internal/v1/agent/runs/{runId}/user-help:search`。
- 请求仅包含非空 `query`（最多 500 字符）和 `limit`（1～5），严格拒绝 `userId`、版本、路由或其他字段。
- 响应包含当前 `helpVersion` 与最多 5 条证据；证据为 `USER_HELP`，只含稳定 evidence/article ID、标题、学生正文、版本、直接命中标记和可选白名单路由。
- `AuthorizedReference` 与 `SafeToolEvidence` 只增加可选、向前兼容的帮助版本/直接命中/相对路由字段。
- 未修改外部 `docs/api/openapi.yaml`，重新生成外部 TypeScript 客户端后无差异。

## 环境变量与启动方式

本任务没有新增环境变量，也没有把秘密写入仓库或 `local.env`。本地凭据仍由 `scripts/Initialize-LocalEnvironment.ps1` 初始化，并且所有真实命令必须经 `scripts/Invoke-WithLocalEnvironment.ps1` 注入。

```powershell
# Java Agent Access
scripts/Invoke-WithLocalEnvironment.ps1 -ScriptBlock {
  java -jar java-platform/agent-access-service/target/agent-access-service-0.1.0-SNAPSHOT.jar --spring.profiles.active=local
}

# Python runtime
scripts/Invoke-WithLocalEnvironment.ps1 -ScriptBlock {
  D:\Anaconda\envs\langgraph\python.exe -m edu_agent_app
}

# 本任务最小真实闭环（脚本自行启动和停止两端服务并精确清理）
scripts/Invoke-WithLocalEnvironment.ps1 -ScriptBlock {
  scripts/Invoke-T13.4UserHelpRealAcceptance.ps1
}
```

真实验收脚本显式关闭在线检索、Redis 运行治理、索引发布、消息保留任务和 Media Outbox 发布，因此不会访问或写入 Qdrant、Neo4j、Redis、RabbitMQ、OSS。

## 数据、伪数据与清理

- 没有创建数据库、表、迁移或长期 Seed。版本化帮助 JSON 是应用资源，不是数据库伪数据。
- 自动化使用进程内 H2/内存替身，JVM/进程退出后释放。
- 真实验收只在已有、用途明确的 `edu_platform_agent_dev` 中，经公开 AI 会话入口创建 1 个随机 owner、2 个会话、各自消息/run/事件和用量事实。没有创建账号、课程、题目或测试登录身份。
- `finally` 按随机 owner 和外键顺序精确删除相关索引 Outbox、记忆/证据/摘要/偏好/主题、安全/用量/工具/取消/事件/媒体引用/run/消息/会话；清理后重新查询 owner 关联事实总数为 0。没有清空共享表，也没有改变全局序列。
- 重新生成方式：再次执行上面的真实验收命令；每次均使用新的随机 owner，完成后自动删除。

## 已知风险与后续依赖

- 历史版本不可变依靠独立版本文件、Git 审查和测试约束，不新增 hash/baseline gate；发布者仍必须遵守只新增版本的流程。
- 当前检索适合首版小型知识库，使用规范化短语和关键词排序；内容规模显著增长时应另行评估检索召回，但不能把帮助接入课程/记忆索引或让无命中回退自由生成。
- 帮助正文会随产品能力演进而过期；修订必须新增版本、更新 manifest，并同时运行 Schema、危险内容、路由和真实闭环测试。
- T15A 只消费现有 SSE、参考来源与安全相对路由，不读取知识库文件、不复制规则，也不新增平行 Help API。
