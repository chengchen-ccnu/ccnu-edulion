# T13.5.1 标准 Skill Runtime

日期：2026-09-13。状态：实现、自动化与真实 MySQL 验收完成；Ready PR 待合并。

## 目标与功能边界

本任务为 `edu_agent_app` 建立 Codex 风格的通用目录 Runtime：内置 Skill 以 `edu_agent_app/skills/<skill-name>/SKILL.md` 为入口，可选携带 `scripts/`、`references/`、`assets/`。Runtime 负责启动发现、有限选择、渐进读取、可信内置脚本执行、统一结果信封和 Agent Access 私有审计。

本任务没有创建组题目录 Skill，没有迁移或删除现有 `PracticeGenerationSkill`，也没有改变组题、检索、Learning 创建或 pending action。包内当前只有 `skills` Python 包而没有具体标准 Skill；T13.5.2 才迁移 `public-practice-generation`。没有 `runtime.yaml`、`agents/openai.yaml`、用户目录加载、在线安装、热加载、hash、baseline、冻结 gate 或第二套插件框架。

## 架构与调用流程

1. 进程组装时，注册表只扫描 wheel 包内 `skills/*/SKILL.md` 的一层目录。frontmatter 以 `yaml.safe_load` 解析，只接受必需 `name`、`description` 和可选 `metadata.version`、`metadata.script-timeout-seconds`；名称必须为 lower-kebab 且等于目录名，版本必须为三段数字 SemVer。
2. Runtime 先使用显式开发测试调用，否则按平台维护的角色、一级/二级意图规则过滤。一个候选直接选；多个候选最多调用一次结构化 LLM；无候选、非法返回或模型失败均返回普通专家回答，不循环或并行试跑。LLM 调用与 Token 进入同一 `RunLimits`。
3. 选中后才加载完整正文，并先向 Agent Access 创建 RUNNING 审计。开始审计失败时不返回执行上下文，因此脚本和后续业务动作均不会发生。
4. 模型只可用相对路径读取当前 `references/` UTF-8 文本，或用 JSON stdin/stdout 执行当前 `scripts/` 下 `.py`。两类调用均计入现有工具和总时限预算；同一脚本与相同输入不能无限重复。
5. Runner 把受 Git 审查的内置 Skill 复制为只读临时副本，以独立工作目录、当前 Python 解释器和清理后的非秘密环境启动子进程；网络 socket、`subprocess` 和常见 `os.spawn/system` 入口被禁用。超时、取消或输出越界会终止子进程并精确删除临时目录。
6. 真实脚本成功后，Runtime 自行填充 `skillName`、`skillVersion`、`script`、`executionId`、`resultType`、`payload` 信封；脚本或模型即使在 payload 中伪造同名键，也不能覆盖外层身份。

## 私有 API、数据库与迁移

内部协议从 1.3.0 升级到 1.4.0，新增：

- `POST /internal/v1/agent/runs/{runId}/skill-executions`：写入 Runtime 生成的 executionId、子请求顺序、Skill 名称/版本和选择来源。
- `PUT /internal/v1/agent/runs/{runId}/skill-executions/{executionId}`：更新完成、失败、取消或超时，并仅携带有界 reference 相对路径、脚本相对路径和安全失败码。

Agent Access V7 新建 `ai_skill_execution`，唯一 `(run_id, sequence_no)` 保证每子请求最多一个 Skill。终态 run 会把遗留 RUNNING 更新为 `ABANDONED`、失败码 `RUNTIME_INTERRUPTED`，不会自动重跑。审计不保存指令/reference 正文、脚本输入输出、提示词、题干、答案、Token、环境变量或绝对路径，不复用 `ai_tool_call.safe_summary`，也不进入 Gateway、浏览器 OpenAPI、SSE 或 RabbitMQ。

真实验收只复用用途明确的 `edu_platform_agent_dev`，由 Flyway 从 V6 向前创建 V7 表；没有创建数据库或永久伪数据。既有专项生成的随机记忆 owner/source 行在 `finally` 精确清理；本任务没有向真实 `ai_skill_execution` 写行，V7 表结构按迁移预期保留。

## 配置与启动

正式依赖新增 `PyYAML>=6.0,<7`，wheel package-data 已声明未来 Skill 的 Markdown、scripts、references 和 assets。统一非敏感配置及默认值为：

- `AGENT_SKILL_REFERENCE_MAX_FILES=3`
- `AGENT_SKILL_REFERENCE_MAX_FILE_BYTES=131072`
- `AGENT_SKILL_REFERENCE_MAX_TOTAL_BYTES=262144`
- `AGENT_SKILL_SCRIPT_DEFAULT_TIMEOUT_SECONDS=10`
- `AGENT_SKILL_SCRIPT_MAX_TIMEOUT_SECONDS=30`
- `AGENT_SKILL_SCRIPT_MAX_OUTPUT_BYTES=65536`
- `AGENT_SKILL_SCRIPT_GLOBAL_CONCURRENCY=4`

配置受代码硬上限和交叉校验约束。正常启动仍为 `python -m edu_agent_app`；本机测试使用 `D:\Anaconda\envs\langgraph\python.exe`，该路径没有进入生产代码或 CI 要求。本次只更新 `.env.example`，没有修改个人 `local.env`，因此没有明文需要删除或迁移；秘密继续只由 DPAPI 包装器或部署 Secret 注入。

## 人工验收与可读性

当前没有具体标准 Skill，因而没有新增学生可见演示入口。开发者可运行 `tests/test_skill_runtime.py`，观察两个临时候选的显式/规则/单次 LLM 选择、选中后正文加载、reference 限制、脚本 JSON 信封、秘密隔离、网络/子进程拒绝、超时/取消清理和审计 fail-closed；Java 集成测试覆盖开始/完成严格幂等及 run 终态后的 ABANDONED 收口。

## 已知风险与后续依赖

首期按任务要求信任经过 Git 审查并随 wheel 发布的内置脚本，不是针对恶意代码的操作系统级沙箱。清理环境和 Python 入口禁用是纵深防护，不能替代代码评审；若未来开放第三方或在线 Skill，必须另行设计容器/OS 隔离，不能直接复用当前信任假设。并发上限是单 Python 进程全局值，多副本总并发仍由部署容量治理。
