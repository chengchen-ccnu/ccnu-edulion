# T16.2 教师资格审核后端契约交付

> 2026-10-01；分支 `codex/t16.2-teacher-qualification-review-contract`；基线 `main@d1f463f`，保留总控准备提交 `955bcc8`。实现提交与 PR 在推送后填写。本任务只交付后端，T17C 才交付管理 Vue，T16.4 才消费审核决定并发送站内消息。

## 目标和边界

复用 T12D 的申请、普通账号能力、刷新会话及 T07 Media 上传/引用台账。管理员列表只含申请编号、内部账号标识、展示名、状态和时间；详情主动打开才开始审核。批准/驳回保留轮次和决定历史，批准与教师能力及审计在同一个 IAM 事务提交，刷新既有学生会话可得到教学权限。材料原件始终走 IAM 按具体轮次授权、Media 一次性服务令牌和短期 OSS 签名 URL。

本任务没有实现 Vue、课程审核、OCR、多级审批、教师撤权/封禁、管理员邀请、公告或站内消息。管理员独立身份、学生学习能力保留；审核不能用角色头或任意 mediaId 绕过 IAM 事实。

## 架构与调用流程

1. 学生沿用 `POST /api/v1/teacher-applications`。Media 先验证上传者、`TEACHER_QUALIFICATION` 精确用途与 READY，IAM 事务写当前投影、新轮次、稳定请求命令、安全审计与 `MediaReferenceBound` Outbox。驳回后的重提创建新轮次，并把旧轮材料的引用释放截止延至替换后 7 天。
2. Gateway 和 IAM 双层要求 `administration:access`，IAM 业务层再确认真实 ACTIVE 管理员角色与权限。管理员列表只读；第一次打开详情将当前轮从 SUBMITTED 推到 UNDER_REVIEW、revision 加一并记录首次查看者/时间。其他管理员可继续处理，不存在独占锁。
3. 决定命令使用 `clientRequestId`、请求指纹和 `expectedRevision`。同请求可返回保存的原结果；不同载荷重用请求 ID、旧 revision 或已决定轮次返回 409。批准还要求确认材料，并通过 Media 短期授权实际读取原件首字节；Media 失败时事务回滚。批准同时授予同账号 TEACHER/`teaching:access`，检查 `learning:access` 仍在。驳回理由长度 10～1000 字，决定不可覆盖。
4. IAM 使用申请 ID＋轮次 ID 解析固定 mediaId，再签发 30 秒、一次性 jti 的内部服务令牌。Media 验签、校验 IAM issuer、管理员 UUID、用途/访问类型/原件/处置方式、READY 状态和 jti，最终签发短期 OSS 原件 URL。浏览器只收到临时授权，不接触 Object Key/Bucket 或服务令牌。
5. 被驳回或被替换的旧轮在各自起点 7 天后由有界任务将 `MediaReferenceReleased` 写入 IAM Outbox。`release_enqueued_at` 只表示释放事件已可靠入队；Media 消费后才更新引用台账，最后一个有效引用释放后仍遵守 Media 原有宽限期与回收检查。决定/审计文本长期保留。待审和通过轮次无截止期，包括后来撤权时。

## API、事件与存储

- OpenAPI 从 0.27.0 向前演进为 0.28.0：`GET /api/v1/admin/teacher-applications` 四状态筛选、`NEWEST/OLDEST` 稳定排序、有界分页和申请 UUID/规范化身份精确查找；`GET /{applicationId}` 主动打开详情；`POST /{applicationId}/decision`；`POST /{applicationId}/material-access`。本人 `/me` 继续只返回最新安全投影。
- MediaReferenceBound/Released v1 复用 `edu.media.events.v1`；新增 `TEACHER_APPLICATION_ROUND` 引用类型，以不可变轮次 UUID 为 referenceId。新 `TeacherQualificationDecided` v1 只携带申请、轮次、用户 ID 与决定状态，不携带文件、联系方式或驳回全文；T16.4 后续消费。
- IAM V4 向前新增 `teacher_application_round`、`teacher_review_decision`、`teacher_review_command`、`iam_outbox_event`，并为列表增加索引。V1～V3 未改。旧申请回填为第一轮，旧有效材料在有界 Worker 中补建引用事件；旧已到期且从未绑定的轮次不会伪造释放。
- IAM Outbox 使用持久 Rabbit 消息、mandatory return、publisher confirm、有限指数退避和耗尽 `FAILED` 留痕；同一媒体的后续事件等待前序发布确认，防止释放抢在绑定之前。Media 引用消费者继续按 `eventId` 幂等。IAM 决定队列持久化并带 DLQ，消息系统消费者留 T16.4。审核事实成功与消息送达是两个状态，不把异步失败说成审批回滚。

## 人工演示步骤

1. 用普通学习账号完成已有资质上传并提交；在管理列表按状态和编号/身份精确查找，确认列表无文件与联系方式、刷新列表不触发审核中。
2. 管理员打开详情，观察首次查看者/时间和 revision；另一管理员打开同一详情，确认未独占。请求当前轮 PREVIEW/DOWNLOAD，实际打开短期图片/PDF。
3. 用当前 revision 批准并明确确认材料；同请求 ID 重放结果不重复决定，旧 revision 返回 409。学生刷新既有会话后 `/users/me` 同时含 `learning:access` 和 `teaching:access`。
4. 另一合成申请驳回并填可理解理由，学生 `/me` 只见最新；替换材料重提后管理员详情保留旧决定。把专用测试轮次时间推进至七天边界，观察 IAM Outbox/Media 引用释放与 Media 宽限期，不把排队释放等同 OSS 物理删除。
