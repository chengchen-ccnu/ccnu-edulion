## 2. 契约与调用流程

### 2.1 外部 API

`docs/api/openapi.yaml` 向前升级至 **0.27.0**。保持已有请求、成功响应和发布枚举，新增可选 `ApiError.supportEmail`、`progressBufferDiscarded` 及暂停响应；相关 Course/Learning 操作及教学文件预览声明 409/503。生成客户端为 `web-apps/packages/api-client/src/generated/schema.d.ts`，没有手写第二套 DTO。

| 使用位置 | 暂停返回 | 其他边界 |
|---|---|---|
| Course 公开详情/内容/新播放授权、本人教学内容 | `409 COURSE.SUSPENDED`，课程暂不可用及配置邮箱 | 公共和教师列表排除暂停课程；未知、非 owner 保持安全 404 |
| Learning 课程学习、课程练习/作业/考试、旧 assessment/attempt/note/wrong ID、学情 | `409 LEARNING.COURSE_SUSPENDED`，安全文案、邮箱及 `progressBufferDiscarded=true` | Course 故障 503；无课程自主练习不受影响 |
| Media 通用 owner 教学文件预览 | `409 MEDIA.COURSE_SUSPENDED`，安全文案和邮箱 | 可信 TEACHER 与 teaching:access；Course 故障 503，失败不调用 OSS |

保留统一错误六字段。暂停错误不包含正文、审核/撤权原因、教师身份或签名 URL。已有 OSS URL 按原有效期过期，不承诺即时吊销。稳定媒体元数据和其他领域历史事实保留。

### 2.2 内部 API

独立契约：`docs/api/course-suspension-internal.yaml`，**1.0.0**；Gateway 未增加内部路由。

| 路径 | 固定调用方 | 输入/输出 |
|---|---|---|
| `PUT /internal/v1/teachers/{teacherId}/course-availability` | iam-service | UUID suspensionId、正整数 accessRevision、布尔 paused；返回当前水位及影响数 |
| `GET /internal/v1/courses/{courseId}/availability?afterSequence=0` | learning-service | 精确课程 owner、revision、paused、邮箱、最多 100 个区间和 hasMore |
| `GET /internal/v1/teachers/{teacherId}/course-media-access` | media-service | 已验证媒体 owner 的教学预览资格，允许 204，暂停安全 409 |

固定 `X-Internal-Caller` 与至少 32 字节的 `X-Internal-Service-Token` 必须同时匹配，秘密常量时间比较。IAM 写命令使用独立秘密；Learning/Media 只读适配复用现有 Course/Media 秘密。错误 caller/秘密或缺失身份 401；非法 UUID/参数 422；未知精确课程 404。Media 只取得授权裁决，不查其他服务数据库。

未来 IAM 持久化单调 `accessRevision`；每次撤权用新 `suspensionId`，恢复沿用该 ID。旧 revision 返回当前事实无副作用；相同 revision 相同内容幂等，相同 revision 不同内容、活动周期不匹配或重用恢复后的周期为 409。恢复先到留下水位，迟到暂停不复活旧状态。更高 revision 的相同活动状态只推进账号水位，不重复写区间。

### 2.3 Course 事务与可靠事件

锁顺序为教师行锁 → 课程 ID 升序行锁，每批最多 100 门，同一账号命令整体事务提交。发布流程同样先锁教师，暂停教师不能发布草稿绕过限制。恢复只闭合同周期、仍系统暂停的已发布课程。

新增 `CourseAvailabilityChanged` v1，Schema 为 `docs/events/course-availability-events.v1.yaml`。完整信封；payload 仅含课程 ID、周期 ID、revision、paused、suspendedAt、resumedAt。暂停必须显式 `resumedAt:null`，恢复给出结束时间，不发布原因/媒体信息。

- Exchange `edu.course.availability.events.v1`，routing key `course.availability.changed.v1`。
- Queue `edu.learning.availability.v1`；DLX `edu.learning.availability.dlx.v1`；DLQ `edu.learning.availability.dlq.v1`；死信 key `learning.availability.dead.v1`。
- Course 同事务写既有 Outbox，复用 mandatory、publisher confirm、最多 20 次有限补投；没有第二套发布器。
- Learning Spring AMQP 总计最多 3 次尝试，失败拒绝不重入队，进入 DLQ；成功与 eventId 幂等事实同事务提交。毒消息不自动回流。
- 事件仅提示追平，消费者通过受保护 HTTP 读取当前权威事实。迟到暂停不覆盖恢复；重复 eventId 不再补时；非法版本/字段进入 DLQ。人工补偿先修复依赖再按原 eventId 重放。

## 3. Learning 时钟、并发与进度

### 3.1 在原系统内补时

`@CourseClock` 显式标注受影响入口，外层可写事务先取得 Learning 课程行锁、访问 Course，然后进入既有领域事务。旧 ID 在本域反查课程并约束主体；非 owner/未知统一 404，教师主体再核对 Course owner。列表同步后重读任务，避免返回顺延前的时间。

草稿保存、提交、教师调截止、关闭/结算、公布/批改及 Worker 共用课程 → 测评 → attempt 锁顺序。暂停时前台拒绝，后台关闭/结算无操作；依赖故障拒绝执行并保留待处理事实。

按 Course 微秒区间计算时长，仅在一个闭合区间首次应用时顺延：

- HOMEWORK/EXAM 在暂停前已发布、仍 OPEN、答案/成绩未公布，暂停开始最终截止未过去或没有截止。
- closesAt、lateUntil 顺延；尚未开放的 opensAt 也顺延，保留等待和作答窗口。
- 这些任务中，仅 DRAFT 且 deadlineAt 未过期的 attempt 顺延服务端截止，保留原剩余考试时间。
- 已提交/已批 attempt、CLOSED 或已公布的任务不改、不重开。PRACTICE 只有访问门禁，没有新增时钟。
- 多次闭合区间逐项应用，完成水位和审计唯一键防重复；100+ 历史区间全部分页追平。分页间 Course revision 变化则整体回滚为 503，后续重试。
- 顺延递增既有 task/attempt revision；旧 revision 写请求仍 409，应刷新。恢复后继续使用原有至少距当前时间一小时等截止调整规则。

### 3.2 授权准入边界

跨服务使用实时 HTTP，不建立分布式事务。**以 Course 权威可用性读取为请求准入边界**：暂停提交后取得暂停事实的请求拒绝；提交前已取得允许事实的在途请求可以完成本次事务。Learning 行锁保证同课程补时与领域操作互斥。不能据此声称取消全部在途请求或吊销 OSS URL。T16.3 必须完成/可靠重试 Course 协调后才能报告完整成功，并使旧教学令牌失效。

### 3.3 Redis 舍弃边界

沿用 Hash、dirty ZSet、Lua、Worker/MySQL，不新增进度系统。聚合增加 availabilityRevision：

1. 暂停/恢复改变代际，未落库旧 Hash **整体舍弃**；无法精确拆分的观看/日增量不补入 MySQL，已落库/强制检查点保留。
2. 暂停拒绝新进度；读取、强制检查点、Worker 核对代际。暂停/旧代际 Worker ACK 舍弃，但仍核对代际、版本、租约才精确删除；依赖故障保留 dirty 重试。
3. 恢复后新 Lua 心跳原子重置到 MySQL 基线；恢复前/暂停期间的旧事件拒绝，观看增量最多为最近恢复后实际经过秒数。
4. 旧无代际缓冲兼容为 0，ACK 不因缺字段永远失败。新增指标 `learning.progress.worker.suspension-discarded`。
5. 暂停错误 `progressBufferDiscarded=true` 提供后续客户端提示契约；本次未实现 Vue 提示。

授权不再使用旧一秒缓存；Course 故障为 503，不使用过期允许事实。

## 5. 测试数据与清理

真实验收仅用明确的 `edu_platform_course_dev`、`edu_platform_learning_dev`、Redis DB **4** 与本地 RabbitMQ；各 JVM 只创建/清理本域 Fixture，跨服务只走 HTTP/事件。

- Course：随机 teacher/course/version/chapter/lesson UUID，一个最小已发布测试课程。VIDEO 只有进度所需类型/修订元数据，没有可播放资产或 OSS 对象。
- Learning：随机 learner、报名/进度；HOMEWORK/EXAM/PRACTICE 各一场，前两者草稿各一份。任务没有题目，仅验访问/时钟，不以空题宣称评分通过。另有最小进度事件、日活动、时钟/消费审计及 Outbox。
- 两次暂停/恢复发出四个确认事件；另注入旧暂停重复事件与不支持版本毒事件，只按毒事件 eventId ACK，不 purge 队列。
- dirty ZSet 与目标 DLQ 必须原本为空，否则停止，避免领取已有积压。Hash/dirty member 按本轮随机键清理。
- finally 按精确 ID 逆外键清理并断言残留零，实际输出 Course/Learning cleanup complete。正式新表与持久 RabbitMQ 资源保留，临时业务行、Redis 缓冲和本轮毒消息已清理。
- 人工《线性代数》`5cfa6b44-92f4-4d11-9fcb-67dd1c8c5057` 前后完整 course 行一致；目录、绑定、视频和人工学习事实没有写入。本次未播放第二课时/调用真实 OSS。
