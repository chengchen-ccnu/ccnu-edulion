## 目标和边界

启用既有“账号权限”侧栏和 `/admin/users`，保持“教师审核、账号权限”顺序与默认审核落点。交付账号分页、状态/关键词查询、脱敏详情、四动作的影响预览/二次确认、最近命令恢复、状态查询和有限补偿，并同步统一登录后的安全深链回跳。

没有实现管理员邀请、教师审核改造、任意角色编辑、解锁、强制下线、账号资料编辑或新导航槽位。没有修改 Java、OpenAPI 0.31.1、事件或迁移；生成的 `schema.d.ts` 与 HEAD 一致。首次教学仍由正常资格审核授予，恢复的资格及暂停周期由后端核对。

## 主要文件和流程

- `web-apps/apps/admin-web/src/views/AccountPermissionsPage.vue`：管理页面、内存写入快照、查询/错误/离页状态及计时器清理。
- `web-apps/apps/admin-web/src/account-permissions-api.ts`：生成 GatewayClient 的七个受控接口适配；共用认证的一次401恢复。
- 管理端 `router.ts`、`navigation.ts`、`styles.css`：受保护路由、固定侧栏启用及响应式样式。
- `web-apps/packages/api-client/src/index.ts`：仅增加生成 schema 类型别名，没有重复 DTO。
- `web-apps/packages/auth/src/index.ts`：ADMIN安全回跳接受账号路由；页面与登录共用定位参数过滤。
- 相应组件/适配器/路由/导航/共享认证测试，以及四个 `scripts/*T17C2*` / `scripts/t17c2_*` 验收工具。

调用链为 `AccountPermissionsPage → account-permissions-api → authorizedRequest → 生成GatewayClient → Gateway → IAM → 已有Course/Learning内部协调`。浏览器不直连领域服务或数据库。账号管理本身不需要OSS；真实资格夹具复用既有Media上传和授权，不增加生产上传功能。

| 现有API | 页面行为 |
|---|---|
| GET `/api/v1/admin/users` | page/size=20、keyword、status；仅当前页，不逐行预取详情或命令。 |
| GET `/api/v1/admin/users/{userId}` | 按需脱敏详情、真实能力、封禁/短期锁定、revision。 |
| POST `…/{userId}/permission-previews` | 四种合法动作的五分钟预览、真实课程数/去重ACTIVE学生数；503不显示零。 |
| POST `…/{userId}/permission-commands` | 10～500字理由、勾选、二次确认、原preview/revision及稳定ID；202只表示IAM提交。 |
| GET `…/{userId}/permission-commands/latest` | 重新进入/刷新/跨管理员接手先查询；204先返回null，不解析空正文；不猜ID关系。 |
| GET `/api/v1/admin/permission-commands/{commandId}` | 读取公开返回的命令ID，并核对userId；四态按服务端事实展示。 |
| POST `…/{commandId}/retry` | 仅FAILED且attempts在3～5，以当前expectedAttempts及稳定补偿ID明确补偿一次。 |

URL只保存page（1～50001）、ACTIVE/DISABLED状态、userId/commandId UUID和detail/coordination面板。关键词、理由及原载荷仅内存，不进入URL、日志或持久存储；未知/重复/非法参数及hash被过滤。没有角色筛选或任意排序控件。登录默认落点仍是教师审核。

普通账号展示学生、学生＋教师或封禁；管理员单独展示，只有受控BAN/UNBAN，自封禁按钮不提供且服务端仍保护。短期锁定独立显示。UNBAN只恢复学生，RESTORE_TEACHING在Course确认后重读账号能力与revision。NOT_REQUIRED/PENDING/FAILED/APPLIED分别说明，APPLIED不承诺所有Learning消费者/通知完成。

每个HTTP请求15秒有界等待。写入网络/5xx/超时保留未知结果、原ID和原载荷，最多三次手动发送；不自动新建命令。查询最近事实不会推断原请求是否成功，必须完成新一轮账号/latest读取并明确“已核对”才结束本地未知请求。409必须显式刷新核对再重新预览，422保留理由并显示字段错误，429尊重Retry-After。

PENDING默认2秒最多30次查询，页面props可调整（间隔至少500ms、次数1～100）；到限转手动查询。隐藏、离线、切账号、身份变化或卸载取消查询。FAILED不自动补偿，六次预算耗尽明确交后续运维；原命令不另建周期。身份变化或401/403清私有数据和原载荷，旧请求不能串到新账号；卸载清除HTTP等待、轮询、到期、冷却计时器及所有监听。理由、在途/未知写入有切账号/离页/关闭标签提醒，关闭或崩溃后不承诺保存内存载荷。

## 人工演示与后续依赖

1. 用上面脚本建立专用夹具与环境；由合成学生正常上传资质、管理员通过真实授权读取后批准。
2. 管理员统一登录深链到账号详情，查看脱敏列表/能力及短期锁定，进入两发布课教师的撤权预览，核对2门课程/1名去重学生。
3. 填10～500字理由、勾选、二次确认。先看IAM提交和PENDING，再看Course确认；恢复教学后重新核对revision/实际能力。
4. 封禁后检查旧会话失效，解封仅学生、再单独恢复教学；草稿始终不暂停。并发409先刷新核对，不覆盖另一管理员决定。
5. 丢回执时保留未知和原载荷，另一管理员用userId重新进入恢复最新命令。FAILED只在服务端预算许可时补偿，六次耗尽停止；故障演示在Mock下明确标注。
6. 检查刷新、返回、移动宽度和键盘，最后verify、cleanup、STOP。不要操作原管理员或手工课程。
