# T11C.2 课程作业/考试与教师成绩册前端

## 任务目标与边界

本任务在已合并的 OpenAPI 0.21.0、T11C.1/T11C.1.1 后端和 T12B 前端基础上，交付学生端 HOMEWORK/EXAM 课程上下文与教师成绩册。PRACTICE 仍只在 `/practice`；作业和考试不再从练习中心进入。

本任务没有修改 Java、Python、Flyway、RabbitMQ、Redis、OSS、OpenAPI 或全局页面规格；没有实现历史 attempt 查看、附件作业、免交/个别延期、排名、异步 XLSX、第二套答题器、结果页或批改器。

## 页面、路由与调用流程

学生端新增并保护以下路由，均要求 `learning:access`：

- `/learn/:courseId/tasks`：课程任务总览，调用 `GET /api/v1/learning/courses/{courseId}/tasks`，只渲染 HOMEWORK/EXAM 安全摘要、服务端时间状态、提交/批改事实、次数和时间节点。
- `/learn/:courseId/tasks/:assessmentId`：课程任务作答。与旧 `/practice/:assessmentId` 共用 `PracticeAttemptPage`、`AttemptSaveController`、服务端 deadline 校准、题目渲染、媒体授权、有限重试和离页清理；课程任务调用课程任务详情/开始接口。旧练习深链遇到 HOMEWORK/EXAM 会转入课程任务路由。
- `/learn/:courseId/tasks/:assessmentId/result`：调用最后有效结果接口，不接受 attempt ID；与旧结果页共用双视图和 `resultDisclosure` 安全投影。

课程详情只有在已恢复报名且具备学习能力时显示“课程作业与考试”入口；当前学习页调用课程任务列表并传递精确 `currentLessonId`，只展示当前课时的任务，不提供课程总览链接。

教师端新增 `/teacher/gradebook`，要求 `teaching:access`。页面只负责 HOMEWORK/EXAM 成绩矩阵、提交/批改/迟交状态、服务端汇总和 CSV。点击有最终 attempt 的单元格复用既有 `/teacher/assessments?courseId=&assessmentId=&attemptId=&panel=grading` 深链，不复制教师批改面板。

## API 与前端适配

`packages/api-client/src/index.ts` 增加了对已生成 OpenAPI schema 的课程任务、成绩册和查询类型导出；生成文件未手工修改。

学生 `assessment-api.ts` 新增：

- `listCourseTasks`
- `courseTask`
- `startCourseTask`
- `courseTaskResult`

教师新增 `gradebook-api.ts`：

- `getTeacherGradebook`
- `exportTeacherGradebookCsv`

CSV 适配器请求使用 `parseAs: "text"`，将生成客户端返回的 CSV 文本封装为真实 Blob，读取并净化 `Content-Disposition` 文件名；页面为每次逻辑下载生成稳定 `clientRequestId`，防重复点击，显示长时间生成状态，支持取消，finally 撤销 Object URL 和中止请求。导出只携带当前有效筛选条件，不把分页/排序伪装成导出契约字段。

成绩册 URL 状态由 `gradebook-state.ts` 规范化：`courseId`、`assessmentId`、`type`、`submissionStatus`、`gradingStatus`、`late`、`keyword`、`page`、`size`、`sort`、`direction`。无效枚举、页码、尺寸和方向回到确定默认值；PENDING 响应阶段禁用 SCORE 排序并把 URL 收敛回 `STUDENT_NUMBER`。

## 数据库、伪数据与环境

本轮没有创建数据库、表、迁移、账号、课程、课时、题目、媒体、Redis Key、RabbitMQ 消息、OSS 对象或落盘 CSV。为避免两个既有 Seed 的固定断言互相污染，先在明确的 `edu_platform_learning_dev` 专用库执行 T11C.1 Initialize，切换到 T12B Initialize 进行学生数据准备，再执行 T12B Cleanup，最后执行 T11C.1 Initialize 收口；没有删除 Seed 脚本，也没有覆盖其他领域数据。最终保留 T11C.1 的 2 场幂等成绩册演示 Seed，T12B 的 6 场 Seed 脚本仍保留，可按既有 Initialize/Cleanup/Rebuild 重新生成。

真实服务已在本机监听：Gateway 8080、IAM 8081、Course 8082、Media 8083、Learning 8084、Operation 8085，student-web/teacher-web 为 5173/5174。公共课程列表与固定课程详情返回 200；不存在课程返回 404；未认证课程任务和成绩册分别返回统一 401。IAM 健康检查为 503，原因是本地 SMTP 未配置，但其数据库、Redis、ping/readiness 组件正常。

本轮按用户要求重新启动内置浏览器，已成功建立本地浏览器会话；上一轮的内核资源初始化错误没有再次出现。浏览器复用既有 local/test 学生会话，未读取、猜测或输入密码，也没有绕过 Gateway。课程详情、课程任务路由、练习中心、当前课时任务区、刷新/返回、导航高亮、键盘焦点和控制台均已进行真实页面检查；课程任务 API 统一返回 503，教师成绩册使用学生会话返回 403，因此未把失败页面冒充成业务成功。

## 已知风险与后续依赖

- 内置浏览器系统通道已恢复；当前明确阻塞是 Learning 的课程事实 HTTP 适配器。它以严格记录只声明 `Chapter(List<Lesson>)`、`Lesson(String id, String type)`，而 Course 实际响应还包含章节/课时的 `id`、`title`、`sequence`、`previewable` 等字段；Learning 的严格 Jackson 配置因此将课程任务请求转为 503。该问题属于既有后端适配实现，不在本次前端范围内，本任务没有修改 Java 或放宽契约。服务端容量验收已由 T11C.1.1 完成，本轮没有重复 5,000×100 压测。
- OpenAPI 的 CSV 响应是同步文本流，浏览器只能显示“服务器正在生成”的阶段状态，无法从当前契约推断服务端百分比；页面不虚报进度。
- 课程任务列表契约没有独立的类型筛选参数，练习中心继续调用既有 learner assessments 列表后在页面边界过滤 PRACTICE；后续如契约新增服务端类型筛选，可向前兼容优化，但当前不猜字段。
- 页面构建仍有既有 HLS/入口大 chunk 警告；本任务没有复制播放器或扩大媒体范围。
