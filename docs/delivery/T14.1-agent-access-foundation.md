# T14.1 Agent Access 会话与授权基础交付

日期：2026-09-09。状态：实现与本地自动化验证完成，PR #57 的 push/PR 两轮 CI 共 8 项检查全绿，已合并到 `main@9afc1ae`。

## 1. 目标与边界

本任务新增独立 Java `agent-access-service`，实现 AI 会话、消息、run、公开流事件、取消、恢复和安全审计位置；由 Java 先验证 `learning:access`、资源归属和当前领域事实，再按 T13.1 协议调用 Python 并代理 SSE。Course/Learning 同时提供独立 Index Worker 所需的稳定分页事实源，并在事实变化的同一事务写入最小 Outbox 通知。

本任务不实现 T13.2 的 Qdrant/Neo4j/检索 Worker，不实现 T13.3 的动态五角色和模型调用，不实现 T14.2 长期记忆/真实额度闭环，不创建 Vue 页面，也不把旧 FAISS 固定流程包装成“真实 Agent”。Python 不访问 Java MySQL、不接 OSS SDK；Agent Access 不跨服务查表。

## 2. 外部 API 与调用流程

外部唯一事实源 [`openapi.yaml`](../api/openapi.yaml) 升级至 0.23.0，新增：

- 创建、分页和读取本人会话；
- 分页读取会话消息；
- 发送用户消息并获得 SSE；
- 按 runId 恢复已保存事件；
- 按 cancelRequestId 幂等取消。

Gateway 只把 `/api/v1/ai/**` 路由到 8086，并要求已认证用户具备 `learning:access`。Agent Access 从认证头取得不可伪造 userId；owner 不匹配统一隐藏为 404。同一 `createRequestId` 或 `clientRequestId` 加相同指纹安全重放，指纹冲突为 409；数据库唯一约束保证同会话最多一个活动 run，不后台排队。

发送流程为：验证 owner/权限 → 调用 Learning/Course/Media 现有领域 API 解析当前题目、课时和图片事实 → 仅保存稳定 ID 上下文 → 创建消息/run → 按 [`agent-internal.yaml`](../api/agent-internal.yaml) v1 调用 Python → 逐事件校验、脱敏、持久化并代理。短期图片 URL 只存在于本次内存请求，不入库、不入日志、不回显。客户端断开会请求取消；服务重启后发现的孤儿活动 run 合成明确 FAILED 终态，恢复读取不会再次启动模型。幂等请求若落到没有本地上游句柄的其他实例，只返回已保存快照而不误杀活动 run，客户端随后通过 run 事件恢复接口继续追踪。

## 3. 内部索引源与事件

新增 [`agent-index-source-internal.yaml`](../api/agent-index-source-internal.yaml) 1.0.0：

- Learning 分页提供 ACTIVE、SYSTEM、JUNIOR、MATH 的题目安全投影，不含答案、解析和教师私题；
- Learning 分页提供已启用初中数学知识点及最多 32 个直接前置关系；
- Course 分页提供当前已发布、非空 ARTICLE 文字投影；在线检索命中仍必须回 Java 复核用户课程访问；
- 游标固定为 `(sourceRevision, entityId)`，单页最多 200；也支持事件后的单实体拉取；
- 内部入口需 `X-Internal-Caller: agent-index-worker` 和至少 32 字符的专用令牌，Gateway 不路由。

Question/Knowledge/Course 的写服务在领域事务中写入 T13.1 定义的 `agent.index.v1` Outbox，消息只含实体 ID、动作、revision、学段/科目/可见范围，不复制题干、正文、答案或签名 URL。题目新增 `question_index_revision` 是为解决一个具体顺序失败：SYSTEM 子题先作为根题产生 UPSERT，随后被组合题引用时必须产生更高 revision 的 DELETE tombstone；复用业务 revision 会破坏既有安全清理语义，普通唯一约束或 eventId 去重也无法阻止旧 UPSERT 复活，因此使用独立单调索引 revision。
