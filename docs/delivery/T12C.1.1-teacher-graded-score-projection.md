# T12C.1.1 教师已批个人成绩安全投影

## 目标与边界

在 `codex/t12c1.1-teacher-graded-score-projection` 修正 T12C.1 单生任务明细：owner 教师查看当前 ACTIVE 学生时，HOMEWORK/EXAM 已关闭且草稿结算完成、该生最后有效 attempt 已正式批改，便可看到该生原始分、总分和百分制。其他学生仍待批时，本人分数可见而 `resultsReady=false`；排名、排名人数、领先比例、班级均分、极值、分布和按成绩排序继续隐藏。PRACTICE 继续使用个人最高有效成绩。未新增接口、Vue 页面、缓存、数据库迁移或业务表。

## 契约与调用流程

先将 `docs/api/openapi.yaml` 从 0.26.0 向前标注为 0.26.1，再重新生成 `web-apps/packages/api-client/src/generated/schema.d.ts`。接口字段和类型保持不变，仅明确已有 nullable 分数字段的可见条件：

`GET /api/v1/teacher/learning/courses/{courseId}/students/{learnerId}/tasks`

Gateway 可信身份头需要 `teaching:access`；Learning 再经 Course API 核实课程 owner，并只允许读取 ACTIVE 报名者。Learning 从本域 `assessment_participant.final_attempt_id` 读取最后有效 attempt，核对参与者已提交且批改状态与 attempt 状态均为 `GRADED`。正式任务必须同时为 `CLOSED`、`COMPLETED` 才开放个人分数。全班 `pending_count=0` 才开放 `resultsReady`、排名及班级统计；个人已批不会触发排名查询。本人未批、最后 attempt 待批、未关闭或未结算时，三个分数字段均为 `null`。

成绩册与整场 results 仍调用原有服务逻辑并保持全批改门禁；本次没有改动其实现。Course 不可用时仍按既有规则返回 503，非 owner 或非 ACTIVE 学生安全返回 404，缺少教学能力返回 403。

## 数据、环境与启动

没有新增数据库、表、迁移、环境变量或永久伪数据；没有连接或修改本地 MySQL、Redis、RabbitMQ、OSS。回归测试使用专用内存 H2 `t12c1_analytics_test`，创建最小伪课程、ACTIVE/退课学生、正式任务和多次 attempt；`@Transactional` 在每例结束回滚，重新执行同一测试即可重新生成，清理由测试事务自动完成。既有 local.env 无需删除或迁移任何本任务配置。

沿用 T12C.1 启动方式：按 `docs/development/local-environment.md` 通过 `scripts/Invoke-WithLocalEnvironment.ps1` 提供现有本地配置并启动 Gateway、Course、Learning；本任务没有对真实开发库执行验收写入。
