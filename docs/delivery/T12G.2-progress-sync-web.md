# T12G.2 播放进度同步前端

## 任务目标与边界

本任务在既有 `/learn/:courseId/:lessonId` 学习页接通 T12G.1 的 OpenAPI 0.20.0 进度事件契约。实现范围是共享播放器采样、学生端同步控制器、课程学习页导航检查点和同步状态反馈；没有修改 Java、Flyway、OpenAPI、生成客户端、课程路由或 ARTICLE 独立完成命令。

真实浏览器复核曾观察到 PAUSE/ENDED 返回 422；继续定位后确认前端此前把稳定错误码和字段校验丢弃，且同一动态路由的课时切换不会触发 `onBeforeRouteLeave`。现已补充 422 诊断信息，改用 `onBeforeRouteUpdate` 发送切课检查点，并加入仅开发环境的脱敏网络观测日志。

## 页面和同步控制器职责

- `packages/ui/src/playback-progress.ts` 按真实墙钟时间累计观看时长，默认每 5 秒产生 `HEARTBEAT`；暂停产生 `PAUSE`，自然结束产生 `ENDED`，拖动只更新位置而不增加观看时长。`FLUSH` 仅供页面离页前抓取内存增量。
- `packages/ui/src/HlsVideoPlayer.vue` 继续是唯一播放器，新增 `flushProgress()` 暴露方法；组件不判断学生角色、课程权限或 Gateway 业务，只输出中立样本，并继续清理 HLS、授权请求、定时器和临时 URL。
- `apps/student-web/src/progress-sync.ts` 把播放器生命周期映射到 OpenAPI `eventType`，维护一个有界内存快照而不是无界请求队列。位置取最远值，观看秒数合并且每个请求不超过 300 秒，完成标记只有 `ENDED` 可以为 true。
- `CourseLearningPage.vue` 负责学习事实、播放器授权、五类事件来源、页面导航生命周期和反馈文案。课时导航发送 `LESSON_SWITCH`，退出学习发送 `LEAVE`；路由守卫也覆盖浏览器后退等未经过页面按钮的导航。

## 事件、重试和状态流程

1. 播放器周期样本映射为 `HEARTBEAT`，暂停和自然结束分别映射为 `PAUSE`、`ENDED`。
2. 普通请求串行执行，失败的快照在内存中合并；网络、超时、429、5xx 最多三次有界尝试，重试期间复用同一个 `clientEventId` 和请求体。耗尽后不再后台无限重试，下一次同步、网络恢复或手动“重试”才启动新的逻辑请求 ID。
3. `PAUSE`、`LESSON_SWITCH`、`LEAVE`、`ENDED` 是强制检查点；路由操作最多等待约 3 秒。成功收到 `PERSISTED` 才自动继续，失败时保留当前页面并提供“重试”和“仍然离开”。暂停失败不会触发 SPA 离开确认。
4. `BUFFERED` 只显示“正在同步”，不表示 MySQL 已写入；`PERSISTED` 显示“已保存”；读取到 `PERSISTED_ONLY` 显示“当前显示最近已保存进度”；存在未保存数据的失败显示“进度尚未同步”。
5. `pagehide` 使用同一 Gateway API 的认证头和 `fetch keepalive: true` 做一次 LEAVE 尽力发送，不等待、不重试、不承诺必达。`beforeunload` 只在存在未保存内存快照时触发浏览器原生提示。未保存进度不写入 localStorage、sessionStorage、IndexedDB 或 Cookie。

## API、数据和环境

复用以下已冻结接口和生成类型：

- `POST /api/v1/learning/courses/{courseId}/lessons/{lessonId}/progress-events`
- `GET /api/v1/learning/courses/{courseId}/progress`
- `ReportLessonProgressRequest.eventType`：`HEARTBEAT`、`PAUSE`、`LESSON_SWITCH`、`LEAVE`、`ENDED`
- `LessonProgress.persistenceStatus`：`BUFFERED`、`PERSISTED`、`PERSISTED_ONLY`

本任务没有创建数据库、表、迁移、伪数据、Redis Key、租约、OSS 对象或消息。真实验收只使用既有 local 开发数据；目标聚合行和事件基线在验收前记录为 `position=8`、`watched=8`、`completed=false`、`revision=1`，事件表仅保留既有 `NULL` 类型事件。验收产生的目标课时事件按精确 `clientEventId` 删除，聚合字段、时间、revision、bufferVersion 和 Redis 目标 Hash/dirty 成员均恢复到上述基线，未影响其他进度。
