# T12F.1.1 教师已保存正文图片预览授权补口

## 目标与功能边界

本任务把 OpenAPI 从 0.19.0 向前演进到 0.19.1，为教师重新进入、刷新或再次读取已保存 ARTICLE 课时时补齐专用正文内容投影。投影只面向课程 owner 的当前可编辑版本，返回已保存 Markdown，以及其中实际引用且可安全展示的 READY `ARTICLE_IMAGE` 的短期 `ORIGINAL/INLINE` 授权。

本任务没有修改 Vue 页面、组件、路由或样式；没有把 `ARTICLE_IMAGE` 放入普通学习资料列表，也没有为它增加 PREVIEW/DOWNLOAD；没有新增接收任意 mediaId 的授权 API，没有重写学生受保护内容投影，没有修改 T12F.2 分支或 PR #43。字幕、多码率、清晰度、历史海报重处理、Office 在线转换等能力均不在范围内。

## 架构与调用流程

新增 `GET /api/v1/teacher/courses/{courseId}/lessons/{lessonId}/article-content`，请求只含课程和课时路径参数，不含 versionId、resourceId 或 mediaId：

1. Gateway 继续按教师路由验证 JWT、`TEACHER` 角色和 `teaching:access`，向 course-service 转发可信用户 ID/角色。
2. course-service 在同一 SQL 查询中限定课程 owner，并通过 `COALESCE(current_draft_version_id, published_version_id)` 只解析当前可编辑版本；存在草稿时历史发布课时不可见，没有草稿时当前发布编辑快照可读。
3. course-service 重新校验已保存的受控 Markdown，得到去重后的 `media:UUID` 引用集合；每个引用必须在同课时全部资源行中恰好绑定一次，且绑定用途精确为 `ARTICLE_IMAGE`。未引用绑定被忽略，缺失、重复或错用途绑定在调用媒体域前以安全 409 整体拒绝。
4. course-service 仅用上述服务端解析结果，通过既有跨服务客户端和一次性服务 JWT 请求 media-service 的 `COURSE_ARTICLE_IMAGE/ORIGINAL/INLINE`。
5. media-service 继续独立复核令牌字段、允许动作、资产实际用途和 READY 状态，再由既有 OSS 适配器签发短期 GET；404/409 被 course-service 适配为不可枚举或安全冲突。

响应只包含 `courseId`、`lessonId`、`articleMarkdown` 以及 `{mediaId, grant}` 映射。它不含普通资源行、文件快照、Bucket、Object Key、永久 URL、OSS 凭据或服务间 Token。授权过期后，原签名不能续期；浏览器必须重新调用 owner 接口并再次通过课程所有权与当前版本校验。

## 数据库、迁移与环境

没有新增或修改数据库迁移、表、索引、约束、事件 Schema、环境变量或本地环境文档。实现只查询现有 Course V4 的 `course`、`course_version`、`chapter`、`lesson` 和 `lesson_media_resource`；服务之间没有跨 Schema Join、外键、共享 Mapper 或事务，也不直接访问 OSS。

常规本地启动仍使用仓库已有 `scripts/Invoke-WithLocalEnvironment.ps1` 注入 DPAPI 加密的 MySQL、IAM 和 course/media 服务授权秘密。本次真实验收临时把媒体访问授权 TTL 设为 5 秒、服务令牌 TTL 设为 5 秒，并在独立本地进程中关闭与本场景无关的 MQ 消费、Gateway 分布式限流和 sessionVersion 查询；这些值没有写入仓库或用户配置。验收后进程和临时日志均已清理，因此不更新 `docs/development/local-environment.md`。

### 真实 owner 与 OSS 验收

所有带凭据命令均通过 `scripts/Invoke-WithLocalEnvironment.ps1` 执行，目标被测试强制限定为 `edu_platform_course_dev` 和 `edu_platform_media_dev`：

- `T12F11_REAL_ACCEPTANCE=true` 的 Course 门控 1/1 通过。用例经真实 Gateway 创建随机临时课程，保存含固定 READY ARTICLE_IMAGE 的 Markdown，重新读取当前可编辑版本，取得短期 INLINE 授权并从项目专用 OSS 成功加载非空 `image/png`。
- 同一用例等待 5 秒签名过期后直接复用得到 OSS 403；随后重新请求教师投影，再经 owner/current 校验获得新授权并成功加载，证明签名不会无限自动续期。
- 同一真实链路验证非 owner、错课程、错课时和历史发布课时为安全 404；未引用 ARTICLE_IMAGE 绑定不返回；实际媒体用途为普通附件时为安全 404；Markdown 引用缺少绑定时为 `COURSE.CONTENT_INCONSISTENT` 409；携带任意 `?mediaId=` 不改变投影。
- Media 门控 1/1 通过。它只把固定 `...f103` ARTICLE_IMAGE 的状态从 READY 临时改为 UPLOADED，经固定 owner 课程和真实 Gateway/Course/Media 链路确认 `MEDIA.NOT_READY` 409，然后在 `finally` 中恢复 READY。
- Media 门控首次两次只在 Spring 测试上下文启动阶段失败：先发现测试 classpath 同时含 Learning 迁移，再发现 Gateway 自动配置被测试依赖带入；两次均在测试方法执行前终止，没有修改媒体状态或数据。门控随后按仓库既有真实 Media 测试限定 Flyway 目录并排除 Gateway 自动配置，最终通过。

## 伪数据、清理与重新生成

没有创建数据库、表、迁移或 OSS 对象，也没有修改正式或来源不明的数据。真实验收使用两类明确开发数据：

- Course 用例创建一个随机 courseId 及其版本、章节、课时、资源绑定和相关 Outbox，仅用于保存、重读、版本隔离与异常绑定验收；`finally` 按随机 courseId 逆序精确删除，并复核课程计数为 0。
- Media 用例复用 T12F.1 固定开发 Seed `...f103`，只临时修改状态并无条件恢复；固定数据库记录和 OSS 原件均保留。用例还按测试前后 nonce 快照删除本轮新增的一次性服务授权，并按 `t12f11-*` trace 精确删除短期访问审计；到期的验收服务 nonce 通过现有回收方法删除。

没有新增需要重新生成的长期 Fixture。要重复验收，只需保留既有 T12F.1 固定 Seed，启动 Media→Course→Gateway 后重新运行两个 `T12F11_REAL_ACCEPTANCE=true` 门控。不要对固定 Seed 执行 Cleanup；本任务的随机数据会由用例自身清理。

## 人工演示步骤

1. 确认 T12F.1 固定 Course/Media Seed 完整，使用本地环境包装器启动 Media、Course、Gateway。
2. 以固定测试 owner 保存包含 `![说明](media:<ARTICLE_IMAGE>)` 的 ARTICLE 正文。
3. 调用教师 `article-content`，确认响应 Markdown 与引用一致，仅返回 `{mediaId, grant}`，并用 grant 成功加载图片。
4. 等短期签名过期，确认原 URL 失败；重新调用接口，确认再次通过 owner 校验并获得可加载的新签名。
5. 分别以非 owner、错 lessonId、历史 lessonId 请求，确认不可枚举；再验证未引用、错用途和非 READY 不获授权。
6. 删除随机课程数据和任务授权审计，恢复固定媒体 READY，停止临时服务；复核 T12F.1 固定 Seed 与 OSS 对象仍存在。
