## 目标与边界

公共题库组题已从 Python 类式 `PracticeGenerationSkill` 迁移为 T13.5.1 Runtime 加载的目录 Skill `public-practice-generation@1.1.0`。本任务不修改浏览器 OpenAPI 0.23.4、Learning 自主练习数据模型、题库索引结构、Vue、导航、OSS 或 RabbitMQ。

## Skill 目录与执行流程

目录仅包含 `SKILL.md`、`references/practice-rules.md` 和 `scripts/validate_proposal.py`。实际使用 skill-creator 的 `init_skill.py public-practice-generation --path edu_agent_app/skills --resources scripts,references` 初始化；随后删除平台不消费的 `agents/openai.yaml`，没有 `runtime.yaml`、assets、README、示例或空目录。最终已通过 skill-creator `quick_validate.py`。

启动时 Registry 只读取 name、description 和 1.1.0；平台 eligibility 只允许 `PRACTICE_COACH + RECOMMEND_PRACTICE`。唯一候选直接按 RULE 选择，不调用额外 LLM；选中后加载正文，先创建 RUNNING 审计，再按需读取详细规则，只通过 `QUESTION_SEARCH` 获取候选，最后由受控 Runner 执行脚本。脚本 stdout 必须是 `resultType + payload`；Runtime 校验结果类型并生成不可伪造的 Skill 信封，服务仅把身份匹配的 `PRACTICE_PROPOSAL` 映射为既有 `FINAL_RESULT.practiceProposal`。

审计开始失败、脚本失败、超时、取消、非法 JSON、非法结果类型或非法 payload 均不产生 proposal。Java 仍在 pending action 前与确认时调用 Learning 复核；学生明确确认后才由 Learning 幂等创建、作答、保存、提交和评分。
