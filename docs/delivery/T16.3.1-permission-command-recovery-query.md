## 契约、架构与流程

先修改 OpenAPI 0.31.1 并落盘 [契约评审](../api/T16.3.1-contract-review.md)，再实现 IAM。最终操作：

| 方法/路径 | 授权与结果 |
|---|---|
| `GET /api/v1/admin/users/{userId}/permission-commands/latest` | 当前有效独立管理员；200 为最近 `AccountPermissionCommand`，存在账号无命令204无正文，未知账号404 `IAM.NOT_FOUND` |

流程为 Gateway 既有 `/api/v1/admin/users/**` 路由/能力/Redis会话检查 → IAM 持久 sessionVersion 过滤器 → `AdminAuthority.require` 读取当前账号、角色与管理能力 → 核对目标存在 → 精确 `user_id=? ORDER BY decided_revision DESC,id DESC LIMIT 1` → 原 `response(row,false)` 安全投影。

管理员可跨原操作者读取，不能只信任旧JWT。非法UUID422，匿名/过期会话401，当前非管理员403；Gateway会话缓存被撤销而缺失时安全503，重新登录回填当前版本后旧JWT401。其他统一错误语义沿现有边界。GET不写入、不启动Course调用/补偿、不消耗attempts或预算。四态都按读取时事实返回，后台可能随后推进；200的`replayed=false`，不返回原因、request_json、联系方式、凭据或内部响应正文。OpenAPI提供合成只读示例，避免Prism通用布尔生成将读取错误示例为写请求重放。

取得commandId后调用既有 `GET /api/v1/admin/permission-commands/{commandId}`，FAILED时才按当前attempts调用原retry。自动最多3次、显式最多再3次、总计6次；原水位/周期、幂等及409保持。202只表示IAM提交，APPLIED只确认Course事实/Outbox，不承诺全部Learning消费者完成。无需依赖commandId等于clientRequestId。

## 数据库与环境

无新数据库、表、索引、迁移或事件版本；IAM V5完整校验通过且没有迁移待应用。复用`account_permission_command`及其既有账号索引。读取路径只访问IAM本域，不跨服务查表。未进行生产容量验收，当前无证据要求增加索引。

生产启动方式沿已有local环境，IAM/Gateway需既有JWT与数据库配置；本次无新增生产环境变量。凭据命令始终经 `scripts/Invoke-WithLocalEnvironment.ps1`。真实验收入口：

```powershell

```

脚本限定`edu_platform_iam_dev`，拒绝已占用18080/18081，打包并仅启动本轮IAM/Gateway。关闭Seed、资格保留、IAM Outbox发布和权限协调Worker，保留Redis会话与Gateway限流；只为测试进程设置`edu:t1631:test:session-version`、`edu:t1631:test:gateway:rate`，Gateway共享IAM Redis逻辑库。`T1631_RECOVERY_REAL_ACCEPTANCE`、`T1631_CLEANUP_ONLY`仅为显式测试开关，无需写入local.env。脚本finally恢复进程环境并停止其创建的JVM，日志在忽略目录`.m2/t16-3-1-recovery-acceptance`。

没有修改个人local.env，无本轮配置需要删除或迁移。数据库/JWT等秘密继续用当前用户DPAPI，正式部署由Secret Manager注入；非敏感服务地址/Schema约定可按运行环境保留。
