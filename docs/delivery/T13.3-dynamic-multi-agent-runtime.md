# T13.3 动态多 Agent 与多轮运行时交付说明

日期：2026-09-09。状态：实现与本机验收已完成，Ready PR 待创建。

## 目标与边界

本任务把 Python 在线入口替换为 T13.1 冻结协议定义的动态运行时。Coordinator 采用规则优先、结构化模型兜底的一级/二级意图识别和受约束槽位抽取，只能从固定的 Math Tutor、Practice Coach、Study Planner、Platform Help 中选择专家；一次最多执行两个有序子请求，第三个请求不会自动展开。专家没有自主循环或任意转交能力，所有步骤、模型、工具、视觉、压缩和候选记忆共同受 run 预算约束。

按本任务边界，Platform Help 在 T13.4 前明确不可用，自主组题写入留给 T14.3；没有实现 Vue、Java 数据库迁移、帮助知识库、长期记忆数据库、衰减或用户画像持久化。旧固定认知诊断、固定解题图、FAISS、人工教师转交、LangGraph 递归和 PostgreSQL checkpoint 已从项目运行时代码与依赖中移除；T13.2 的独立索引 Worker 保留不变。

## 架构与调用流程

在线入口为 `POST /internal/v1/agent/runs`，取消入口为 `POST /internal/v1/agent/runs/{runId}/cancel`，请求和事件直接复用 `docs/api/agent-internal.yaml` 的 v1 DTO、五角色、14 个二级意图、工具名、SSE 事件及五种唯一终态，没有新增第二套枚举或外部浏览器 API。

一次运行依次执行：原子登记会话/run → 立即发送 `RUN_ACCEPTED` → 规则或最多一次有限修复的结构化意图识别 → 必要时澄清 → 选择一个专家或顺序执行两个子请求 → 按角色、意图、Java grant 与资源范围四重校验工具 → 直接流式专家回答 → 保存有限最近轮次/候选摘要 → 唯一 `FINAL_RESULT`。多专家输出直接按请求顺序组合，不为了“总结”额外调用模型。

运行时使用 T13.1 默认预算：12 个编排步骤、8 次 LLM、10 次工具尝试、2 次专家转交、同工具同参数 2 次、约 90 秒；Java 可在冻结范围内逐 run 下发更小或更大的合法值。超限、取消、总超时、空闲超时、慢客户端和断线都会停止后续模型/工具调用。已经发出的文本保留为部分回答，事件 sequence 从 `RUN_ACCEPTED` 后严格连续，每个 run 只允许一个 `FINAL_RESULT`。心跳不消耗模型调用。

## 检索、权限与多模态

`QUESTION_SEARCH`、`KNOWLEDGE_SEARCH`、`COURSE_TEXT_SEARCH` 分别接入 T13.2 的 `math_questions`、`math_knowledge`、`course_content`，沿用 dense + 服务端 multilingual BM25 + RRF + 本地 reranker 和分集合阈值；无可靠命中返回空，不填充伪证据。Neo4j 只在知识点命中后做深度最多 3、结果最多 50 的前置知识扩展，故障时返回空并继续降级回答。

课程检索先限定 Java 下发的 course/version/lesson，再要求候选逐项经过可注入的 Java `course_verifier`。T13.1/T14.1 当前没有冻结 Python→Java“课程候选再次授权”端点，这是本任务发现的契约缺口；因此没有自创平行 HTTP API。默认未注入 verifier 时所有课程候选一律剔除，只允许继续使用公开数学知识，不会退化为全课程库搜索。T14.2 或后续契约任务需要先补充该版本化 Java 端点，再把实现适配器注入运行时。

图片只读取 `TrustedContext.media` 中 `AUTHORIZED_BY_JAVA` 且带未过期短期授权的媒体；工具还会复核媒体 ID grant、MIME、大小和禁止重定向。Python 不接受模型或用户提供的任意图片 URL，不接 OSS SDK，只把安全读取的字节编码为内存 data URL 交给视觉模型。视觉结果必须返回经校验的 `{summary, reliable}`；模糊字符、数字或题意不可靠时返回澄清，猜测不会进入可靠证据或摘要。

## 多轮与教学策略

进程内会话状态使用 Java 已授权摘要和当前进程最近消息。超过字符阈值后执行确定性有限压缩，保留数学公式、未解决问题、明确偏好和必要来源标题；清除 URL、签名参数、Token 等秘密，不写入工具原始结果、隐藏画像或完整受限课程正文。压缩只生成 T14.2 未来可消费的候选记忆，不写 Java/MySQL/Qdrant `student_memories`。

默认提示模型逐步引导；本轮明确要求完整答案，或 Java 下发来源为 `EXPLICIT` 的完整讲解偏好时，才完整解释。针对同一主题连续“不懂”，依次换一种表述、给简单数字例子、回退可靠前置知识；第三次达到上限后以 `DEGRADED` 收口。主题改变会重置该计数，一次求助不会持久化为能力不足。

## 配置与启动

模型使用共享环境的阿里云百炼 OpenAI 兼容配置：`OPENAI_BASE_URL`、`OPENAI_API_KEY`、`CHAT_MODEL_NAME`、`VISION_MODEL_NAME`。秘密必须通过 `scripts/Invoke-WithLocalEnvironment.ps1` 注入，模型配置对象隐藏 API Key 的 repr，日志只记录 runId、模型名、调用数、Token、阶段延迟和终止原因，不记录完整提示、完整回答、隐藏推理或短期 URL。

```powershell
& .\scripts\Invoke-WithLocalEnvironment.ps1 -ScriptBlock {
    D:\Anaconda\envs\langgraph\python.exe -m edu_agent_app
}

# 独立索引 Worker 仍使用自己的启动模式。
& .\scripts\Invoke-WithLocalEnvironment.ps1 -ScriptBlock {
    D:\Anaconda\envs\langgraph\python.exe -m edu_agent_app index-worker
}
```

非敏感新增/调整项为 `AGENT_ONLINE_RETRIEVAL_ENABLED`、`AGENT_MODEL_REQUEST_TIMEOUT_SECONDS`、`AGENT_CONTEXT_COMPRESSION_THRESHOLD_CHARS`。运行时默认值见 `.env.example`；预算仍由每个 Java 请求的冻结 `budget` 与 `timeoutPolicy` 决定。

## 人工演示

1. 用安全包装器启动 Python，确认 `/health` 返回 `ok`；只从本机 Java Agent Access 调用内部运行端点。
2. 发送“不要直接告诉我答案，只给提示：解方程 x+2=5”，观察 `RUN_ACCEPTED`、阶段、文本增量和唯一 `COMPLETED`。
3. 同一会话连续发送三次“还是不懂”，确认提示依次改变且第三次为 `DEGRADED`；换一个明确主题后不会继承能力判断。
4. 在首个 run 尚未结束时对同一会话发起第二个 run，确认 409；取消首个 run，确认后续调用停止且保留部分回答。
5. 用 Java 授权图片测试清晰和模糊样本；模糊样本应要求补充文字或清晰图片。没有 Java 注入或资源 ID 超 scope 的图片必须在外部请求前拒绝。

## 数据、清理与风险

本任务没有创建或修改 MySQL/Redis 数据、Java 表、Qdrant 点、Neo4j 节点/关系、RabbitMQ 队列/消息、OSS 对象或伪数据。真实检索仅只读 T13.2 已保留派生索引；视觉图片在测试进程内生成并随进程释放；Java 回归仅使用 H2 内存库并在测试 JVM 结束后释放。wheel 位于被忽略的 `.m2/python-wheels`；发现的旧 setuptools 构建缓存已移到被忽略的 `.m2/build-stale-t13.3-20260910`，两者均可按普通构建缓存清理，不影响源码或数据。

尚有两个明确后续依赖：其一是上述课程候选再次授权端点契约缺口，在补齐前运行时保持 fail-closed；其二是 T14.1 当前请求没有稳定提供最近消息正文和全部学习事实读取适配器，Python 只能使用本进程最近轮次与 Java 已授权摘要，跨进程恢复、Redis 活跃状态、长期记忆事实和真实额度仍属于 T14.2。进程重启会丢失候选记忆和最近消息，这是当前阶段的预期边界。

代码已在 `codex/t13.3-dynamic-multi-agent-runtime` 实施；关键提交和 PR 创建后回填。本任务没有修改共享 `local.env`；现有明文非秘密模型名/地址可保留，`OPENAI_API_KEY` 必须继续留在 DPAPI/正式 Secret，不应写入或复制到 `local.env`。
