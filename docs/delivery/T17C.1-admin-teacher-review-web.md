沿用管理端 AppShell、统一认证和头像消息菜单，侧栏固定“教师审核、账号权限”，仅审核可用，账号权限为不可点击的建设中。默认落点和共享 ADMIN 工作台目标为 `/admin/teacher-review`；旧 `/admin/dashboard`、`/admin/reviews` 只重定向。student-web 继续承载唯一登录及消息页。

## 架构与调用流程

`TeacherReviewPage.vue → teacher-review-api.ts → @edu/auth.authorizedRequest → 生成 GatewayClient → Gateway → IAM → Media`。只有材料读取按 IAM 返回的短期授权直连对象存储，前端不接 OSS SDK、不接域服务地址、不自选 mediaId。共享 api-client 只增加生成 schema 的类型别名，没有手写 DTO。

| 现有 API | 页面消费方式 |
|---|---|
| GET `/api/v1/admin/teacher-applications` | 固定每页20条；状态、排序、页码在URL；精确身份只在本页内存，不写URL/存储/日志。空分页与零匹配分别提示。 |
| GET `/api/v1/admin/teacher-applications/{applicationId}` | 仅主动选中、真实深链接或手动刷新详情调用；首次查看者/时间在详情显示。不悬停预取、不逐行请求，不制造N+1。 |
| POST `/{applicationId}/material-access` | 使用生成的 roundId＋PREVIEW/DOWNLOAD；实际读取Blob后展示图片/PDF或交给浏览器下载。历史轮次材料不构成当前轮批准证据。 |
| POST `/{applicationId}/decision` | 保存原clientRequestId、expectedRevision及完整生成载荷；批准须当前材料已成功读取、人工勾选及二次确认；驳回10～1000字并二次确认。 |

URL白名单为 page（1～50001）、status、order、applicationId、panel=detail/history。共享安全回跳将旧管理链接归一到新入口，并移除精确身份、未知参数和hash；刷新/返回保持公开定位信息，精确查询需重新输入。直接深链可以打开当前列表页之外的申请，不扫描其他分页。

每个决定最多三次逻辑发送，401只复用共享认证既有的一次恢复；不自动无限重试。网络、5xx或15秒超时保留未决状态并冻结原快照，输入变化及详情刷新不能自动创建新命令。重试仍使用原ID、revision和载荷。409不自动读取新版后覆盖：用户须点击“刷新详情并核对”，再明确结束旧请求；若仍待审，需要重新读取材料并决定。请求重放的最终事实以IAM为准。

离页、换申请及刷新/关闭标签保护未保存理由、在途决定和未决结果。401/403、账号ID/角色/能力变化立即清理私有详情、理由、精确查询、材料确认及命令载荷，取消并发授权/读取/决定，旧身份不能重试；仅保留必要的未决警示。卸载移除beforeunload监听，清理冷却/超时/到期计时器及全部Blob URL。授权到期也撤销预览和批准资格。关闭详情恢复列表按钮焦点，移动端保持同序导航和顺序堆叠。

## 数据库、配置与启动

没有新建数据库、表或迁移。开发验收复用明确的 `edu_platform_iam_dev`、`edu_platform_media_dev`、`edu_platform_operation_dev`，其他域仅只读比对。账号、身份、角色、申请/提交命令、轮次/决定/重放命令、安全/登录审计和刷新会话是既有IAM表；上传会话/资产/处理/引用/短期授权审计是既有Media表；通知/投递工作与消费回执是既有Operation表。事件继续复用已有Outbox与RabbitMQ。

随机Fixture密码只以DPAPI保存于当前用户 `.ccnu-edulion/t17c1-fixture.credential.clixml`，子进程环境临时加载，cleanup删除该凭据。没有修改个人local.env，也无本轮新增项需要删除；其中若曾留有秘密，应删除并迁入DPAPI或部署Secret Manager。三端测试地址只在启动子进程环境，停止后无需清理持久配置。

## 人工演示

1. 初始化Fixture并启动上面的专用环境；使用DPAPI注入的临时身份，不向日志或文档写密码。学生打开 `/apply-teacher` 上传PNG并提交。
2. 管理员进 `/admin/teacher-review`，查四种状态和排序/精确查询，观察仅打开详情才变为审核中，首次查看者/时间在详情出现。
3. 预览或下载当前材料，勾选人工核对并确认批准；学生刷新申请及能力，教学入口可用。重复原决定返回原结果，不重复授能。
4. 第二份申请驳回并填写理由，学生上传新资质重提，管理端历史保留旧决定。两管理员同时读取，另一人先决定后当前旧revision返回409，必须刷新核对后重新决定。
5. 对本轮resubmit原件执行remove-material，预览失败且批准按钮禁用；直接批准仍由IAM拒绝。非管理员深链和API均不能获取审核材料。
6. 在三种宽度、键盘和浏览器返回/刷新检查页面；结束时settle、cleanup、STOP，仅收口本轮实例/数据。
