# T16.3.1 权限命令恢复查询契约评审

2026-10-04，先审查 OpenAPI 0.31.0、IAM 权限服务、管理员授权/会话过滤器、V5 及 T17C.2 缺口，再修改契约；本记录与 OpenAPI 0.31.1 先于生产实现落盘。属于兼容新增读取操作，不改变既有字段或写入语义。

## 最终决定

- `GET /api/v1/admin/users/{userId}/permission-commands/latest`，operationId 为 `getLatestAccountPermissionCommand`，无请求正文。
- 当前有效独立 ADMIN 且具有 `administration:access`；Gateway 校验 JWT/会话，IAM 复核持久会话版本与当前身份。原操作者不构成读取限制，其他有效管理员可接手。先授权再判断目标是否存在。
- 精确按 userId 过滤，`decided_revision DESC, id DESC LIMIT 1`。revision 是账号决定次序；UUID 字典序作为相同 revision 的稳定次序，不用时间戳或协调状态排序。使用 V5 既有账号索引，无性能证据支持新增索引，不修改已合并迁移。
- 200 复用 `AccountPermissionCommand`，四种状态均可返回，读取的 `replayed=false`。账号存在而无命令为 204 无正文，未知账号为 404 `IAM.NOT_FOUND`；非法 UUID 422，未认证/旧会话401、非当前管理员403，限流429，安全依赖不可用503，沿用统一错误信封。Gateway 缺失会话缓存仍可能安全拒绝503，不能把它描述成必然401。
- 不返回理由、request_json、联系方式、秘密或内部响应正文。单次读取只说明当时事实，后台状态可继续推进，无冻结快照承诺。
- GET 不写入、不推进协调、不调用 Course，不增加次数或预算。恢复后的 commandId 交给现有按 ID 查询/retry；不依赖 commandId 与 clientRequestId 的内部偶合。
- 自动3次、显式最多追加3次、总计6次，FAILED/expectedAttempts/幂等/并发409及原 accessRevision/suspensionId 不变。202 不等于协调完成，APPLIED 不等于 Learning 全部消费完成。

## 实现与验证约束

只增加 IAM 控制器/服务读取，Gateway 现有 `/api/v1/admin/**` 路由与安全规则复用。无需 DTO、迁移、缓存、事件或页面。H2 验证隔离、revision 优先及稳定排序、四态、授权、响应安全、无副作用和原补偿回归；真实 Gateway→IAM→MySQL 验证响应丢失后两管理员交接、空/未知账号及旧会话。生成客户端与 Prism 都读取同一 OpenAPI，Mock 结果和真实证据分列记录于交付文档。
