# T16.3 契约设计与评审

## 已确认边界

普通账号仅 STUDENT、STUDENT+TEACHER 或 DISABLED 无有效能力；ADMIN 独立同权。
首次教学授予仍走 T16.2，恢复读取不可变 APPROVED 决定，不伪造历史。
撤权和封禁不删除任何领域事实。Course/Learning 继续采用 T16.1 暂停区间停止计时及恢复顺延。

## 权限命令设计

新增影响预览、明确确认的权限命令和命令状态查询。预览保存目标 revision、动作、操作者、有效期和影响统计；确认时重新校验操作者、目标 revision 和影响范围。
动作限定 REVOKE_TEACHING、RESTORE_TEACHING、BAN、UNBAN；普通命令不能创建 ADMIN。
原因 10～500 字，expectedRevision 防覆盖，clientRequestId 保存原始结果并拒绝异载荷复用。
IAM 决定、本域审计、单调 accessRevision、suspensionId 和协调记录同事务提交。
课程协调返回 PENDING、FAILED、APPLIED；无课程动作返回 NOT_REQUIRED。FAILED 保留事实，通过有限补偿重放同一命令，不回滚资格。
暂停与恢复严格按同账号序号执行；恢复沿用未完成撤权周期，不能恢复其他周期或原本未发布的课程。
Course 只提供本域课程范围，Learning 对这些稳定 ID 聚合去重 ACTIVE 报名人数，IAM 不跨服务查表。

## 会话一致性评审

登录、刷新、所有撤销路径统一先锁 IAM user 行，再锁 Refresh Session；禁止反向锁序。
登录等待锁后重读密码与状态，刷新等待锁后重读会话状态和账号版本。
签发事务完成提交并归还数据库连接后，缓存发布在新事务重新锁 user 并读取当前已提交版本，不发布捕获的旧快照。避免在提交回调仍占用原连接时申请第二连接，防止小连接池并发耗尽。
撤销在持有 user 行锁后先删除 Redis 版本，再提交数据库版本和会话变化；回滚最多造成安全拒绝，可通过重新登录回填原数据库版本。
Redis 不可用、版本缺失仍安全拒绝；不发布未提交的能力、不增加完整 JWT 白名单。
需真实 MySQL/Redis 并发验证登录/刷新先后两种顺序、撤销失败回滚及缓存发布故障。
